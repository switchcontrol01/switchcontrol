TASK

Implement live GPU telemetry using Windows Performance Counters as the primary source for real-time GPU usage, instead of relying on "systeminformation" for usage percentage.

PROBLEM

The current GPU telemetry path is not reliable enough for live usage data, especially on AMD GPUs like the RX 7800 XT.

"systeminformation" may provide:

- GPU name
- VRAM total
- VRAM used

But it is not reliable for:

- live GPU usage %
- real-time activity graphing

As a result, the GPU line is missing, flat, or misleading.

GOAL

Add a real, live GPU usage line and tooltip using Windows Performance Counters.

REQUIRED OUTPUT

At minimum:

- live GPU usage %
- usable for graph history
- visible in tooltip

Nice to have:

- keep existing GPU name / VRAM info from "systeminformation"
- combine static GPU card info with real live GPU usage from Windows counters

IMPLEMENTATION PLAN

1. USE WINDOWS PERFORMANCE COUNTERS FOR GPU USAGE

Use Windows counters for:

- "\GPU Engine(*)\Utilization Percentage"

or another correct GPU performance counter path available on the system.

The implementation must:

- gather GPU engine utilization
- aggregate relevant engine values into a single usable GPU usage %
- avoid duplicate counting where possible

2. AGGREGATE INTO A SINGLE GPU USAGE VALUE

The raw counter may return many engine instances.

Implement logic to:

- inspect all engine instances
- identify relevant engines for the active adapter if possible
- sum or otherwise normalize to a realistic total GPU usage %
- clamp to 0–100 if needed

Do NOT leave this as raw per-engine data only.
The frontend graph needs one live GPU usage value.

3. KEEP EXISTING STATIC GPU CARD INFO

Continue using current static source for:

- GPU name
- VRAM total
- VRAM used if already working

The new counter path is specifically for live GPU usage.

4. TELEMETRY PIPELINE

Wire the new GPU usage value into the existing live telemetry flow:

- backend fetch
- payload
- history buffer
- frontend graph
- tooltip

Confirm the graph reads the correct GPU field.

5. FALLBACK BEHAVIOR

If Windows GPU counters fail or return no usable data:

- do NOT fake numbers
- return a clear unavailable state
- do NOT silently hardcode 0 forever

6. DEBUG LOGGING

Temporarily log:

- raw GPU counter instances
- aggregated GPU usage result
- final telemetry payload sent to frontend

I want to know:

- whether counters are being read correctly
- whether aggregation is correct
- whether the frontend is receiving the final value

IMPORTANT

Do NOT keep using "systeminformation" alone for GPU usage if it is not reliable on AMD.
Use Windows performance counters as the live usage source.

Do NOT fake GPU usage with random values.

TEST CASE

Test with real GPU load:

- open a GPU-heavy game
- run a benchmark
- stress the GPU

Expected:

- GPU usage line should visibly rise
- tooltip should show changing GPU values
- graph should no longer be dead or flat

FINAL OUTPUT

Return:

1. what Windows counter path is being used
2. how the raw engine counters were aggregated
3. what file(s) were changed
4. whether AMD required special handling
5. proof that GPU live usage now updates correctly under load
