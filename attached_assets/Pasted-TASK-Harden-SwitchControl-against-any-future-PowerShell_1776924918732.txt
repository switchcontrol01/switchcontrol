IMPLEMENTATION

SECTION 1 — ADD GLOBAL POWERSHELL LIMITER

Create one shared limiter module for all PowerShell-backed execution paths.

New file suggestion:
- electron/powershell-limiter.js

It must provide a single source of truth for whether PowerShell work is already running globally.

Required behavior:
- every PowerShell-backed task acquires through this shared limiter
- limiter must track:
  - active count
  - current owner / function name
  - timestamp started
  - reason
- if a new task is attempted while global policy says it must not run, return an explicit skipped result

I do NOT want each file inventing its own isolated behavior anymore.
I want one central limiter that all PowerShell execution paths go through.

Use a structure like this conceptually:

- tryAcquirePowerShellSlot({ file, fn, reason, scope })
- releasePowerShellSlot(token)
- getPowerShellLimiterState()

Support at least:
- global single-flight mode
- optional keyed single-flight mode per function if needed

If we already have per-function locks, keep them, but put a global limiter above them as a second safety layer.

SECTION 2 — REPLACE UNSAFE setInterval POLLING WITH SAFE ASYNC LOOPS

Any PowerShell-backed repeating poll must not use naive setInterval if a previous run can still be alive when the next tick fires.

Audit all repeating PowerShell paths.
Where PowerShell is involved, replace this pattern:

setInterval(async () => {
  await doWork();
}, 1000);

with a safe loop pattern:

- while active
- await doWork()
- await sleep(delay)
- next iteration only starts after prior one fully completes

This must be done wherever PowerShell-backed work can overlap.

Important:
- do NOT blindly refactor unrelated safe cached polling
- only convert the paths where PowerShell / execFile / spawn is involved, or where overlap risk exists

SECTION 3 — RETURN EXPLICIT SKIPPED STATES

Anywhere execution currently returns:
- null
- undefined
- silent no-op
- fake success
when a call was skipped because another run is active, replace that with an explicit structured result.

I want a consistent return shape like:

{
  ok: false,
  skipped: true,
  reason: "already_running",
  scope: "global" or "function",
  file: "...",
  fn: "...",
  activeOwner: "...",
  activeSince: ...
}

Apply this to:
- tweak sync/check paths
- network tweak sync/check paths
- telemetry PowerShell reads if skipped
- trigger monitoring if skipped
- any limiter refusal path

Frontend / callers must treat skipped as skipped, not success.

SECTION 4 — HARD EXECUTION LOGGING

Temporarily add strong diagnostic logging around every PowerShell launch path.

For every attempted launch, log:
- file
- function
- reason
- timestamp
- whether acquire succeeded
- whether skipped
- whether a global slot was already occupied
- total execution time
- release event

Example style:

Make logs clear enough that I can launch the app, sit idle, and prove there is no repeated spawn storm.
