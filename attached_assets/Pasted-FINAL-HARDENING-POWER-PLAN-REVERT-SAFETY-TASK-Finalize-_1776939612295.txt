FINAL HARDENING — POWER PLAN REVERT SAFETY

TASK
Finalize the power plan revert pipeline so free-trial expiry and premium downgrade always restore the correct Windows default behavior safely.

GOAL
When premium expires:
- if SwitchControl applied a premium power plan, revert safely
- if the target Windows Balanced scheme already exists and is active, do nothing
- if the target Windows Balanced scheme is missing, restore default schemes and retry
- never override a user’s manual post-apply change
- never use plan name matching in the revert path

REQUIRED CHECKS

1. KEEP GUID-ONLY LOGIC
- Use only GUID constants in apply/revert
- No string name matching like "Balanced" or display-name comparisons in the actual control path
- Display names are UI only

2. EARLY EXIT
Inside activatePlanByGuid():
- read current active GUID first
- if already active, return structured success:
  { ok: true, alreadyActive: true, changed: false }

3. MISSING DEFAULT PLAN FALLBACK
If target GUID is BALANCED_GUID and activation fails because the plan does not exist:
- run `powercfg -restoredefaultschemes`
- re-read available schemes
- retry activation once only
- return structured metadata:
  { ok: true, restoredDefaults: true, retried: true }
or
  { ok: false, restoredDefaultsAttempted: true, error: ... }

4. OWNERSHIP ENFORCEMENT
Only revert plans where ownership record proves:
- appliedByApp === true

If app did not apply it, do not touch it.

5. MANUAL CHANGE PROTECTION
Before revert:
- compare current active GUID with the plan the app last set
- if the user already moved to another plan manually, skip revert
- return:
  { ok: true, skipped: true, reason: 'user_changed_plan_after_apply' }

6. STRUCTURED LOGGING
Add explicit logs for:
- previousPlanGuid captured
- premium plan applied
- revert skipped because user changed plan
- revert skipped because already active
- restoredefaultschemes invoked
- retry success/failure

7. FINAL TEST MATRIX
Run and confirm all pass:

A. Premium plan active -> trial expires -> reverts to Windows Balanced GUID
B. Premium plan active -> user manually changes plan -> trial expires -> skip revert
C. Balanced already active -> revert call -> no-op success
D. Balanced missing -> restoredefaultschemes -> retry -> success
E. App restart after revert -> UI still shows real active plan correctly

FINAL OUTPUT
Return:
- exact files touched
- exact guards added
- exact retry/fallback behavior
- exact structured result objects now returned
- test results for all 5 scenarios
