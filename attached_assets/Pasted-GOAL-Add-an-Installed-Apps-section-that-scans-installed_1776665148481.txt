GOAL

Add an Installed Apps section that:

- scans installed apps on the PC
- shows them in a premium searchable UI
- lets the user uninstall supported apps directly from SwitchControl
- clearly separates safe curated debloat recommendations from generic installed apps
- protects core Windows components and blocked apps from removal
- preserves trust and safety

IMPLEMENTATION

1. Add a new section or tab inside Debloater

Use one of these structures:

- Debloater tab + Installed Apps tab
  or
- Curated Removals + Installed Apps

Do not dump all installed apps into the exact same curated item list.

They must be visually and logically separate.

2. Scan installed apps on the PC

Add a real installed apps scan using Windows data sources.

Support as much of this as possible:

- traditional installed apps from uninstall registry keys
- per-user uninstall entries
- machine-wide uninstall entries
- AppX / Store apps where removable
- optionally winget-detectable apps if clean and reliable

Show only real installed apps detected on the PC.

3. Display app metadata

For each app, show as much of this as reliably available:

- app name
- publisher
- version
- estimated size if available
- install source
- uninstall type
- install location if available
- uninstall support status
- risk / trust label

Suggested trust labels:

- User Installed
- Microsoft App
- System App
- Protected
- Core Windows
- Unknown Risk

4. Add uninstall actions inside SwitchControl

Supported apps should have an Uninstall button directly inside the app.

Requirements:

- confirmation modal before uninstall
- stronger warning for unknown-risk apps
- disable uninstall for protected/core apps
- show progress state while uninstalling
- show success / failed / partial result clearly
- refresh installed apps list after uninstall

5. Add a protection layer

This is mandatory.

Do not allow direct uninstall of:

- critical Windows components
- Defender / Firewall / Update related core components
- core shell items if removal is unsafe
- anything in a denylist of protected packages/apps/services
- anything with no trustworthy uninstall path unless explicitly supported

Add a strong protected list and block those removals in both UI and backend.

6. Add filters and sorting

Installed Apps manager should support:

Filters:

- all apps
- uninstallable only
- protected
- Microsoft
- third-party
- large apps
- recently installed if data exists
- user-installed
- system apps

Sorting:

- name
- size
- publisher
- install source
- uninstallable first
- largest first

Also add search.

Search should match:

- app name
- publisher
- version

7. Add “recommended cleanup” intelligence

If possible, add smart labels such as:

- likely safe to remove
- optional
- gaming irrelevant
- background-heavy
- Microsoft consumer app
- advanced users only

These labels must be conservative.
Do not invent fake certainty.

8. Add uninstall method clarity

For each app, show which uninstall path is being used:

- registry uninstall string
- AppX removal
- Store-linked removal
- unsupported

That increases trust.

9. Add result logging

Every uninstall action from Installed Apps manager should be logged into history with metadata such as:

- app name
- publisher if available
- uninstall method
- status
- timestamp
- source module = Installed Apps

10. Keep Debloater curated

Do not destroy the existing curated Debloater identity.

Curated Debloater should still be:

- role-based
- safety scored
- estimated impact aware
- recommendation driven

Installed Apps manager should be:

- exploratory
- search-driven
- user-controlled
- more heavily guarded
