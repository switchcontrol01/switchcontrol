TASK
Fix the intro tour and premium tour so they move between pages fluidly without flashing back to the dashboard between steps.

PROBLEM
Right now the tours are bugged.

When clicking Next:
- the app briefly shows the dashboard intro again
- then it goes to the real target page
- this happens between tour steps
- the flow looks broken and cheap

Example:
Dashboard step
Next
Tweaks step
But dashboard flashes again for a split second before Tweaks appears

This destroys the premium feeling.

GOAL
Make both tours:
- fully fluid
- route-aware
- persistent across page changes
- visually premium
- no dashboard flash
- no fallback page showing between steps
- no double render feel

The structure and quality should match the premium flow exactly, but smoother and more polished.

ROOT CAUSE TO INVESTIGATE
Likely issue is one or more of these:
1. Tour state is tied to page-local render state instead of a persistent global controller
2. Route changes briefly mount the default dashboard/home route before the target page settles
3. AppLayout or route animation runs during tour-driven navigation and exposes intermediate content
4. Next button updates both step state and route state in the wrong order
5. Tour target resolution happens before the route is actually ready
6. There may be a fallback <Route> rendering Home/dashboard during transition

IMPLEMENTATION

1. CREATE A SINGLE PERSISTENT TOUR CONTROLLER
Both onboarding and premium tours must be controlled from one stable top-level state source, not page-local state that remounts during navigation.

The tour overlay should remain mounted across route changes.
Do not destroy and recreate the tour UI every time the page changes.

2. ADD ROUTE-AWARE TOUR NAVIGATION
For steps that require a different page:
- navigate first
- wait until the route is actually active
- wait until the target element exists
- then advance the tour step UI

Do NOT increment the visible tour step before the destination page is ready.

Pseudo flow:
- user clicks Next
- controller checks next step target route
- if different route, navigate there
- wait for route match
- wait for target selector to exist
- then transition overlay/highlight to next step

3. BLOCK DASHBOARD FALLBACK FLASH
Audit all routing behavior during tours.
If there is any fallback route rendering Home/dashboard during route transitions, remove that behavior for active tours.

Specifically inspect:
- App.tsx routing
- ElectronAppRoutes fallback route
- any setLocation("/dashboard") calls during tour flow
- any Welcome/onComplete logic that may interfere
- any default route mount while a target page is loading

The app must not show dashboard between steps unless dashboard is the actual next step.

4. KEEP THE TOUR OVERLAY STABLE
The overlay, spotlight, tooltip card, and step chrome should stay mounted while only the target/highlight changes.

Do not:
- fully unmount the tour layer
- restart entrance animation every step
- fade out to nothing between steps

Instead:
- keep backdrop persistent
- animate tooltip position/content smoothly
- crossfade text only inside the tooltip
- smoothly retarget spotlight/highlight after route settles

5. IMPROVE THE MOTION
Current motion feels mechanical and glitchy.
Make it feel more premium.

Use:
- persistent dimmed backdrop
- smooth spotlight retargeting
- tooltip spring motion
- subtle content crossfade
- no harsh disappear/reappear
- no route snap visible behind overlay

The animation should feel intentional, not like a page reloaded.

6. INTRO TOUR AND PREMIUM TOUR MUST SHARE THE SAME SYSTEM
Do not maintain two separate buggy implementations.
Unify them under one tour engine/controller with different step data.

Shared behavior:
- persistent overlay
- route-aware step navigation
- wait-for-target logic
- stable transitions
- identical quality level

7. ADD WAIT-FOR-TARGET LOGIC
For each step:
- identify target selector
- after route change, poll briefly or use a safe observer until the target exists
- only then show tooltip/highlight
- if target fails, fail gracefully and skip or show centered fallback, but never flash dashboard

8. PREVENT APPLAYOUT ROUTE ANIMATION FROM FIGHTING THE TOUR
If AppLayout page transition animation is exposing intermediate screens during tour-driven navigation, then suppress or simplify page transition animation while a tour is active.

Important:
Do not remove global animations permanently.
Only suppress the conflicting route transition behavior during active guided tours.

9. CHECK NEXT/PREV ORDERING
Audit button handlers.
Likely bug:
- step index updates first
- route updates second
or
- route changes but tour reads stale route state

Fix sequencing so navigation and step activation are deterministic.

10. DEBUG LOGS
Temporarily add logs for:
- current step id
- requested next route
- actual current route
- target selector
- target found timestamp
- tooltip render timestamp

This is to prove the flash bug is gone.

SUCCESS CRITERIA
- clicking Next never flashes dashboard unless dashboard is the actual next step
- onboarding tour is fluid across pages
- premium tour is fluid across pages
- overlay remains stable during step changes
- tooltip/highlight transitions feel premium
- no route snap or double-render feel
- no regressions in normal non-tour navigation

FILES TO INSPECT FIRST
- App.tsx
- ElectronAppRoutes
- AppLayout.tsx
- OnboardingTour component
- GuidedTour component
- any shared tour step config
- any setLocation / navigation helper used by tours

FINAL OUTPUT
Return:
1. root cause found
2. exact files changed
3. how route-aware waiting was implemented
4. how fallback dashboard flash was eliminated
5. confirmation both tours now use the same stable transition logic
