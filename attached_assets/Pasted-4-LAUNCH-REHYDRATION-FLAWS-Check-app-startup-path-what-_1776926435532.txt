SECTION 1 — HARDEN EXECUTION RESULTS

Return at minimum:
- success
- verified
- skipped
- item id
- item type
- finalAppliedState or finalValue
- persistedStateWritten true/false
- error if failed

Frontend must stop inferring result from old local assumptions.

SECTION 2 — PERSISTENCE WRITE PATH AUDIT
Audit every persistence write:
- local tweak-state file
- ownership store
- NIC state
- power plan state
- network tweak state

Ensure:
- writes happen only after success
- writes are atomic
- no stale write can overwrite newer state
- no default boot object can wipe existing state

If needed:
- use temp write + rename pattern
- preserve last good state on parse failure
- reject malformed empty writes

SECTION 3 — SAFE REHYDRATION MODEL
Implement a 3-phase state model on the frontend:

phase 1:
- load persisted local state immediately as provisional state

phase 2:
- request actual current status from backend/electron

phase 3:
- reconcile and update only if returned result is newer than current generation

Need:
- request generation id or hydration token
- ignore late responses from previous tab/session/load cycle

SECTION 4 — NO FALSE FLASH
Tweak cards/toggles must support:
- unknown
- loading
- applied
- not applied
- applying
- reverting
- error

Never map unknown/loading to false.

SECTION 5 — TAB / ROUTE HARDENING

- runs syncAll on every remount without guarding
- resets local item state on route change
- depends on unstable callback identity
