    ames matching known browser patterns (chrome, firefox, msedge, brave, opera) → category 'Browser / Electron', safety 'moderate', recommendedAction 'lower_priority'
    Names matching update helpers (updater, update, autoupdate, crashhandler) → category 'Vendor Utilities', safety 'safe', recommendedAction 'stop_process'
    Names matching launcher helpers that are NOT the main launcher (steamwebhelper, epicwebhelper) → category 'Gaming / Launchers', safety 'moderate', recommendedAction 'lower_priority'
    Names matching known bloat patterns (yourphone, people, msteams background, gamingservices if not gaming) → category 'Windows Optional', safety 'safe', recommendedAction 'stop_process'
    Unknown publisher, unknown path → category 'Unknown / Review', safety 'unknown', recommendedAction 'review_only'
    Everything else → category 'Background Apps', safety 'moderate', recommendedAction 'lower_priority'

impactScore = (cpuPct * 0.6 + (memoryMb / 50) * 0.4) clamped to 0-100.

PLAN FUNCTIONS

Write buildPlan(scanResult, profile) that takes a ScanResult and a profile string ('safe', 'competitive', 'extreme') and returns an ActionPlan.

For 'safe': only include processes where safety === 'safe' AND recommendedAction === 'stop_process'. Never include anything in System Core, Audio/Voice, Network/VPN, Gaming/Launchers categories.

For 'competitive': include safe profile targets plus processes where safety === 'moderate' AND recommendedAction === 'lower_priority'. Still never touch protected categories.

For 'extreme': include competitive targets plus Windows Optional processes with safety moderate. Require caller to confirm. Still never touch System Core, Audio, Network, Launchers, or anti-cheat.

Always filter the final plan through isProtected one more time as a safety net. Log [ProcessControl:Plan] profile=X toStop=Y toLowerPriority=Z.

APPLY FUNCTION

Write applyPlan(plan) that:

    Logs [ProcessControl:Apply] starting profile=X.
    Captures before metrics from current system state.
    For each process in toStop: run Stop-Process -Id X -Force via PowerShell with a 5 second timeout per process. Catch errors per process, never let one failure stop the rest. Never stop a protected process — double-check with isProtected before every single action.
    For each process in toLowerPriority: run (Get-Process -Id X).PriorityClass = 'BelowNormal' via PowerShell. Same timeout and error handling.
    After all actions, wait 2 seconds, then run a lightweight rescan (process count only).
    Build and return a BeforeAfterResult with real measured values.
    Save a RestoreRecord to a file called process-control-history.json in the app data directory using an atomic write (write to .tmp then rename). Log [ProcessControl:Verify] complete.

RESTORE FUNCTION

Write restoreLast() that:

    Reads process-control-history.json. If it does not exist, return { ok: false, reason: 'No restore point found' }.
    For startup entries that were disabled: re-enable them via registry or task scheduler. Log each.
    For priority changes: attempt to restore using (Get-Process -Id X).PriorityClass = 'Normal' but catch errors since the process may no longer exist.
    Cannot restart stopped processes automatically unless the path is known and safe. Log what could and could not be restored.
    Return a structured result with what was restored and what could not be.

EXPORTS

Export: scan, buildPlan, applyPlan, restoreLast, getLastResult, getProtectedList, PROTECTED_NAMES.
STEP 4: REGISTER IPC HANDLERS IN MAIN.JS

In electron/main.js:

At the top with other requires, add: const processControl = require('./process-control');

Then find the section where other IPC handlers are registered. Add these handlers in a clearly commented block:

processControl:scan — acquires a psLimiter token with key processControl:scan, calls processControl.scan(), releases token, returns result. If scan is already in flight (token denied), return { skipped: true }.

processControl:applySafe — acquires psLimiter token, calls processControl.buildPlan(lastScan, 'safe') then processControl.applyPlan(plan), releases token.

processControl:applyCompetitive — same but profile 'competitive'.

processControl:applyExtreme — takes a confirmed plan object from the renderer (the renderer must show the plan modal first), validates it is a plain object, calls processControl.applyPlan(plan). Never build an extreme plan server-side without the renderer confirming it first.

processControl:restoreLast — calls processControl.restoreLast().

processControl:getLastResult — returns last cached scan result and last BeforeAfterResult without running any PowerShell.

processControl:getProtectedList — returns the protected names list as an array. Safe, no PS.

All handlers must catch errors and return { success: false, error: message } rather than throwing.
