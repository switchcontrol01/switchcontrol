
1️⃣ Red error toast: X not clickable + wrong styling

What’s wrong

The error toast uses a different component or z-index layer than success toasts.

The close “X” is either:

Behind another element

Has pointer-events: none

Or the toast container is swallowing clicks


Styling mismatch (red toast not matching purple translucent design) breaks visual consistency.


Required fix

Unify all toasts into one toast component.

Rules

Same container

Same z-index

Same backdrop blur

Same translucency

Only color and icon change


Concrete fixes

Ensure:

pointer-events: auto on toast

z-index above cards


Use one toast renderer:

variant: success | error | info


X button must be:

position: absolute

top/right

cursor: pointer



If a user can’t dismiss an error, they assume the app is broken. This is not optional.

2️⃣ “Real” tweaks not working

What’s actually happening

Two possibilities, both common:

A) PowerShell script failed silently

Your screenshot literally shows:

> Requested registry access is not allowed



That means:

Script ran

Script failed

UI still assumed success


That is a logic bug.

B) Tweak applied but user has no confirmation

Either way, trust is broken.


---

Required fix: verification layer

Every tweak must return one of three states:

✅ Applied

⚠ Applied with warning

❌ Failed (with reason)


Example

After running a tweak:

Read back the registry key

Compare expected value

Return boolean + message


Then:

Show Applied only if verification passes

Otherwise show Failed with reason


Never assume success.

3️⃣ “How do I know the tweak actually applied?”

Right now: you don’t. That’s the problem.

Fix (mandatory)

Add post-check verification:

Registry tweaks → read key after write

Services → query service state

Power plan → query active GUID


Then surface:

✔ “Verified”

✖ “Blocked by system policy”

✖ “Requires admin”


This instantly separates you from trash tweakers.

4️⃣ Premium purchase not reflected in app without logout

This is a state sync failure, not a payments problem.

Root cause

App is caching user.plan = free

Purchase happens in browser

App never revalidates session

Only logout forces refresh


This is unacceptable UX.


---

Correct solution (industry-standard)

You need real-time entitlement refresh.

On purchase success (web):

Fire a purchase_complete event

Redirect to a “Return to App” page


That page does one of two things:

Deep link back to app

Or trigger a session refresh endpoint
