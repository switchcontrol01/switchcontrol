TASK
Implement a hard premium device lock for the DESKTOP APP ONLY so premium is linked to the original device id and cannot be used on a different PC with the same account.

GOAL
If a user buys premium and activates it on their original device, that premium desktop app access should become bound to that original device id.

If the same premium account is later used on another PC/device:
- detect the device mismatch
- block premium desktop app access
- do NOT allow premium features on the second device

IMPORTANT
This is NOT a one-session system.
This is a primary/original device binding system for the desktop app premium license.

Also important:
This restriction is ONLY for the desktop app premium access.
Do NOT apply it to:
- website login
- website sessions
- browser access
- Discord
- general account access

The website can still work normally.
Only the desktop app premium runtime should be locked to the original device.

REQUIRED BEHAVIOR
1. First premium activation on desktop app:
- generate/read stable device id
- bind the premium account to that original device id server-side

2. Future premium app checks:
- compare current device id to stored bound/original device id
- if match, allow premium app access
- if mismatch, block premium app access

3. Mismatch behavior:
- show clean blocked state in app
- explain premium is linked to another/original device
- do not grant premium features on the second device

IMPLEMENTATION

1. ADD PRIMARY DEVICE BINDING MODEL
Create server-side premium device binding fields such as:
- user_id
- premium_bound_device_id
- premium_bound_at
- premium_device_status
- optional last_seen_device_id
- optional device_label / app_version / last_seen_at

2. DEVICE ID STRATEGY
Implement a stable desktop app device id.

Need:
- stable across normal app relaunches
- not a random per-session id
- hashed before storage/transmission if appropriate
- reasonable resilience against trivial reset/spoofing

Do NOT overcomplicate with invasive fingerprinting if unnecessary, but make it stronger than a weak session token.

3. FIRST BIND LOGIC
On first premium desktop app activation:
- if no premium_bound_device_id exists
- bind current device id as the original/primary device
- store it server-side
- premium works on that device

4. PREMIUM VALIDATION LOGIC
On every premium desktop app validation:
- read current device id
- compare with premium_bound_device_id
- if same, allow premium
- if different, deny premium desktop app access

5. BLOCKED STATE
If device mismatch is detected:
- block premium desktop app features
- do not silently fail
- show a clean message such as:
  “Premium is linked to another device and cannot be used on this PC.”

Need a polished blocked state in the app.
Do NOT crash the app.
Do NOT break normal account login.
Only premium desktop app features should be blocked.

6. KEEP WEBSITE ACCESS UNAFFECTED
This is critical.
Do NOT apply the device lock to:
- website access
- website login
- browser sessions
- non-app account usage

Only premium desktop app usage is restricted.

7. SUPPORT / RECOVERY PATH
Because legitimate users may change PC, reinstall Windows, or replace hardware, add a recovery path.

At minimum:
- support/admin ability to clear or reset the bound premium device
or
- a controlled self-serve reset flow if already supported by your backend rules

Do NOT leave users permanently trapped with no recovery option.
