TASK
Fix Network Tweaks showing disabled after app restart even though Windows tweak remains applied.

PROBLEM
Network tweaks apply correctly and stay applied when switching tabs or minimizing the app.

But after fully closing and reopening SwitchControl, Network Tweaks show disabled again.

This means the applied action works, but startup/status hydration is broken.

GOAL
On app start and Network page mount, read the real Windows/network state and hydrate the UI from verified backend status.

Never trust default frontend state after restart.

IMPLEMENTATION

1. Find Network Tweaks page/component and status store.

Likely files:
- NetworkTweaks.tsx
- network-tweaks.ts
- tweak store
- ownership store
- main.js IPC handlers
- preload.js exposed APIs

2. Find current startup/default state.

Look for:
- default applied: false
- localStorage state
- Zustand persisted state
- checkAllNetworkTweakStatus
- getNetworkTweakStatus
- networkTweaks:getStatus
- networkTweaks:checkAll

3. Add/repair backend verified status check.

On Network page mount, call:

networkTweaks:checkAllStatus

or equivalent.

Backend must verify real Windows state using:
- registry
- netsh
- PowerShell
- adapter advanced properties
- ownership store only as secondary info

4. Frontend rule:

On mount:
- show checking state
- request verified backend status
- update each card from verified status
- only fall back to persisted state if backend fails

Do NOT initialize all cards as disabled before verification finishes.

5. Apply flow:

When user applies a network tweak:
- run backend apply action
- immediately run verify status for that tweak
- only mark enabled if verified=true
- save ownership record if SwitchControl applied it

6. Restart flow:

When app restarts:
- do not use previous React state
- do not use default false
- do not rely only on ownership store
- call backend verification
- UI must show the actual Windows state

7. Add logs:

Frontend:
[NetworkTweaks] mount — hydrating verified status
[NetworkTweaks] status loading
[NetworkTweaks] status loaded tweakId=... enabled=... verified=... source=windows
[NetworkTweaks] backend status failed — using stale cache

Backend:
[NetworkTweaks] checkAllStatus start
[NetworkTweaks] checkStatus tweakId=... enabled=... source=registry/netsh/adapter
[NetworkTweaks] checkAllStatus done count=... durationMs=...

8. Important distinction:

ownershipStore means:
“SwitchControl applied this”

Windows verified status means:
“this tweak is currently active”

UI enabled state must come from Windows verified status, not ownershipStore alone.

CHECKLIST
- Apply network tweak.
- Switch tabs, still enabled.
- Minimize app, still enabled.
- Exit app fully.
- Reopen app.
- Network tweak still shows enabled if Windows state is still applied.
- If user manually reverts Windows setting outside app, UI shows disabled after verification.
- No fake enabled state from localStorage.
- No default disabled state after restart before status check completes.
