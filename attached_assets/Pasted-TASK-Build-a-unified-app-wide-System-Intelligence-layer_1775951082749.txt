TASK

Build a unified app-wide System Intelligence layer for SwitchControl that exposes real motherboard, BIOS, RAM, storage, GPU, network, process, and platform data across the entire app.

This must power:

- BIOS Advisor
- AI Advisor
- Dashboard
- Hardware / telemetry surfaces
- any other relevant sections that benefit from real system context

PROBLEM

The current app feels fragmented.

Some pages know basic hardware.
Some pages guess.
Some pages are cosmetic only.
BIOS Advisor and AI Advisor do not have a single authoritative system profile.
The Dashboard and other sections are not using one shared truth source.

This causes generic advice, wrong answers, fake-looking UI, and weak trust.

GOAL

Create one normalized System Intelligence profile that is collected on the backend, exposed safely to the frontend, cached sensibly, and reused everywhere.

The app should know and expose, where reliable:

- motherboard manufacturer / model / version
- BIOS vendor / version / release date
- CPU model / cores / threads
- GPU controller name / VRAM / display chain
- RAM total / per-stick layout / configured speed
- disk model / type / interface / filesystem / usage / health-adjacent stats
- default NIC / active interfaces / gateway / Wi-Fi vs Ethernet / link speed
- active processes / top CPU offenders / top RAM offenders
- users / sessions if safely detectable
- battery / chassis on supported devices
- Docker / containers only if detected and relevant
- Windows platform / security / firmware-visible states
- BIOS-related inferred states with confidence labels

This data must be usable by BIOS Advisor, AI Advisor, Dashboard, and other sections.

No fake certainty. No dummy UI. If data is unreliable, show Unknown or remove the feature.

2. Backend collection layer

Collect the data on the backend or Electron main process using "systeminformation" and Windows-safe PowerShell queries where appropriate.

Use, where reliable:

- "si.baseboard()"
- "si.bios()"
- "si.cpu()"
- "si.graphics()"
- "si.memLayout()"
- "si.diskLayout()"
- "si.fsSize()"
- "si.networkInterfaces()"
- "si.networkConnections()"
- "si.processes()"
- "si.osInfo()"
- "si.system()"
- "si.battery()"
- "si.users()"
- Docker/container detection only if cleanly available

For Windows platform-state collection, add safe collectors for:

- Secure Boot
- TPM
- virtualization
- hypervisor present
- VBS / Memory Integrity
- UEFI boot mode if detectable
- Resize BAR only if reliable, otherwise null

3. Reliability rule

For every field:

- if directly known, expose it
- if inferable, expose it with confidence
- if unreliable, return null
- if a UI depends on unreliable data, remove that UI instead of faking it

This is mandatory.

4. Shared data flow

Do not fetch this separately on every page with different logic.

Build one shared service/store so:

- BIOS Advisor reads from it
- AI Advisor reads from it
- Dashboard reads from it
- any future section reads from it

The app must have one authoritative source of truth.
