TASK

Fix launch opening fluidity in the packaged Electron app.

PROBLEM

When the user opens SwitchControl, the app does not open smoothly.
Current behavior:
- brief full white flash on launch
- slight lag/stutter right after opening
- the first visible frame feels raw and unpolished

This breaks premium feel immediately.

GOAL

Make app launch feel cinematic, fluid, and polished:
- zero white flash
- zero raw default frame
- first visible frame must already be dark / branded
- smooth blur + fade in only after renderer is actually ready
- no visible layout snap or lag on first open

FILES TO AUDIT FIRST

- electron/main.js
- electron/preload.js
- client/src/App.tsx
- client/src/main.tsx or equivalent renderer entry
- client/index.html
- any global CSS / Tailwind base styles
- Splash screen component
- any BrowserWindow creation code
- any ready-to-show / did-finish-load / show() timing logic

SEARCH FOR

- new BrowserWindow(
- backgroundColor
- show:
- ready-to-show
- did-finish-load
- loadFile
- loadURL
- mainWindow.show(
- paintWhenInitiallyHidden
- titleBarStyle
- background:
- body background
- html background
- opacity
- blur
- splash
- initial animate
- initial opacity 0
- white backgrounds
- fallback={null}

REQUIRED FIXES

SECTION 1 — FIX FIRST PAINT

The first visible Electron frame must NOT be white.

Do all of the following:
- BrowserWindow must start hidden: show: false
- set explicit BrowserWindow backgroundColor to the exact dark app base, not white
- ensure index.html html/body/root all have dark background hardcoded inline before React loads
- make sure no component or fallback renders white by default

I want the first paint to already be dark even before React hydrates.

SECTION 2 — DO NOT SHOW WINDOW TOO EARLY

Audit the launch order carefully.

If the window is shown before:
- did-finish-load
- initial CSS is applied
- splash container is mounted
- dark background exists

then fix it.

Desired sequence:
1. create hidden window
2. load renderer
3. renderer mounts dark shell / splash
4. wait for did-finish-load or explicit renderer-ready signal
5. show window
6. animate blur/fade in

If needed, replace ready-to-show usage with a stricter renderer-ready handshake from the frontend.

SECTION 3 — ADD RENDERER-READY HANDSHAKE

I want an explicit signal from renderer to main when the first branded frame is ready.

Example concept:
- renderer mounts splash shell
- renderer sends app:first-frame-ready
- main process then shows window
- optional tiny delay of 50ms if needed for stability
- then blur/fade reveal begins

Do not rely only on BrowserWindow ready-to-show if it still allows a white/raw frame.

SECTION 4 — HARDEN HTML / CSS BASE LAYER

In index.html and global CSS:
- html background must be dark
- body background must be dark
- #root background must be dark
- no default white flash possible
- any loading/fallback layer must be dark and branded

Even if React is delayed, the user must only ever see dark themed UI.

SECTION 5 — REMOVE FIRST-OPEN STUTTER

Audit what is blocking the renderer right after launch.

Look for:
- heavy synchronous work on mount
- expensive useEffect chains
- immediate telemetry work
- immediate large fetch bursts
- unnecessary state churn before first paint
- expensive blur/filter/layout work on initial frame
- animations starting before layout stabilizes

If heavy startup work exists, defer it until AFTER first visible frame.

Rule:
- paint first
- then do non-critical startup work
