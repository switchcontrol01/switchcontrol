TASK: Redesign broken admin user deletion flow and fix backend deletion failures

PROBLEM:
The current admin delete-user flow requires typing the exact user email address before deletion. This is poor UX for an internal admin panel and deletions currently fail with "failed to delete user".

GOAL:
Replace the email-entry confirmation system with a safer modern confirmation modal and fully fix backend deletion logic.

IMPLEMENTATION:

FRONTEND:

1. Remove exact email typing requirement completely.

2. Replace with confirmation modal:
   Title:
   "Delete User Account"
   
   Show:
   
   - email
   - username
   - plan
   - user ID
   - account creation date

3. Add warning text:
   "This action permanently deletes the account and cannot be undone."

4. Add confirmation checkbox:
   "I understand this action is permanent"

5. Final delete button:
   
   - red destructive styling
   - disabled until checkbox enabled

6. Add loading state during deletion:
   
   - spinner
   - "Deleting user..."

7. Add proper success/error toast notifications.

BACKEND:

1. Add logging to delete route:
   
   - admin user performing deletion
   - target user ID
   - Stripe customer ID
   - DB delete success/failure
   - full caught exception stack

2. Investigate why deletions fail:
   Possible causes:
   
   - Prisma foreign key constraints
   - missing cascade deletes
   - Stripe API failure
   - invalid auth
   - Electron packaged routing issue

3. Ensure deletion order is safe:
   Example:
   
   - revoke sessions
   - remove device locks
   - remove telemetry/history
   - remove subscriptions/trials
   - optionally archive Stripe metadata
   - delete user row last

4. Prevent frontend generic errors:
   Return structured JSON:
   {
   success: false,
   error: "Specific reason here"
   }

5. Ensure admin delete route works in packaged Electron mode.

CHECKLIST:

- No email typing required
- Confirmation modal works
- Delete button protected by confirmation checkbox
- User deletes successfully
- Related DB rows cleaned safely
- Clear backend logging added
- Frontend shows real error reason if deletion fails

FINAL OUTPUT:
Modern admin deletion workflow with reliable backend deletion handling and proper diagnostics.
