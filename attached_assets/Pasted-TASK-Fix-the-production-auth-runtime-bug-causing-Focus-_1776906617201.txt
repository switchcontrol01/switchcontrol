TASK
Fix the production auth/runtime bug causing Focus Mode and Cleaner scan to fail in the packaged Electron build.

PROBLEM
In the packaged app, Focus Mode activation fails and Cleaner scan does not work.

Evidence:
- Focus Mode toast says: "Failed to activate Focus Mode. Authentication required. Please log in to use AI features."
- Cleaner scan action also fails / does nothing
- Earlier packaged backend logs showed:
  - GET /api/focus/state 401
  - GET /api/focus/history 401
  - GET /api/cleaner/categories 401
  - GET /api/cleaner/history 401
  - GET /api/cleaner/scan-history 401

This means protected backend routes are being hit without valid desktop auth, or the wrong middleware is guarding local desktop features.

GOAL
Make Focus Mode and Cleaner work reliably in the packaged app:
- no 401s after a valid desktop login
- no route calls before auth hydration is ready
- correct auth middleware on focus/cleaner routes
- correct token/cookie attachment on all focus/cleaner requests
- correct user-facing error messages
- packaged build must allow Activate Focus Mode and Cleaner Scan to succeed

FILES TO CHECK
- client/src/pages/FocusMode.tsx
- client/src/pages/SystemCleaner.tsx
- any cleaner hooks/components that fire scan/state/history requests
- client/src/lib/auth-store.ts
- client/src/lib/queryClient.ts
- client/src/lib/api.ts
- server/routes/focus.ts or server/routes/focusMode.ts
- server/routes/cleaner.ts or equivalent cleaner backend route file
- server/middleware/requireCloudAuth.ts
- server/middleware auth helpers shared across protected routes
- electron/main.js
- electron/preload.js

SECTION 1 — IDENTIFY EXACT AUTH PATH USED BY FOCUS MODE AND CLEANER
1. Find every frontend request used by:
   - Focus Mode state
   - Focus Mode history
   - Focus Mode activate
   - Focus Mode revert
   - Cleaner categories
   - Cleaner history
   - Cleaner scan history
   - Cleaner scan action
2. For each request, confirm:
   - exact URL
   - exact HTTP method
   - whether Authorization header is sent
   - whether credentials/cookies are included
   - whether the request fires before auth hydration completes
3. Log one clear line per request in dev:
   - route
   - hasToken true/false
   - userLoggedIn true/false
   - authHydrated true/false

ACCEPTANCE
Produce a short mapping of all Focus Mode and Cleaner requests and how auth is attached.

SECTION 2 — BLOCK ALL PROTECTED REQUESTS UNTIL AUTH IS READY
1. In FocusMode.tsx and SystemCleaner.tsx, do not fire any protected requests until:
   - user?.loggedIn === true
   - auth hydration / entitlement hydration is complete
   - token/JWT is available if required by that route family
2. Disable the main action buttons while auth is unresolved:
   - Focus Mode activate button
   - Cleaner scan button
3. Show a proper loading/locked state instead of letting the user click into a guaranteed 401.

ACCEPTANCE
On fresh app launch, neither page may send protected requests before auth is ready.
No mount-time 401 spam allowed.

SECTION 3 — FIX TOKEN / COOKIE ATTACHMENT FOR THESE ROUTES
1. Audit the request helper used by Focus Mode and Cleaner.
2. Ensure packaged Electron requests to the embedded backend include the same auth strategy used by working protected routes.
3. If the app uses bearer JWT for embedded backend requests:
   - attach Authorization: Bearer <token> consistently
4. If the app uses cookie-backed auth for embedded backend requests:
   - ensure credentials are included consistently
5. Do not let Focus Mode use one auth path and Cleaner use another by accident.

ACCEPTANCE
After login, protected Focus Mode and Cleaner requests must include valid auth every time.

SECTION 4 — FIX WRONG BACKEND MIDDLEWARE / WRONG ERROR MESSAGE
1. Audit the backend middleware attached to Focus Mode and Cleaner routes.
2. Confirm these routes are not incorrectly reusing AI-only middleware or AI-specific auth messaging.
3. If they require login, the error message must be feature-appropriate:
   - Focus Mode: "Please log in to use Focus Mode."
   - Cleaner: "Please log in to use System Cleaner."
4. If these are intended to be desktop-local features after desktop login, use the proper desktop auth path, not AI/premium middleware by mistake.

ACCEPTANCE
No Focus Mode or Cleaner route may return the AI-specific auth message unless it is actually an AI route.

SECTION 5 — FAIL LOUDLY, NOT SILENTLY
1. Any failed activate/scan action must surface:
   - exact backend status code
   - exact route
   - sanitized backend message
2. Remove fake-success or no-op UI states where buttons appear clickable but nothing meaningful happens.
3. If auth is missing, return a clear typed error and show it in the UI.

ACCEPTANCE
Focus Mode and Cleaner failures must be diagnosable from one click, not hidden.
