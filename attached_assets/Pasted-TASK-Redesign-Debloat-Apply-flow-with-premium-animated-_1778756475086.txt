TASK
Redesign Debloat Apply flow with premium animated progress UI.

PROBLEM
When clicking Apply on the Debloat page, the app mostly shows a basic waiting/loading state. It does not feel premium, visual, or satisfying.

GOAL
Create a lightweight animated apply experience with clear progress, graphs, stages, and results.

IMPLEMENTATION
Redesign the apply panel/modal to show:

1. Stage timeline
- Preparing restore point
- Scanning selected items
- Removing safe apps
- Applying system changes
- Verifying cleanup
- Finalizing report

2. Live progress card
- animated progress ring
- percentage complete
- current action name
- item count completed / total
- elapsed time

3. Mini graphs
- estimated storage cleaned
- startup impact reduced
- background services reduced
- risk level meter

4. Result summary
After apply finishes, show:
- items removed
- items skipped
- failed items
- restore point status
- reboot required yes/no
- logs button

5. Visual style
- glass card
- subtle neon accents
- animated scan line
- smooth progress bar
- no heavy canvas loops
- CSS transforms/opacity only
- no CPU-heavy animation

6. Backend progress events
If backend already has progress events, connect to them.
If not, simulate frontend progress only until real backend result returns.

Important:
Simulated progress must not lie.
Use copy like:
“Applying selected actions…”
“Waiting for Windows confirmation…”

7. UI states
- idle
- preparing
- running
- verifying
- success
- partial success
- failed

8. Apply button behavior
- disable while running
- show Cancel only if backend supports cancellation
- otherwise show “Please wait”
- do not allow duplicate apply jobs

9. Add logs
[DebloatApply] started selectedCount=...
[DebloatApply] stage=preparing
[DebloatApply] stage=removing item=...
[DebloatApply] stage=verifying
[DebloatApply] complete removed=... skipped=... failed=...

CHECKLIST
- Apply no longer feels like a frozen wait state.
- User sees animated progress immediately.
- Progress stages are clear.
- Final result is visual and useful.
- No fake “100% complete” before backend finishes.
- No heavy animation or CPU spike.
- Existing debloat logic still works.
