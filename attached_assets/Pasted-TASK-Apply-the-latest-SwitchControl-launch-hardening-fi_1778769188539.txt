TASK
Apply the latest SwitchControl launch-hardening fixes from the recent audit.

PROBLEM
The latest audit found several real issues that affect trust, safety, auth, and polish:

1. "tcp-winhttp" is shown as a real tweak even though it is a no-op.
2. The “Apply Safe” button is not actually guaranteed safe.
3. Network tweak routes are missing auth and rate limiting.
4. CSRF token cache can go stale and cause 403s until reload.
5. "appBooster.ts" may fall back to "__legacy__" if auth middleware is missing.
6. AI Advisor network context can mix network tweak state across users.
7. App page transitions use blur, making the UI look AI-generated.
8. Backend error banner waits 45 seconds, which is too long.
9. Tweak cards show too many badges and look noisy.

GOAL
Fix these issues without changing core app behavior.
Make “Apply Safe” truly safe, make unsupported tweaks honest, harden routes, and reduce AI-template UI traits.

IMPLEMENTATION

1. Mark "tcp-winhttp" as unsupported
   File: "electron/tweak-executor.js"

Add "tcp-winhttp" to "UNSUPPORTED_TWEAKS".

Reason text:

“Apply and revert commands are identical. This tweak has no effect on this Windows version.”

Expected behavior:

- frontend shows it as unsupported
- it cannot be applied
- sync/check status reports it as unsupported, not simply “not applied”

Also ensure "checkTweakStatus("tcp-winhttp")" returns:

- "unsupported: true"
- useful "unsupportedReason"
- "isApplied: false"

2. Make “Apply Safe” actually safe
   Files likely involved:

- "client/src/components/tweaks/TweaksList.tsx"
- "client/src/lib/store.ts"
- "client/src/lib/tweak-registry.ts"
- "shared/tweak-tiers.ts"

Do not call "enableRecommended" directly from the Apply Safe button unless it filters through a safety guard first.

Create or use a helper like:

"isRecommendedSafeTweak(tweak)"

A tweak is safe for “Apply Safe” only if:

- "supported === true"
- "risk === "Safe""
- "level === "Recommended""
- "requiresReboot !== true"
- category is not "Network"
- does not disable input devices, networking, Bluetooth, WiFi, audio, print spooler, virtualization, security, or services that could break normal use
- not runtime unsupported
- not in a manual exclusion list

Add a manual exclusion list for known bad “safe” candidates:

- "bluetooth"
- "wifi"
- "fax-printer"
- "xbox-services"
- "hyper-v"
- "vbs"
- "core-isolation"
- "fast-startup"
- "tcp-nagle" if present
- "tcp-winhttp"
- anything unsupported

Change Apply Safe to apply only the filtered safe IDs.

If zero safe tweaks are available, show a toast:
“No safe tweaks available to apply.”

Add console log:
"[ApplySafe] applying ids=... skipped ids=..."

3. Update risky tweak metadata
   Files:

- "client/src/lib/tweak-registry.ts"
- "shared/tweak-tiers.ts"

Update frontend metadata so risky or disruptive tweaks are not presented as basic/safe.

Required changes:

- "fax-printer"
  
  - Rename title to “Disable Print Spooler”
  - Risk: "Risky"
  - Level: "Advanced" or "Experimental", not "Recommended"
  - Warning: breaks printing, PDF printer workflows, Adobe print/export workflows, virtual printers, and printer discovery.

- "bluetooth"
  
  - Risk: "Moderate" or "Risky"
  - Not part of Apply Safe
  - Warning: disables Bluetooth audio, controllers, keyboards, mice, and paired devices.

- "wifi"
  
  - Risk: "Risky" or at least "Moderate"
  - Not part of Apply Safe
  - Warning: removes WiFi access until reverted, only safe for Ethernet users.

- "tcp-winhttp"
  
  - Unsupported
  - No Apply button
  - No premium gating
