TASK

Fix premium gating inconsistency and reduce startup animation time across the Electron app.

PROBLEM

Two issues are present:

1. Startup animation is too long and makes the app feel slow on launch.
2. Premium gating is inconsistent:
   - Power Plan is hard-gated with a proper premium lock experience
   - Network Tweaks is only soft-gated by rendering the full page behind a blur/overlay
   - free users can still see and mount too much premium-only UI

This creates:

- slower first impression
- inconsistent premium UX
- unnecessary component mounting for free users
- reduced trust because premium enforcement feels sloppy

GOAL

- Cut startup / boot animation time down by about 2 seconds total
- Make Network Tweaks use the same hard premium gating standard as Power Plan
- Prevent premium-only pages from mounting expensive/live content for free users
- Standardize one premium lock pattern across the app

FILES TO CHECK

- client/src/App.tsx
- client/src/pages/NetworkTweaks.tsx
- client/src/pages/PowerPlan.tsx
- client/src/pages/AppBooster.tsx
- client/src/pages/FocusMode.tsx
- client/src/components/ui/premium-page-overlay.tsx
- any shared auth / premium gating hooks used by these pages

SECTION 1 — REDUCE STARTUP ANIMATION TIME

In App.tsx, shorten the boot flow aggressively.

Current boot feels too slow because multiple delays stack:

- login_success hold
- welcome intro delay
- welcome container animation
- authenticated app fade
- phase stable gating delay

Change these values:

- login_success timeout:
  1400ms -> 500ms

- WelcomeAnimation introDelay:
  1.7 -> 0.4

- welcome screen animate-in duration:
  2.4s -> 0.8s

- welcome exit duration:
  reduce to around 0.6s to 0.8s max

- authenticated app fade:
  current slow fade/delay -> around 0.35s total with no extra delay

- phase stability gate:
  1600ms -> 500ms

Important:
Do not break flow ordering.
Do not remove polish completely.
Just remove dead time and stacked cinematic delay.

SECTION 2 — HARD-GATE NETWORK TWEAKS

NetworkTweaks currently uses a soft gate:

- content still mounts
- page still renders
- it only blurs with opacity/blur and shows PremiumPageOverlay

That is not good enough.

Make Network Tweaks behave like a truly locked premium page.

Required:

- if user is not premium, do NOT mount expensive premium content
- do NOT mount live diagnostics hooks, polling hooks, or live telemetry-heavy sections unnecessarily
- do NOT render the entire interactive page body under the lock
- show a locked premium state consistent with Power Plan

Preferred pattern:

- render page shell/header
- render limited static preview only if desired
- render one centered premium lock surface
- block all premium controls and background polling

SECTION 3 — STANDARDIZE PREMIUM GATING

Audit premium-only pages and standardize one shared pattern.

Pages to check:

- Network Tweaks
- Power Plan
- App Booster
- any other premium-only page

Need one consistent rule:

- free user = hard gate
- premium user = full page mounts normally

Do not leave some pages using:

- hard modal lock
  while others use:
- blurred background + fully mounted live content

That inconsistency is the bug.

SECTION 4 — PREVENT FREE-USER MOUNT COST

For free users on premium pages:

- avoid mounting live telemetry
- avoid starting diagnostics polling
- avoid route fetches
- avoid expensive graphs
- avoid live network or system hooks unless they are part of a tiny static preview

This is both a UX and performance fix.

Return:

- exact files changed
- exact startup timing values before and after
- exact premium gating logic before and after
- confirmation that Network Tweaks no longer mounts heavy premium content for free users
- confirmation that premium page locking is now visually and behaviorally consistent across pages
