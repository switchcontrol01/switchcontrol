2) Sign out bug: you log out, exit app, it logs you back in

That is a real persistence mismatch.

Root causes

You are clearing auth in the UI store but not clearing the persisted session.

You are using an auth SDK (Supabase, Firebase, Clerk, etc) that has a persistent session cookie and you are not calling the real signOut.

Your app boots and calls “restore session” unconditionally.


Required behavior

If user clicks sign out:

Clear local store

Clear persisted storage (localStorage, indexedDB if used)

Call provider signOut

Clear any refresh tokens

On next app start, do NOT restore a session


What to tell Replit to do

In auth-store.ts or wherever you manage auth:

Ensure signout does all of this:

await auth.signOut() from your provider

clear any tokens in storage

clear Zustand persist if you use it

set user=null, session=null


Add a boot log:
