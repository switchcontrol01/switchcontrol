What you have right now is mostly a UI shell. It looks good, but it is not a real power-plan system yet.

The hard truth: a power-plan page is fake until these 5 things are real:

1. read actual current Windows power state


2. map each card to real Windows settings


3. apply settings through a backend executor


4. verify the settings actually changed


5. persist profile state from real system data, not frontend guesses



Right now the page looks like it is pretending to manage power plans. That is why it feels hollow.

What the backend needs

You need a proper Power Plan backend service in Electron, not scattered tweak calls.

Core architecture

Build it like this:

Frontend

PowerPlan page

calls typed Electron APIs only

never assumes a profile is active unless backend confirms it


Electron preload

exposes:

getPowerProfiles()

getActivePowerProfile()

applyPowerProfile(profileId)

getPowerPlanDetails(profileId)

setPowerSetting(settingKey, value)

verifyPowerProfile(profileId)



Electron main process

owns the real logic

runs PowerShell / powercfg

parses output

returns normalized JSON


Windows layer

uses:

powercfg /list

powercfg /getactivescheme

powercfg /query

powercfg /setactive

powercfg /setacvalueindex

powercfg /setdcvalueindex

powercfg /S

powercfg /SETACTIVE

maybe registry only where truly needed, but avoid registry first



Best way to structure it

Create one backend file like:

electron/power-plan-manager.js

Inside it, define:

listPlans()

getActivePlan()

readPlanSettings(guid)

applyPlanPreset(presetId)

applyIndividualSetting(setting)

verifyAppliedState(presetId)


That is the clean way.

If you keep mixing power plans into generic tweaks, it will become garbage fast.

How the presets should really work

Your cards like:

Maximum Performance

Balanced Gaming

Efficiency / Laptop


should not just be names.

Each preset needs a strict config object.

How to actually apply it

When user clicks Activate Profile:

Step 1

Choose base scheme:

Balanced

High Performance

Ultimate Performance if available


Step 2

Apply every setting one by one with powercfg

Step 3

Re-read the actual values from Windows

Step 4

Return verification result:

success

partial success

failed settings

actual active plan GUID

actual current values


If you skip verification, your app will lie.

Why your current UI still feels fake

Because I can already see the breakdown boxes are likely frontend text, not backend-derived values.

For example:

“Minimal parking allowed”

“Dynamic based on demand”

“Selective suspend enabled”


Those should not be hardcoded labels.

They should come from backend-parsed Windows values.

So when a profile is applied, the backend should send the current values back and the UI should render them.

That means your breakdown section should be driven by:

{
  coreParking: {
    value: 100,
    label: "No parking allowed"
  },
  frequencyScaling: {
    value: "adaptive",
    label: "Dynamic based on demand"
  },
  usbSelectiveSuspend: {
    value: 0,
    label: "Disabled"
  }
}

Not static strings.

What commands matter most

For a usable first version, support these real settings:

active plan

min processor state

max processor state

processor boost mode

core parking

USB selective suspend

PCIe Link State Power Management

sleep timeout

hibernate timeout

display timeout


That is enough to make the page honest.

What to avoid

Do not do this:

fake “active” badge from frontend state only

change card highlight without Windows confirmation

label settings as active based on last click

use registry hacks first

create 50 tiny power tweaks before the core profile system works


That is how these apps become bloated junk.

Biggest design mistake to avoid

Do not make profile detection based on exact equality of every setting unless you control every field.

Windows power configs vary a lot. So detection should be:

strict for core fields you manage

tolerant for unrelated fields

able to say:

exact match

close match

custom modified



Otherwise users click one thing in Windows and your app breaks.

Your Power Plan section has strong visuals, but functionally it is still halfway fake.
