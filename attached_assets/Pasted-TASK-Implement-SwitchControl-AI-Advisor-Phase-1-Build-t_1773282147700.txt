TASK: Implement SwitchControl AI Advisor (Phase 1). Build the correct OpenAI-backed pipeline with secure server-side key. No BIOS changes yet.

PROBLEM
- We need an “AI Advisor” inside SwitchControl that can analyze the user’s system data and give specific, actionable optimization advice.
- We cannot put the OpenAI key in the client (it will be stolen and credits drained).
- Current app needs a clean, scalable architecture for AI features.

WHAT WE ARE IMPLEMENTING
Phase 1: AI Advisor (safe, explain + recommend)
- A server endpoint /api/ai/advice that takes structured system data + user goal, calls OpenAI, and returns structured advice.
- A strict response format (JSON) so the UI can render it reliably.
- Rate limiting and basic request validation.
- Logging that does NOT store sensitive raw dumps.

Phase 2: BIOS Advisor (later)
- Separate endpoint /api/ai/bios-advice that is gated + disclaimers + “verify in BIOS” workflow.
- Not implementing Phase 2 in this patch.

REQUIRED SECRETS / CONFIG
- Add env var OPENAI_API_KEY in Replit Secrets (server only).
- Optional env vars:
  - AI_MODEL=gpt-4o-mini (default)
  - AI_MAX_TOKENS=900
  - AI_RATE_LIMIT_PER_MIN=20

NON-NEGOTIABLE RULES
- Client must never call OpenAI directly.
- No OpenAI key in frontend code or .env committed.
- API returns structured JSON only (no unstructured long essay).
- The model must be instructed to avoid generic advice; it must reference the provided system facts.
