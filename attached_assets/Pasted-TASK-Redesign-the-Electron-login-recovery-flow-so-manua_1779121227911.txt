TASK:
Redesign the Electron login recovery flow so manual code entry is hidden by default and only appears as a fallback after login delays or failures.

PROBLEM:
Current login UX feels unstable and unpolished because the manual auth code UI can appear during normal login attempts. Users should almost never see raw auth/recovery code inputs during successful OAuth flow.

The current behavior makes the app feel:

- unfinished
- debug-oriented
- unreliable
- technically exposed

GOAL:
Create a clean premium login experience with:

- silent OAuth handling
- smooth waiting state
- delayed recovery fallback
- hidden manual code entry by default

EXPECTED LOGIN FLOW:

1. NORMAL FLOW

- User clicks login
- External browser opens
- User authenticates
- Electron deep link returns automatically
- User is logged in
- No manual code UI ever appears

2. RECOVERY FLOW
   Only after:

- timeout
- failed callback
- browser closed
- deep link failure
- auth exchange failure

THEN:

- show subtle recovery UI
- allow retry
- optionally allow manual code entry

IMPLEMENTATION:

1. CREATE EXPLICIT LOGIN STATES

Replace boolean-based auth fallback UI with proper login state management.

Add states similar to:

type LoginState =
  | "idle"
  | "authorizing"
  | "recovery"
  | "failed";

DO NOT use:

- showCodeInput
- isCodeVisible
- scattered timeout booleans

The login UI must render entirely from LoginState.

2. AUTHORIZING STATE

When login starts:

- set state to "authorizing"
- show:
  - loading spinner
  - subtle text
  - animated waiting UI

Example UX copy:
"Waiting for secure browser login..."

DO NOT:

- show code field
- show raw token UI
- show debug auth info

3. SOFT TIMEOUT SYSTEM

Add a soft timeout ONLY for UI fallback.

IMPORTANT:
The actual auth exchange MUST continue running in background.

Behavior:

- after 45 seconds:
  - switch UI state to "recovery"
  - DO NOT cancel auth
  - DO NOT clear auth state

4. RECOVERY STATE UI

Recovery state should show:

- retry login button
- optional expandable manual recovery section

Manual code input must:

- be collapsed by default
- appear secondary
- never dominate UI

Suggested structure:

"Login taking longer than expected"

[Retry Login]

"Having trouble?"
[Expand manual recovery]

Only after expanding:

- show manual code input field

5. REMOVE RAW CODE-FIRST UX

Find and remove any logic that:

- auto-opens code modal
- immediately displays auth code field
- exposes raw callback/token state during normal login

The manual code UI should NEVER appear automatically during healthy OAuth flow.

6. PRESERVE EXISTING AUTH LOGIC

Do NOT break:

- deep link auth
- token exchange
- entitlement refresh
- OAuth callback handling
- browser login flow

This task is ONLY:

- UX cleanup
- state cleanup
- fallback flow cleanup

7. CLEANUP REQUIREMENTS

Remove:

- duplicated timeout logic
- scattered recovery booleans
- auth UI race conditions

Consolidate login flow into:

- one state machine
- one timeout controller
- one recovery renderer

FINAL RESULT:
The login experience should feel:

- premium
- invisible
- stable
- modern
- automatic

Users should only ever see manual recovery options if something genuinely failed or stalled.
