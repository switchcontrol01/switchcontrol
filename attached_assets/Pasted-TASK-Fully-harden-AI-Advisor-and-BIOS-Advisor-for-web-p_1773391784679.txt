TASK: Fully harden AI Advisor and BIOS Advisor for web + packaged Electron

PROBLEM

AI Advisor and BIOS Advisor currently have multiple issues:
- Packaged Electron loads the frontend from file:// but does not start a backend or route /api requests correctly
- Advisor pages still use raw fetch instead of the shared API helper
- x-device-id is supported server-side but not attached client-side
- AI Advisor message rendering uses dangerouslySetInnerHTML without proper sanitization
- BIOS photo upload validation is mismatched between frontend file size and backend base64/body limits
- Current packaged mode behavior has been inferred, not proven with real end-to-end evidence

GOAL

Make AI Advisor and BIOS Advisor safe, consistent, and fully functional across:
- web development
- web production
- Electron development
- packaged Electron

IMPLEMENTATION

1. Packaged Electron backend startup
- Explicitly start the bundled backend in packaged Electron
- Ensure it listens on a known localhost port
- Add readiness detection before advisor requests are allowed
- Add clear startup failure logging

2. Single API base resolver
- Create one source of truth for API base resolution
- Dev web / Electron dev: use dev backend origin
- Web production: use production backend origin
- Packaged Electron: use explicit localhost backend origin
- Remove reliance on raw relative /api fetches from file:// pages

3. Migrate advisor pages to shared API helper
- Replace raw fetch calls in AiAdvisor and BiosAdvisor with the shared API helper
- Ensure consistent credentials and CSRF behavior
- Attach x-device-id when available from Electron preload
- Log resolved API base during development/debug builds

4. Fix AI chat rendering safety
- Remove unsafe HTML injection risk in AI Advisor
- Do not render raw model/user content through dangerouslySetInnerHTML unless it is sanitized first
- Escape HTML before markdown formatting, or switch to a safe markdown rendering path
- Verify that both user messages and model responses cannot inject arbitrary HTML

5. Fix BIOS photo upload validation mismatch
- Align frontend and backend validation so the same image that passes client checks also passes server checks
- Account for base64 expansion if still sending base64
- Prefer a transport/limit strategy that reflects actual request payload size honestly
- Return clear user-facing errors when image size is too large

6. Improve network error handling
- Stop relying on exact err.message === "Failed to fetch"
- Handle network, CORS, backend unavailable, and non-JSON failure cases more robustly
- Show clear user-facing messages for unreachable backend vs validation failure vs server error

7. Prove packaged mode end to end
- Run real packaged Electron tests for:
  - AI Advisor chat
  - BIOS explain
  - BIOS photo-scan with a real BIOS screenshot
- Log:
  - resolved API URL
  - backend startup success
  - backend route hit
  - response status
  - user-visible result

CHECKLIST
- No raw fetch calls remain in advisor pages
- One shared API helper is used everywhere
- Packaged Electron starts a real backend
- Packaged Electron uses an explicit valid API origin
- x-device-id is attached when available
- AI Advisor rendering is safe from HTML injection
- BIOS photo upload validation is aligned across client and server
- Network error handling is more robust than exact string matching
- Packaged mode success is proven with real test evidence

FINAL OUTPUT
Return:
- exact files changed
- exact API base resolution logic
- exact packaged backend startup method
- exact sanitization/rendering fix for AI Advisor
- exact photo upload validation fix
- proof of successful packaged Electron requests for AI Advisor and BIOS Advisor
- any remaining known limitations
