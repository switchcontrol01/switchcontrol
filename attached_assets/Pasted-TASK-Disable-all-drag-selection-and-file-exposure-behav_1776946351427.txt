TASK
Disable all drag, selection, and file exposure behaviors in the Electron app UI.

PROBLEM
Users can:
- click and drag UI elements
- create file:// links to internal app resources
- drop links on desktop
- expose internal app file structure

This breaks product integrity and UX.

GOAL
The app must behave like a native locked interface:
- no dragging UI elements
- no dragging links
- no file:// exposure
- no unintended navigation
- no text selection unless explicitly allowed
- no right-click menu unless custom

REQUIRED FIXES

1. DISABLE DRAGGING GLOBALLY

In renderer (App root or index):

document.addEventListener('dragstart', (e) => {
  e.preventDefault()
})

document.addEventListener('drop', (e) => {
  e.preventDefault()
})

document.addEventListener('dragover', (e) => {
  e.preventDefault()
})

2. DISABLE LINK DRAGGING

For all <a> tags:
- draggable={false}

Also enforce:

document.querySelectorAll('a').forEach(a => {
  a.setAttribute('draggable', 'false')
})

3. DISABLE TEXT SELECTION (EXCEPT INPUTS)

Apply CSS globally:

body {
  user-select: none;
  -webkit-user-drag: none;
}

Allow exceptions:

input, textarea {
  user-select: text;
}

4. BLOCK FILE:// NAVIGATION

In preload or renderer:

window.addEventListener('click', (e) => {
  const target = e.target.closest('a')
  if (target && target.href?.startsWith('file://')) {
    e.preventDefault()
  }
})

5. DISABLE DEFAULT CONTEXT MENU

In main.js:

mainWindow.webContents.on('context-menu', (e) => {
  e.preventDefault()
})

6. DISABLE DEVTOOLS IN PRODUCTION

In main.js:

if (!isDev) {
  mainWindow.webContents.closeDevTools()
  mainWindow.webContents.on('devtools-opened', () => {
    mainWindow.webContents.closeDevTools()
  })
}

7. HARDEN BROWSERWINDOW

Ensure:

webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true
}

8. OPTIONAL: BLOCK NAVIGATION

mainWindow.webContents.on('will-navigate', (e, url) => {
  if (url.startsWith('file://')) {
    e.preventDefault()
  }
})

CHECKLIST

- dragging UI does nothing
- dragging links does nothing
- no .url files created on desktop
- cannot expose file:// paths
- right click does nothing (or custom only)
- text not selectable except inputs
- devtools inaccessible in production

FINAL OUTPUT

Return:
- where drag behavior was coming from
- what listeners were added
- confirmation all drag/navigation vectors are blocked
