TASK

Fix premium grant propagation so the app reflects premium immediately after I click Grant Premium.

PROBLEM

Right now, after clicking Grant Premium in admin, the premium state takes around 10 seconds to show up in the app.

That is too slow and feels broken.

The expected behavior is:

- I click Grant Premium
- the backend confirms success
- the app reflects premium immediately
- premium UI, unlock state, and any related animation render right away

No delayed waiting. No stale entitlement state hanging around.

GOAL

Make premium grants feel instant.

As soon as Grant Premium succeeds:

- the admin panel should update immediately
- the target user’s entitlement should be updated immediately
- the live app should reflect premium without waiting 10 seconds
- unlock UI should trigger instantly if relevant
- no manual refresh should be needed
- no polling delay should be required for basic entitlement visibility

Audit the full chain:

- admin Grant Premium button

Find the exact bottleneck causing the 10 second lag.

Check whether premium state is being delayed because of:

- cached /api/me
- cached entitlement response
- stale React query / SWR / Zustand snapshot
- slow polling interval
- delayed refreshEntitlements call
- backend cache TTL

After Grant Premium succeeds:

- immediately re-read the user’s current entitlement from the backend
- update admin state instantly
- update the app state instantly
- do not wait for background polling

This should be an immediate post-success reconcile, not a lazy eventual update.

4. Add optimistic unlock behavior only after confirmed backend success

Do not fake premium before the write succeeds.

But once the backend confirms success:

- set premium state immediately in the renderer/store
- trigger unlock UI immediately
- trigger premium animation immediately if applicable

That means:

- confirmed success first
- instant UI state switch second

5. Make the target app react in real time

If the app is already open for that user, it should not sit there waiting.

Implement one of these properly:

- immediate entitlements refetch on successful premium mutation
- event-based entitlement invalidation
- IPC/store signal that forces premium reconciliation now
- websocket or live event if already present
- direct local store patch after confirmed response

Pick the cleanest real solution, not a timer hack.

6. Remove artificial delay dependencies

Audit any of these:

- setTimeout before refresh

- delayed auth refresh

- unlock flow tied only to next app navigation
- premium tour/unlock effect only running on app startup

Premium grant must not depend on "wait a bit" or "navigate away and back".

When premium becomes true after a fresh grant:

- unlock animation should run immediately

- entitlement-aware components should re-render immediately

Correct sequence:

- backend write succeeds
- canonical entitlement is refreshed or updated
- all premium UI updates immediately from that confirmed source of truth
