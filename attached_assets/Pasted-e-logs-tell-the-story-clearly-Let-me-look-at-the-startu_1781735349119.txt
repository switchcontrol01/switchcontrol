3 root causes, all fixed:

1. DevTools auto-opening in production (electron/main.js)
The openDevTools({ mode: 'undocked' }) call had zero production guard. Every time the packaged app launched it spawned a second BrowserWindow — white by default — that briefly overlapped the main window. Now wrapped in if (!isProdBuild). Also wired up the existing app:window-shown IPC send that was missing.

2. scale: 1.004 on Splash exit (App.tsx)
The exit animation { opacity: 0, scale: 1.004 } forced Chromium to create a new GPU compositing layer at the exact moment the Splash began fading. On Windows, layer promotion = one white frame. The scale was invisible to the eye anyway (0.4% change). Removed — exit is opacity-only now.

3. Seven simultaneous willChange promotions (CameraGlow.tsx)
Every inner div had willChange: "transform, opacity". CameraGlow activates in the same React batch as the Splash exit, so 7 GPU layers were force-promoted at once — on top of the layer being created by the scale animation. That's a cascade of GPU layer creations in one frame, amplifying the flash. Removed all willChange hints; Framer Motion handles GPU compositing on its own.
