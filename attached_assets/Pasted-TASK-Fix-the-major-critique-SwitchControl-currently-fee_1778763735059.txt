IMPLEMENTATION

1. Tweak credibility audit

Go through all tweak metadata and backend tweak definitions.

Every tweak must be classified into one of these groups:

A. Safe
Registry-only or reversible, low downside.

B. Situational
Can help some users but hurt others depending on hardware, network, or setup.

C. Advanced
Requires the user to understand the tradeoff.

D. Risky
Can break features, security, voice chat, internet, apps, Docker, WSL, or Windows behavior.

E. Unsupported
No reliable implementation, helper missing, fake tweak, or no real verification.

Rules:
- no fake tweaks
- no placebo toggles
- no tweak can show success unless apply + verify passes
- no tweak can be Recommended if it has meaningful downside
- no audio, microphone, Wi-Fi, Bluetooth, or network-risk tweak can be Safe
- no helper-required tweak can appear as working if helper is missing

3. Fix fake slider logic

Audit every slider.

No slider may use fake 0 to 100 ranges unless the real system setting is actually 0 to 100.

For SystemResponsiveness / MMCSS:
- do not expose as a 0 to 100 generic slider
- replace with presets

Example:
- Default Windows
- Gaming Focus
- Aggressive Low Latency
- Custom Advanced

Each preset must show the exact registry value it writes.

SystemResponsiveness must not be explained as “more is better”.
Explain clearly:
- lower values reserve less CPU for background tasks
- 0 can fully disable background reservation behavior
- aggressive values may hurt background audio, capture, streaming, or multitasking

If custom mode exists:
- show exact numeric value
- show warning
- require confirmation if setting 0
