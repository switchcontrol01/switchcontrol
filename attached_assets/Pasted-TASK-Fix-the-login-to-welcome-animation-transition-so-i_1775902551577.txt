TASK

Fix the login-to-welcome animation transition so it no longer hard-cuts instantly from the login screen into the welcome animation.

PROBLEM

After login succeeds, the app instantly cuts to the welcome animation screen.

The welcome animation itself may play, but the transition into it is not fluid.
There is no smooth fade/blur handoff from the login screen.
It feels abrupt and cheap.

GOAL

Make the transition from login screen -> welcome animation fully fluid, premium, and cinematic.

Expected behavior:

1. login succeeds
2. login panel acknowledges success
3. login screen softly fades / blurs out
4. welcome animation scene fades / blurs in smoothly
5. no hard cut
6. no blank frame
7. no snap between screens

IMPORTANT

Do NOT just slow down the existing welcome animation.
Do NOT hard cut to the welcome scene and then animate.
The handoff itself must be animated smoothly.

ROOT CAUSE TO FIX

This is likely caused by auth success immediately switching the entire view tree.

Audit:

* auth success handler
* route/view swap timing
* login component unmount timing
* welcome animation mount timing
* parent shell remounts
* blur/backdrop timing
* AnimatePresence or motion initial states

REQUIRED IMPLEMENTATION

1. Create a controlled post-login transition state.

Suggested stages:

* idle
* authenticating
* login_success
* login_fade_out
* welcome_fade_in
* welcome_complete
* app_enter

Do NOT let auth success instantly hard swap screens.

2. On successful login:

* briefly acknowledge success
* begin login fade/blur out
* keep login scene visually stable during exit
* then reveal welcome animation scene
* then continue into dashboard/app

3. Animate the login scene out:

* slight blur increase
* opacity fade
* optional gentle scale or depth shift
* no snapping
* no immediate unmount visible to user

4. Animate the welcome scene in:

* soft fade in
* blur-to-sharp reveal
* glow/background build
* ensure it feels connected to the login scene

5. Prevent blank/intermediate frames:

* no white flash
* no black flash
* no raw background frame
* no hard auth repaint

6. Keep the transition visually consistent with the app’s premium neon/glass identity.

TIMING

Target:

* total login handoff into welcome animation feels around 1.5s to 2.5s before the main welcome animation proceeds naturally
* smooth, not slow
* premium, not theatrical

TESTING

Replit must test:

* fresh login from logged-out state
* login success into welcome animation
* repeated login/logout cycles
* packaged Electron build, not only dev
* no instant hard cut remains

FINAL OUTPUT REQUIRED

Return:

* root cause found
* files changed
* transition state logic used
* exact login -> welcome transition flow
* confirmation that the hard cut is removed
* confirmation the handoff now fades/blurs smoothly
