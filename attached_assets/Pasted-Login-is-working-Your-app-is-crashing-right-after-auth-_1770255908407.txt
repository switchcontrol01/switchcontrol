Login is working. Your app is crashing right after auth because your Home page is assuming system specs exist, but Electron is returning undefined. That is why it “never loads in the app”.

Ignore the Radix deprecation spam. That is noise.

The real failures are these two:

1. Failed to get system specs: Cannot read properties of undefined (reading 'model')


2. Uncaught TypeError: Cannot read properties of undefined (reading 'toFixed')



That means your UI is doing something like:

specs.cpu.model when specs.cpu is undefined

someNumber.toFixed(...) when someNumber is undefined


So the fix is not auth. It is make system specs always return a safe object, and make the UI null safe.

Below is what to tell Replit to change, with a strict checklist.


---

1) Fix the root cause: IPC “system:getSpecs” must always return a complete object

In electron/main.js, your handler for system:getSpecs is returning incomplete data or failing silently.

Tell Replit: implement a hard fallback contract like this:

Always return:

cpu: { model: string, cores: number, threads: number }

gpu: { model: string }

ram: { totalGB: number }

os: { platform: string, release: string }


Never return undefined fields, even if detection fails

Catch errors and return defaults


Example handler (CommonJS version, pasteable):

const os = require("os");
const { ipcMain } = require("electron");

ipcMain.handle("system:getSpecs", async () => {
  try {
    const totalGB = Math.round((os.totalmem() / (1024 ** 3)) * 10) / 10;

    // If you do not have real hardware detection installed, return safe placeholders
    return {
      cpu: {
        model: os.cpus()?.[0]?.model || "Unknown CPU",
        cores: os.cpus()?.length || 0,
        threads: os.cpus()?.length || 0
      },
      gpu: {
        model: "Unknown GPU"
      },
      ram: {
        totalGB: Number.isFinite(totalGB) ? totalGB : 0
      },
      os: {
        platform: process.platform,
        release: os.release()
      }
    };
  } catch (e) {
    return {
      cpu: { model: "Unknown CPU", cores: 0, threads: 0 },
      gpu: { model: "Unknown GPU" },
      ram: { totalGB: 0 },
      os: { platform: process.platform, release: "" }
    };
  }
});

This alone will stop specs.cpu.model from exploding.

If you are using systeminformation in some file, that is fine, but the rule stays: return a complete object even on failure.

2) Fix the UI: never call .toFixed() unless you verified it is a number

Your crash shows .toFixed on undefined. That usually comes from something like:

CPU usage percent

RAM usage

temps

FPS

ping

anything numeric


Tell Replit to implement a helper:

export function safeFixed(value: unknown, digits = 1, fallback = "0.0") {
  const n = typeof value === "number" ? value : Number(value);
  return Number.isFinite(n) ? n.toFixed(digits) : fallback;
}

Then replace every x.toFixed(1) with safeFixed(x, 1).

Fast band-aid if they refuse: use (x ?? 0).toFixed(1) only if x is guaranteed number. Safer is the helper.
