TASK: Fix Electron Google login flow end-to-end

PROBLEM

The login flow for Electron is unreliable / incorrect.

The current flow starts with:
http://switchcontrol.org/auth/google?source=electron

Problems:
1. It starts with http instead of https
2. Electron source/handoff may not be preserved correctly through OAuth
3. The callback flow needs to return control back into the desktop app cleanly
4. We need a proper deep-link handoff after successful login
5. Web login and Electron login should share auth, but use different final redirects

GOAL

Make Google login work correctly for the Electron app.

Correct flow must be:

Electron app
→ open system browser
→ Google login
→ backend callback
→ backend detects source=electron
→ backend generates one-time auth handoff
→ redirect to switchcontrol:// deep link
→ Electron app receives callback
→ app exchanges code/token safely
→ user becomes logged in

No broken redirects.
No http.
No dead-end browser page.
No ambiguous callback handling.

IMPLEMENTATION

SECTION 1 — FORCE HTTPS FOR ELECTRON LOGIN START

Search for where Electron opens Google login.

Replace any use of:

http://switchcontrol.org/auth/google?source=electron

with:

https://switchcontrol.org/auth/google?source=electron

This must be the only production Electron Google login start URL.

Rules:
- production always uses https
- localhost/dev may use local URLs only in development
- never use http for production auth

SECTION 2 — PRESERVE ELECTRON SOURCE THROUGH OAUTH

The backend must reliably know whether login came from:
- web
- electron

Do not rely only on query params surviving the full OAuth roundtrip.

Use one of these:
- signed cookie
- OAuth state payload
- server-side session flag

Preferred:
When /auth/google?source=electron is hit:
- store auth_source=electron in signed cookie or session
- then start Google OAuth

When callback returns:
- read that stored source value
- if electron, use Electron return flow
- if web, use normal website return flow

Important:
The source must not be lost during redirects.

SECTION 3 — ELECTRON CALLBACK MUST USE DEEP LINK

After successful Google callback, if source=electron:

Do NOT just redirect to website dashboard.

Instead:
1. create a short-lived one-time auth handoff code or token
2. redirect to a deep link like:

switchcontrol://auth/callback?code=ONE_TIME_CODE

Preferred:
Use a short-lived one-time code, not a long-lived JWT directly in the URL.

Then Electron app handles:
- onCallback
- validate payload
- exchange code with backend
- create logged-in session locally/app-side as designed

If your existing app already has deep-link auth handling, reuse that exact mechanism.
Do not invent a second auth callback system.

SECTION 4 — WEB CALLBACK MUST STAY NORMAL

If source is NOT electron:
- continue normal website login behavior
- set session cookie
- redirect to normal website destination

Do not break browser login while fixing Electron.

SECTION 5 — ADD A SAFE TOKEN/CODE EXCHANGE ENDPOINT IF NEEDED

If not already present, add a backend endpoint for Electron handoff exchange.

Example:
POST /api/auth/electron/exchange

Input:
- one-time code

Server verifies:
- code exists
- code not expired
- code not already used
- code belongs to valid auth session

Then return only what the Electron app actually needs.

Rules:
- short expiry (example: 60–120 seconds)
- single use only
- invalidate after exchange
- never allow replay

SECTION 6 — VERIFY GOOGLE CALLBACK CONFIG

Confirm Google OAuth app is configured with the exact production callback URI:

https://switchcontrol.org/api/auth/google/callback

If development callbacks exist, keep them separate and do not mix them into production logic.

Do not change working Google client IDs unless necessary.
Do not break the current website login.

SECTION 7 — ELECTRON APP HANDOFF

In Electron:
- keep using system browser for Google login
- do not embed Google sign-in in a fragile internal browser flow unless already stable
- listen for switchcontrol://auth/callback
- parse callback safely
- reject malformed callback payloads
- exchange code with backend
- complete login
- clear loading state if callback fails or times out

SECTION 8 — LOGIN ERROR / CANCEL HANDLING

If the user:
- closes browser
- cancels login
- callback fails
- exchange fails

Then Electron must return to a clean login state.

No hanging spinner.
No dead blank state.
No partial auth state.

Show a clean message such as:
- Sign in cancelled
- Login failed, please try again

SECTION 9 — ADD LOGGING FOR DEBUGGING

Add safe structured logs for:
- login start
- source detected
- callback hit
- deep-link redirect issued
- exchange success/failure

Do not log:
- JWTs
- OAuth secrets
- raw access tokens

Log only:
- requestId
- source
- result
- error reason if safe

SECTION 10 — VERIFY PRODUCTION URLS

Production:
- website auth start = https://switchcontrol.org/auth/google?source=electron
- callback = https://switchcontrol.org/api/auth/google/callback
- deep link = switchcontrol://auth/callback?code=...

Development:
- allow localhost only if explicitly in dev mode
