TASK

Fix the Live System Monitor GPU line startup behavior on app launch.

PROBLEM

When the app opens, the green GPU line does not render correctly from the start.

Right now it looks broken because:

- the GPU series is not connected immediately
- the line appears late
- I have to wait around 10 seconds before it finally joins and looks normal
- CPU and RAM feel present first, but GPU feels delayed and fake

That makes the graph feel unreliable and unfinished.

GOAL

Make the GPU line behave like a real first-class telemetry stream.

On app launch:

- the GPU line must appear immediately with the rest of the chart
- it must not look disconnected or half-loaded
- it must not wait 5 to 10 seconds to become valid
- the chart should feel already alive from first paint

No fake staggered startup. No delayed visual joining.

IMPLEMENTATION

1. Diagnose the exact startup chain for GPU telemetry

Trace the full flow from:

- Electron telemetry poll startup
- cached telemetry state
- renderer hydration
- chart data normalization
- line rendering conditions

Find exactly why GPU arrives later than CPU and RAM.

I want the root cause identified, not patched blindly.

2. Remove delayed first-valid GPU rendering

If GPU telemetry starts after the other streams, fix that.

The GPU stream must initialize at the same time as CPU and RAM on app boot.

Do not let the renderer wait for a later background cycle before GPU becomes eligible.

3. Seed the chart with valid startup data

The chart should not start with:

- null GPU points
- missing GPU series
- broken segments
- delayed line construction

Use a proper startup seed so GPU has an initial usable value from the first chart frame.

If needed:

- prewarm telemetry before first paint
- read the latest cached GPU value before mounting the chart
- initialize the renderer with a complete telemetry snapshot

4. Keep the series structurally complete

The GPU line must not disappear or render as disconnected because of null / undefined / missing points.

If a value is temporarily unavailable:

- use the last known valid GPU value during startup
- or hold a short boot snapshot
- or mark startup state cleanly without breaking the line

Do NOT let the chart visually break because one source arrives later.

5. Make the boot visually coherent

At first load, all visible lines should feel synchronized:

- CPU
- RAM
- GPU
- Disk if enabled

No one line should feel like it is joining the party late.

6. Fix chart rendering conditions

Audit whether the GPU line is gated behind conditions like:

- showGpu
- gpuAvailable
- usagePct > 0
- source !== null
- telemetryReady
- delayed async state merge

If any of these cause the line to mount late, fix the logic so the series is present from first render whenever GPU exists on the machine.

This system already knows the GPU exists.
So the chart should not behave like it is discovering it 10 seconds later.

7. Preserve truthfulness

Do not fake random numbers.
Do not animate in a pretend line.
