ASK
Fix the startup white flash regression properly. It got worse and lasts longer now.

PROBLEM

The app still flashes white on startup.
The flash is now longer, which means the launch/reveal timing regressed.

This is not acceptable.
The user must never see a white frame, blank white DOM, or half-painted renderer during startup.

ROOT CAUSE AREAS TO AUDIT FIRST

1. Splash / first-frame-ready timing
2. BrowserWindow show timing
3. document/html/body/#root initial background and opacity
4. renderer reveal timing vs app:window-shown handshake
5. any transparent frame before the first dark frame is fully composited

FILES TO AUDIT FIRST
- electron/main.js
- electron/preload.js
- client/src/main.tsx
- Splash.tsx
- index.css
- root app container styles
- any launch opacity/reveal code

PROBABLE FAILURE

Right now app:first-frame-ready is likely firing too early.
The main process then shows the window before the first fully dark stable frame is actually painted.

Also app:window-shown exists, but the renderer reveal path is not clearly using it as the single source of truth.
The handshake is incomplete.

REQUIRED FIXES

1. FORCE DARK ROOT FROM THE EARLIEST POSSIBLE MOMENT

In index.css set these immediately:

html, body, #root {
  background: #07090D !important;
  background-color: #07090D !important;
  margin: 0;
  padding: 0;
  width: 100%;
  height: 100%;
  overflow: hidden;
}

Also ensure body never defaults to white before React mounts.

2. START HIDDEN AT DOCUMENT LEVEL

Before React mounts, renderer root must already be hidden.
Do not wait until after createRoot without an initial hidden state.

Set documentElement and body to opacity 0 at startup, then only reveal later through the launch handshake.

3. USE A REAL TWO-STAGE HANDSHAKE

Correct order must be:

- renderer mounts splash
- renderer waits at least 2 animation frames after splash dark background is definitely painted
- renderer sends app:first-frame-ready
- main process shows window
- main process sends app:window-shown
- renderer then fades opacity from 0 to 1

Do not reveal before app:window-shown arrives.

4. MAKE SPLASH BACKGROUND FULLY OPAQUE

Splash root must have a hard solid dark background.
No transparent root.
No relying on inherited background.
No blur-only layer that allows white underneath.

The very first splash frame must be a full-screen opaque dark surface.

5. REMOVE EARLY REVEALS

Audit for any code in Splash.tsx, main.tsx, or app bootstrap that sets:
- document.documentElement.style.opacity = '1'
- body opacity = 1
- root opacity = 1

before app:window-shown is received.

There must be exactly one reveal path.

6. DO NOT SHOW WINDOW FROM ready-to-show
Keep ready-to-show as logging only.
Window must show only from the first-frame-ready handshake after the splash dark frame is confirmed.

7. ADD DEBUG TIMESTAMPS
Add logs for:
- renderer bootstrap start
- splash mounted
- splash first dark frame painted
- first-frame-ready sent
- mainWindow.show called
- app:window-shown received
- renderer reveal started
- renderer reveal completed

Need exact timing chain in logs.

SUCCESS CRITERIA

- zero white flash on startup
- no brighter frame before splash
- no transparent/blank frame before dashboard
- launch remains dark from first visible pixel
