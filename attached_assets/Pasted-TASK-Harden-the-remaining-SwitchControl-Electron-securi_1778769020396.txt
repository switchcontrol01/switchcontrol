TASK:
Harden the remaining SwitchControl Electron security and stability issues found in the final audit.

PROBLEM:
A few Electron helper paths still rely on weak validation before PowerShell use, and one power plan state file writes directly instead of atomically. These are not launch-blocking payment bugs, but they should be fixed before public release.

GOAL:
Make the remaining helper logic safer, more stable, and less likely to corrupt state or freeze from repeated expensive checks.

IMPLEMENTATION:

1. Harden "startup:setEnabled"
   Find the IPC handler or helper handling startup enable/disable.

Add strict validation before using "registryName", task names, or task paths in PowerShell.

Use a safe regex like:

const SAFE_REGISTRY_NAME_RE = /^[A-Za-z0-9 ._\-()]{1,260}$/;
const SAFE_TASK_NAME_RE = /^[A-Za-z0-9 ._\-()\\\/]{1,260}$/;

function isSafeStartupName(value) {
  return typeof value === "string" && SAFE_REGISTRY_NAME_RE.test(value);
}

function isSafeTaskPath(value) {
  return typeof value === "string" && SAFE_TASK_NAME_RE.test(value);
}

Reject invalid values with:

return { ok: false, error: "Invalid startup entry format" };

Do not build a PowerShell command with unvalidated renderer-provided strings.

2. Harden "startup:setDelay"
   Before creating a delayed startup scheduled task, validate the executable path.

Use something like:

const SAFE_EXE_PATH_RE = /^[A-Za-z]:\\[A-Za-z0-9 ._\-()\\]+\.exe$/i;

function isSafeExePath(value) {
  return typeof value === "string" &&
    value.length <= 260 &&
    SAFE_EXE_PATH_RE.test(value);
}

If invalid, return:

return { ok: false, error: "Invalid executable path" };

Keep the scheduled task name sanitized. Do not allow raw names directly into PowerShell.

3. Make "power-plan-manager.js" state saving atomic
   Replace direct "fs.writeFileSync(STATE_FILE, ...)" with temp-file then rename.

Use this pattern:

function saveState(state) {
  const dir = path.dirname(STATE_FILE);
  if (!fs.existsSync(dir)) fs.mkdirSync(dir, { recursive: true });

  const tmp = `${STATE_FILE}.tmp`;
  fs.writeFileSync(tmp, JSON.stringify(state, null, 2), "utf8");
  fs.renameSync(tmp, STATE_FILE);
}

If rename fails, log the error and do not destroy the existing state file.

4. Cache Focus fullscreen detection
   In "focus-helper.js", the fullscreen trigger currently recompiles C# or runs expensive PowerShell repeatedly.

Fix it so the fullscreen detection helper is loaded once per Focus session, not every 5-second poll.

Target result:

- no repeated "Add-Type" compile every poll
- polling still works
- failures return false instead of crashing the loop

5. Add schema validation to "focus/enable"
   In the server focus route, validate these JSON fields before storing them:

- "electronResults"
- "appliedState"
- "verification"
- "triggerSource"

Use Zod or the existing validation style.

Keep it flexible but bounded:

- objects only
- no arrays unless already expected
- reject extremely large payloads
- reject unknown primitive spam where possible

Example:

const SafeJsonObject = z.record(z.string(), z.unknown()).optional();

const FocusEnableSchema = z.object({
  profileId: z.string().optional(),
  durationMinutes: z.number().int().min(1).max(1440).optional(),
  triggerSource: z.string().max(80).optional(),
  electronResults: SafeJsonObject,
  appliedState: SafeJsonObject,
  verification: SafeJsonObject,
});
