TASK
Build the real backend foundation for the Security / System Integrity page so it stops being placeholder UI and starts returning meaningful live data from the machine.

PROBLEM
Right now the page can look premium but it is not backed by a real system. That kills trust.

Main backend gaps:
1. No real security status contract
2. No real scan job flow
3. No startup / background process analysis pipeline
4. No recommendation engine
5. No proper history storage
6. No real image upload analysis contract
7. No clean premium enforcement on backend responses

GOAL
Create a backend that makes the Security page a real premium feature.

This backend must:
- return actual machine security posture where possible
- support scan actions with real staged progress
- analyze startup apps and background processes for performance/security impact
- generate meaningful recommendations
- store recent scan history
- support image upload analysis flow
- enforce premium access server-side, not just frontend

IMPORTANT
Do NOT build a fake antivirus engine.
Do NOT claim malware detection that does not exist.

Position this backend as:
- system integrity monitoring
- protection status aggregation
- startup/background impact analysis
- performance-aware security recommendations
- visual diagnostic analysis

If some data is not available yet, return explicit capability flags and partial availability, not fake completed results.

3. SECURITY STATUS ENDPOINT
Implement GET /api/security/status

Return a real aggregated status object.

Gather what is realistically available from Windows / Electron / Node side:
- Defender status if accessible
- Realtime protection state if accessible
- Firewall state if accessible
- engine/platform version if accessible
- last scan timestamps if accessible
- fallback capability flags if not accessible

If full Defender integration is not ready, do NOT lie.
Return:
- available: false where appropriate
- source: "partial"
- clear capability flags
- stable placeholder nulls where needed

Example principle:
Good:
"tamperProtectionEnabled: null, capability: unavailable"
Bad:
"tamperProtectionEnabled: true" when not actually known

4. SCAN JOB SYSTEM
Implement a real scan flow instead of instant fake buttons.

POST /api/security/scan/start should:
- validate premium access
- accept scan type:
  - quick
  - full
  - smart
- create a scan job id
- start an async staged scan
- return the job id immediately

The scan job should move through stages:
1. checking protection status
2. reading startup entries
3. inspecting running background processes
4. measuring performance impact
5. building recommendations
6. completed

Store progress in memory first if needed.
The frontend must be able to poll progress.

5. SMART SCAN LOGIC
Smart Scan is the differentiator. Make it real.

It should aggregate:
- protection posture
- startup app review
- high-impact background processes
- overlays / updaters / launchers
- realtime protection overhead indicators
- obvious conflicts between security posture and gaming/performance goals

Do not invent malware findings.
Do produce useful findings like:
- too many launchers/updaters at boot
- Discord overlay / Steam / Epic / OneDrive / RGB apps / vendor services stacking at startup
- protection active but potentially high overhead during gaming
- no critical issues detected
- low startup hygiene
- good balance between security and performance

6. STARTUP ANALYSIS
Add a backend function to inspect startup entries.

Collect:
- app name

- path
- enabled state
- category
- estimated performance impact
- confidence
- recommendation

Classify items into:
- safe
- review
- unnecessary
- high-impact

Do not delete or modify anything yet.
This phase is analysis only.
