REPLIT TASK: Fix SwitchControl Electron “auto logout after login / premium purchase” bug

Goal
- Stop the app from logging the user out automatically after a successful deep-link login or premium return.
- Logout and cookie clearing must ONLY happen when the user explicitly clicks “Sign out”.
- Ensure premium entitlement refresh is resilient to cookie/session timing delays.

What is happening (symptoms)
- Deep link is received correctly: [PremiumFlow] deep-link received: switchcontrol://auth/success?token=...
- Token exchange succeeds: [Auth] Exchanging token for session → success true
- Immediately after, the app triggers logout: [Auth] Electron logout initiated / performFullLogout()
- performFullLogout clears cookies (nuclear option) and destroys the session right after it was created
- /api/me then returns loggedIn:false and isPremium:false, so premium never “sticks”
- Result: “Go to app” feels broken and premium animation never plays

Root cause (most likely)
- There is a code path that calls performFullLogout (or store.logout) as a reaction to a single failed /api/me or a transient loggedIn:false right after exchangeToken.
- This is invalid behavior in Electron because session cookies can take a moment to become available. One failure must not be treated as “user logged out”.

Important rules
1) performFullLogout is ONLY allowed on explicit user sign out.
2) refreshEntitlements / validateToken must NEVER clear cookies.
3) A single loggedIn:false right after exchangeToken must trigger retries, not logout.

STEP 2: Implement safe entitlement validation with retries
Problem scenario
- Right after exchangeToken, /api/me might return loggedIn:false temporarily.
- This can be due to cookie write timing, session store latency, or SameSite/domain issues.
- It MUST NOT cause logout/cookie clearing.

Required behavior
After exchangeToken succeeds:
- Wait 300ms (or 500ms, pick one and be consistent)
- Call /api/me (refreshEntitlements)
- If loggedIn:false:
  - wait 500ms
  - retry up to 6 times total (3 seconds total)
  - During retries, do NOT clear cookies, do NOT logout
- If still loggedIn:false after retries:
  - show UI message: "Session not established, please login again"
  - optionally redirect to login
  - still do NOT clear cookies automatically

Implementation details
- Add a helper in auth-store.ts (or a dedicated util):
  retryRefreshEntitlements({
    attempts: 6,
    delayMs: 500,
    initialDelayMs: 300
  })
- It should return:
  { ok: true, user } when loggedIn true
  { ok: false, reason: "not_logged_in_after_retries" } if still false

STEP 3: Cookie clearing must be restricted
Current behavior to remove
- Any call that invokes electronAPI.clearAuthCookies() from:
  - refreshEntitlements()
  - validateToken()
  - boot validation
  - deep link handling
  - premium activation flow
  - any automatic path

Required behavior
- electronAPI.clearAuthCookies() is called ONLY inside the explicit sign out handler:
  - user clicks “Sign out”
  - then call backend /auth/logout
  - then clear local Zustand store
  - then clear Electron cookies
  - then navigate to login screen
