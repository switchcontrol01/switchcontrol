Replit Task — Fix Slow First Launch + Heavy System Intelligence Blocking

Problem

Tester logs show the app is stable, but startup is still bottlenecked by heavy synchronous system intelligence collection.

Critical evidence from logs:

- App backend healthy in ~726ms
- Dashboard visible around ~4.6s
- Full system intelligence collection takes 38.7 seconds
- Cleaner previously caused black flashes due to transition stacking (already fixed)

Main remaining issue:

[SysIntelligence] Collection complete in 38785ms

This means expensive hardware collection is still running too aggressively during startup.

The app FEELS stable now, but this long-running collection can still:

- Stall Electron thread scheduling
- Cause delayed UI hydration
- Create intermittent black flashes on weaker GPUs
- Delay telemetry readiness
- Hurt perceived polish

---

Goal

Refactor system intelligence collection into staged, non-blocking background phases.

The dashboard should NEVER wait for full hardware intelligence.

---

Required Architecture Changes

1. Split System Intelligence Into 3 Phases

Phase A — Critical Fast Boot (<1s)

Collect ONLY:

- CPU name
- RAM total
- GPU name
- BIOS version
- motherboard model

This phase is allowed during startup.

Everything else deferred.

---

Phase B — Deferred Warm Collection (5s after dashboard stable)

Collect:

- RAM sticks
- display signal analysis
- latency estimates
- instability metrics
- driver metadata
- monitor info

Run AFTER dashboard visible.

Trigger only after:

dashboardStable === true

and:

setTimeout(..., 5000)

---

Phase C — Deep Background Analysis (idle only)

Collect:

- WMI-heavy scans
- SMART data
- firmware analysis
- PCI topology
- advanced telemetry history

Must run ONLY during idle periods.

Use:

requestIdleCallback

or equivalent deferred scheduling.

Never block rendering.

---

2. Add System Intelligence Cache

Current logs suggest every cold launch performs a full scan.

Add persisted cache:

Location:

%APPDATA%/SwitchControl/cache/system-profile.json

Structure:

{
  "timestamp": 1779164499849,
  "profile": { ... }
}

Rules:

- Cache valid for 24h
- Startup uses cache immediately
- Background refresh updates cache later
- UI hydrates from cache instantly

This alone will massively improve perceived startup speed.

---

3. Prevent Blocking WMI Calls

Any WMI query exceeding:

- 3000ms

must:

- timeout
- log warning
- return partial data

Never allow one hanging motherboard sensor query to block the entire intelligence pipeline.

Add timing logs:

[SysIntelligence] phase=cpu elapsed=120ms
[SysIntelligence] phase=ram elapsed=90ms

and:

[SysIntelligence] phase=timeout source=WMI query=Win32_BIOS

---

4. Remove Startup Telemetry Race

Current log order:

telemetry:getLive cache not ready yet

This means dashboard mounts before telemetry warmup completes.

Fix:

- preload telemetry cache before dashboard widgets mount
- dashboard cards should render cached snapshot first
- live updates attach afterward

No "0 values then update later" flash.

---

5. Reduce Dashboard Mount Burst

At:

04:21:44.615 → 04:21:44.618

many API routes fire simultaneously.

Throttle initial dashboard intelligence requests.

Instead of:

6 requests in same frame

stagger:

- 50ms
- 100ms
- 150ms

This reduces Electron renderer spikes.
