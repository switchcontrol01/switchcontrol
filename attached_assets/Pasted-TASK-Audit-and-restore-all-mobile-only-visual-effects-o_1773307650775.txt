TASK: Audit and restore all mobile-only visual effects on desktop

PROBLEM

Some visual effects, animations, parallax layers, shine passes, fades, Framer Motion transitions, glow layers, and decorative motion elements are visible on mobile but missing or inconsistent on desktop.

Example:
- In the hero section, the shine effect on the SwitchControl app example appears on mobile but does not appear on desktop.

This means desktop is not receiving the same intended visual system as mobile.

GOAL

Scan the entire site and identify every effect, animation, motion layer, shine, fade, parallax element, spotlight, glow, hover transition, entrance animation, background effect, and Framer Motion behavior that is active on mobile.

Then ensure those same intended effects are also enabled and visible on desktop unless there is a deliberate design reason not to.

Desktop should not lose effects because of:
- breakpoint hiding
- conditional mobile-only rendering
- z-index issues
- overflow clipping
- different desktop component branches
- broken Framer Motion viewport triggers
- incorrect absolute positioning
- disabled pointer/opacity/display states
- media-query logic
- hydration or mount timing issues

Do not simplify or remove effects.
Do not downgrade the design.
Do not just patch one section.
This must be a full audit across the site.

CONSTRAINTS

- Do not break mobile behavior
- Do not remove existing effects to make desktop "match"
- Do not create duplicate effect layers
- Do not introduce performance-breaking infinite rerenders
- Keep the intended premium design system intact
- Preserve current visual hierarchy and layout
- Do not change content, copy, or section meaning
- Only fix rendering, visibility, triggering, and desktop parity of effects
- Avoid hacks that only work for one viewport size
- If a desktop-specific branch exists, it must include the same intended effect system as mobile

IMPLEMENTATION

SECTION 1 — FULL EFFECT AUDIT

Scan the entire codebase for all visual effect systems, including:

- Framer Motion components
- motion.div / motion.section / motion wrappers
- whileInView / animate / initial / exit / variants
- parallax logic
- spotlight layers
- shine overlays
- glow effects
- gradient or animated overlays
- fade-in / blur-in / slide-in transitions
- hover animations
- floating particles
- background visual stacks
- glass reflections
- pseudo-elements used for light passes
- CSS keyframe animations
- requestAnimationFrame or scroll-driven motion
- conditional rendering based on screen size
- useMediaQuery / isMobile / window.innerWidth / matchMedia usage
- Tailwind breakpoint classes affecting visibility or opacity

Identify all cases where an effect exists on mobile but is missing, disabled, hidden, clipped, or not triggered on desktop.

SECTION 2 — FIND MOBILE-ONLY LOGIC

Specifically search for and fix cases like:

- isMobile-only effect rendering
- window.innerWidth checks that disable desktop effects
- matchMedia branches that remove motion on desktop
- separate mobile and desktop component trees where desktop is missing the effect
- mobile component includes a decorative layer but desktop component does not

Desktop must receive the same intended visual behavior unless explicitly justified in code.

SECTION 3 — FIX BREAKPOINT HIDING

Audit breakpoint-related classes and styles that may hide effects on desktop, including:

- hidden / block / flex
- md:hidden / lg:hidden / xl:hidden
- md:opacity-0 / lg:opacity-0
- scale, translate, blur, visibility, display, pointer-events
- classes that unintentionally disable effect layers at larger breakpoints

Remove or correct any breakpoint logic that causes desktop to lose mobile effects.

SECTION 4 — FIX STACKING AND CLIPPING

Audit all missing desktop effects for:

- z-index issues
- stacking-context issues from transform, filter, opacity, isolation, backdrop-blur
- overflow-hidden clipping
- clipped absolute/fixed elements
- parent containers masking or hiding visual layers
- desktop layout wrappers that bury effect layers behind cards or backgrounds

Ensure each effect is visible in the correct layer order on desktop.

SECTION 5 — FIX POSITIONING AND RESPONSIVENESS

Check all absolutely positioned and decorative visual layers.

Many effects may technically render on desktop but be positioned off-screen or outside the visible focal area.

Fix:
- absolute positioning
- top/left/right/bottom offsets
- transforms
- scale
- width/height
- anchor points
- responsive placement

Desktop should preserve the intended composition, not just technically render the effect somewhere off-screen.

SECTION 6 — FIX FRAMER MOTION TRIGGERS

Audit all Framer Motion and in-view logic on desktop.

Fix cases where desktop layouts break animation triggers because of:
- incorrect viewport thresholds
- incorrect whileInView behavior
- sections starting in a non-triggered state
- grid/layout differences causing motion never to fire
- initial states that stay stuck on desktop
- mount timing issues

Ensure entrance animations, fades, reveals, and motion transitions trigger correctly on desktop.

SECTION 7 — HERO SECTION PRIORITY

Specifically inspect the hero section first.

The shine/light-pass effect on the SwitchControl app example must work on desktop exactly as intended, not only on mobile.

Verify:
- shine layer exists on desktop
- it is not hidden by breakpoint logic
- it is not behind another layer
- it is not clipped
- its animation runs on desktop
- positioning and opacity are correct
- Framer Motion or CSS animation is not disabled on larger screens

SECTION 8 — GLOBAL PARITY PASS

After fixing obvious missing effects, do a full desktop parity pass across all major routes and sections.

Compare mobile vs desktop behavior for:
- hero
- cards
- app mockups
- spotlight/background systems
- fades/reveals
- glow layers
- interactive hover motion
- glass reflections
- section transitions
- decorative ambient effects

Desktop should feel at least as complete and premium as mobile.

SECTION 9 — STABILITY AND BUG PREVENTION

While fixing desktop parity, ensure:
- no duplicated overlays
- no flicker
- no animation loops caused by bad state updates
- no hydration mismatch issues
- no broken layout from z-index changes
- no blocked interaction from decorative layers
- no console errors
- no major performance regression

CHECKLIST

[ ] Hero shine effect works on desktop
[ ] All mobile-only effects have been audited across the site
[ ] Desktop is no longer missing motion/effect layers that exist on mobile
[ ] No breakpoint classes are incorrectly hiding desktop effects
[ ] No desktop effects are buried behind stacking-context or z-index issues
[ ] No desktop effects are clipped by overflow or container structure
[ ] Framer Motion triggers work correctly on desktop
[ ] Absolute-positioned decorative layers are visible and correctly placed on desktop
[ ] Mobile behavior remains intact
[ ] No new visual bugs or console errors were introduced

FINAL OUTPUT

After completing the audit and fixes, report:

- files changed
- sections/components audited
- which missing desktop effects were found
- what caused them
- what was fixed
- whether the hero shine effect now works on desktop
- any remaining effects that still need manual design decisions
