CPU Scheduling & Latency
CPPC
What it is: Hardware hints that help the OS schedule threads to the right cores.
Affects: Latency, frametime stability.
Recommendation: Enable for most Ryzen systems unless you are doing manual fixed-core competitive tuning.
Pros: Better thread placement, less random boosting behavior.
Cons: Can cause core selection behavior you don’t want if you are forcing static clocks.
When NOT to change: If you run a fully fixed overclock and manually manage preferred cores.
CPPC Preferred Cores
What it is: Tells the OS which cores are best for boost and responsiveness.
Affects: Latency, frametimes.
Recommendation: Enable for competitive gaming on Ryzen.
Pros: Better 1 percent lows and responsiveness.
Cons: May increase core hopping in some edge cases.
When NOT to change: If you are pinning games to specific cores.
SMT
What it is: Two threads per core.
Affects: Frametime stability, sometimes latency.
Recommendation: Keep enabled unless a specific game or anti cheat behaves better with it off.
Pros: Higher throughput, better background task handling.
Cons: Some titles can show slightly worse frametimes due to shared resources.
When NOT to change: If you stream, record, or multitask heavily while gaming.
Global C-State Control
What it is: Allows CPU cores to enter deep idle states.
Affects: Latency (wake-up), stability, power.
Recommendation: For ultra low latency, many competitive builds disable or limit deep C-states.
Pros: Reduced wake latency variance.
Cons: Higher idle power, more heat at idle.
When NOT to change: If your system runs hot at idle or you need low idle power.
Package C-State Limit
What it is: Controls how deep the whole CPU package can sleep.
Affects: Latency spikes and frametime consistency.
Recommendation: Limit deep package sleep if you chase consistency.
Pros: Less random hitching under sudden load changes.
Cons: Increased idle power.
When NOT to change: Laptops or systems where power matters.
DF C-States
What it is: Sleep behavior for AMD Data Fabric.
Affects: Memory access latency variance.
Recommendation: Disable for max consistency if available.
Pros: Tighter latency floor.
Cons: Higher idle power.
When NOT to change: If your BIOS is unstable with it disabled.
APIC Mode (x2APIC)
What it is: Interrupt controller mode used by modern OS scheduling.
Affects: Scheduling overhead, stability.
Recommendation: Enable x2APIC.
Pros: Better interrupt handling on modern systems.
Cons: Rare compatibility issues on very old configs.
When NOT to change: Only if you troubleshoot a boot issue.
HPET (BIOS)
What it is: High precision event timer availability.
Affects: Timing sources, latency consistency.
Recommendation: Leave as default unless you have a measured reason to change.
Pros: Can help certain timing edge cases.
Cons: Can worsen performance on some systems depending on OS timer selection.
When NOT to change: If you do not measure changes. This is not a magic FPS setting.
Core Parking (Firmware side)
What it is: Firmware support for parking cores under light load.
Affects: Latency and thread availability.
Recommendation: Reduce aggressive core parking behavior for competitive profiles.
Pros: More immediate core availability.
Cons: More power and heat.
When NOT to change: If your cooling is borderline.
TSC Stability
What it is: CPU time stamp counter consistency.
Affects: Timing accuracy and smoothness.
Recommendation: Prefer stable TSC modes if BIOS exposes them.
Pros: Less timing drift under load.
Cons: Usually not user facing.
When NOT to change: If the BIOS only offers vague options without documentation.
Power & Voltage Behavior
PBO
What it is: AMD boost behavior control.
Affects: Frametime stability, thermals, sometimes latency.
Recommendation: For competitive consistency, either tune PBO properly or keep it conservative.
Pros: Better peak performance.
Cons: More heat, more boost variance if untuned.
When NOT to change: If your cooler cannot handle sustained boost.
Curve Optimizer
What it is: Per-core voltage curve tuning.
Affects: Performance, stability.
Recommendation: Only use if you validate stability. Start conservative.
Pros: Better efficiency, higher sustained boost.
Cons: Can cause silent errors or random crashes if too aggressive.
When NOT to change: If you cannot test properly under load.
LLC
What it is: How VRM compensates voltage droop under load.
Affects: Stability, temps, noise.
Recommendation: Moderate LLC for stability, avoid extremes.
Pros: Prevents voltage sag under spikes.
Cons: Too high can overshoot voltage and increase heat.
When NOT to change: If you do not understand your board’s LLC scale.
CPU Current Capability
What it is: Current limit behavior.
Affects: Sustained performance, VRM load.
Recommendation: Do not max it blindly. Raise only if throttling is confirmed.
Pros: Prevents current limiting.
Cons: Can stress VRM and raise temps.
When NOT to change: Small VRM boards or poor airflow.
Power Phase Control
What it is: VRM phase behavior under load.
Affects: Voltage stability.
Recommendation: Prefer optimized or extreme only for heavy loads and strong VRM.
Pros: Smoother delivery under spikes.
Cons: Higher VRM temps.
When NOT to change: If VRM temps already run hot.
VRM Switching Frequency
What it is: VRM switching rate.
Affects: Ripple, thermals.
Recommendation: Leave default unless you know what you are doing.
Pros: Can reduce ripple at cost of heat.
Cons: Higher frequency increases VRM heat.
When NOT to change: Almost always.
Power Supply Idle Control
What it is: Compatibility setting for low power states.
Affects: Stability.
Recommendation: Set to “Typical Current Idle” if you ever get idle reboot issues.
Pros: Fixes random idle reboots.
Cons: Slightly more idle power.
When NOT to change: If you have no idle issues.
Thermal Throttling Behavior
What it is: How aggressively CPU reduces clocks at temp limits.
Affects: Frametime stability.
Recommendation: Keep safe limits. Consistency comes from cooling, not removing throttling.
Pros: Protects hardware.
Cons: Throttling causes sudden dips if cooling is weak.
When NOT to change: Never disable safety. Improve cooling instead.
Memory & Fabric
XMP / EXPO
What it is: Memory overclock profile.
Affects: Latency, FPS, frametimes.
Recommendation: Enable and validate stability.
Pros: Huge performance uplift vs JEDEC.
Cons: Unstable profiles can cause crashes and stutter.
When NOT to change: If you cannot stability test.
Memory Frequency
What it is: RAM speed.
Affects: Bandwidth, latency.
Recommendation: Use stable sweet spots, not max.
Pros: Better 1 percent lows and responsiveness.
Cons: Too high can increase latency if timings loosen.
When NOT to change: If it forces very loose timings or instability.
Memory Gear Mode
What it is: Controller gear ratio on some platforms.
Affects: Latency.
Recommendation: Prefer the lowest latency ratio that is stable.
Pros: Lower memory controller latency.
Cons: May limit max frequency.
When NOT to change: If it prevents stable boot.
Command Rate
What it is: 1T vs 2T command timing.
Affects: Latency, stability.
Recommendation: 1T if stable.
Pros: Lower latency.
Cons: Harder to stabilize at high speeds.
When NOT to change: If it causes errors.
tRFC and tFAW
What it is: Secondary timings.
Affects: Latency and stability.
Recommendation: Informational only unless advanced user.
Pros: Can reduce memory latency.
Cons: Very easy to break stability.
When NOT to change: If you are not doing memory tuning.
FCLK
What it is: Infinity Fabric clock.
Affects: Latency.
Recommendation: Match stable fabric sweet spot, do not chase max.
Pros: Lower interconnect latency.
Cons: Too high causes instability or performance regression.
When NOT to change: If you get WHEA errors.
UCLK:MEMCLK Ratio
What it is: Memory controller ratio.
Affects: Latency.
Recommendation: Prefer 1:1 when stable.
Pros: Lowest latency.
Cons: May cap max frequency.
When NOT to change: If you need higher RAM speed for other workloads.
Memory Training
What it is: How BIOS trains memory at boot.
Affects: Boot stability and consistency.
Recommendation: Keep enabled unless troubleshooting.
Pros: Improves boot success and stability.
Cons: Longer boot times.
When NOT to change: Only disable for troubleshooting.
Memory Context Restore
What it is: Skips full retraining for faster boots.
Affects: Stability and boot reliability.
Recommendation: Enable only if stable.
Pros: Faster boot.
Cons: Can cause intermittent boot or resume issues on some configs.
When NOT to change: If you ever get random cold boot failures.
EMI / Signal Integrity
Spread Spectrum
What it is: Slight clock modulation to reduce EMI.
Affects: Frametime consistency, micro variance.
Recommendation: Disable for competitive performance profiles.
Pros: Slightly tighter timing consistency.
Cons: EMI compliance tradeoff.
When NOT to change: Corporate or compliance sensitive environments. And Such as external speakers that can sound jitterness and buzzing.
BCLK Stability
What it is: Base clock stability.
Affects: Everything timing related.
Recommendation: Keep BCLK at 100.00 unless you are an advanced tuner.
Pros: Predictable stability.
Cons: BCLK tuning affects many buses and can break USB, PCIe.
When NOT to change: Almost always.
PCIe Spread Spectrum
What it is: EMI modulation on PCIe clocking.
Affects: Latency variance, device stability.
Recommendation: Disable only if stable and competitive focused.
Pros: Slight improvement in timing consistency.
Cons: Rare compatibility issues.
When NOT to change: If you ever see device disconnects.
