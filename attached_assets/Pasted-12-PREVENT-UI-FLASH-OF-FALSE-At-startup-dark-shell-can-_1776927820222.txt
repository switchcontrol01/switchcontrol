12. PREVENT UI FLASH OF FALSE

At startup:
- dark shell can render
- page skeleton can render
- tweak cards can render in loading/neutral state
- but incorrect grey off states must never flash before verification

13. PERSIST VERIFIED SNAPSHOT

After a successful sync:
- persist the verified snapshot to disk / store
- on next app open, you may render cached snapshot instantly only if clearly marked as cached
- then replace with fresh verified results
- cached snapshot must never permanently override live verification

14. ADD DEBUG LOGGING FOR HYDRATION

Temporarily add logs for:
- page mounted
- sync started
- sync requestVersion
- sync finished
- stale response ignored
- store updated from verified state
- cached state loaded
- route remount did not reset state

Need clean console evidence showing:
- no reset to false on mount
- no stale overwrite
- verified truth wins

15. HARDEN AGAINST PREMIUM / FREE TRIAL EDGE CASES

If premium expires while user is inside a premium page:
- first complete revert and state refresh
- then navigate or gate the page
- do not let premium modal cover or replace the revert summary before user sees it
- after revert, re-run full verification so UI reflects the new real state

16. WINDOWS DEFAULT POWER PLAN RULE

When free trial or premium expires:
- premium power plan must revert to Windows Balanced default
- not just "some previous app plan"
- not left active
- not stale in UI

Balanced default must be both:
- applied on the system
- shown correctly in UI after refresh

IMPLEMENTATION DIRECTION

A. Shared store shape

Use a single authoritative store like:

{
  tweaks: Record<string, { status: 'unknown' | 'applied' | 'not_applied', verified: boolean, checkedAt?: string }>,
  networkTweaks: Record<string, ...>,
  nicTuning: Record<string, ...>,
  powerPlans: {
    activePlanGuid: string | null,
    activePlanType: 'balanced' | 'switchcontrol' | 'custom' | 'unknown'
  },
  hydration: {
    started: boolean,
    completed: boolean,
    requestVersion: number,
    lastCompletedVersion: number | null
  }
}

B. Request version pattern

Before every full sync:
- increment version
- capture local version
- when response arrives, apply only if version === currentVersion

C. Card render logic

Status rules:
- unknown = loading shimmer / neutral glow / no grey off styling
- applied = green / active
- not_applied = grey / inactive
- unsupported = separate unsupported styling
- error = warning state, not false state

D. Page behavior

Pages should:
- subscribe to store
- trigger sync if needed
- never rebuild default false state locally
