TASK: AUTH + TELEMETRY ARCHITECTURE STABILIZATION

PROBLEM

The packaged Electron build has architectural instability around auth state, websocket telemetry auth, reconnect handling, and startup hydration.

Current symptoms from production logs:

- Repeated:
  [AUTH] JWT verification failed: invalid signature
  [WS] Rejected telemetry client (invalid or expired token)

- Frontend logs "WebSocket connected" even after backend rejection.

- Premium/auth truth drifts between:
  entitlementsVerified
  isPremium
  storedIsPremium
  persisted auth
  backend auth
  websocket auth

- Startup hydration mounts multiple systems simultaneously causing excessive polling, repeated renders, and unstable initialization order.

GOAL

Create a single stable auth source-of-truth architecture for packaged Electron builds.

Fix websocket auth lifecycle completely.

Prevent reconnect spam and false connected state.

Ensure startup progressively hydrates instead of hard-blocking large subsystems.

IMPLEMENTATION

1. JWT SECRET CONSISTENCY

Audit ALL JWT signing and verification paths.

Verify:

- cloud JWTs
- desktop JWTs
- websocket JWTs
- persisted JWTs

Ensure the SAME secret source is used consistently.

Add explicit diagnostics:

- token issuer
- token source
- signing mode
- verification mode

Prevent fallback secret generation after install/update.

Desktop secrets must remain stable across sessions.

2. WEBSOCKET AUTH LIFECYCLE

Current behavior is incorrect:
frontend marks socket connected before auth succeeds.

Fix flow:

- transport connects
- auth packet exchanged
- backend validates JWT
- ONLY THEN set telemetry state = connected

If auth fails:

- close socket immediately
- set explicit auth_failed state
- do NOT mark connected
- do NOT instantly reconnect

3. RECONNECT BACKOFF

Implement exponential reconnect backoff:

Attempt 1 = 2s
Attempt 2 = 5s
Attempt 3 = 10s
Attempt 4+ = 30s capped

Stop reconnect attempts entirely after repeated auth failures until token refresh occurs.

4. AUTH SOURCE OF TRUTH

Create ONE canonical auth state.

Current architecture appears fragmented across:

- persisted storage
- local state
- entitlement state
- websocket state
- backend verification state

Refactor so:

- backend verification drives truth
- frontend derived states cannot override canonical auth
- persisted state is hydration-only, not authoritative

5. STARTUP HYDRATION

Convert startup into progressive hydration.

Do NOT block initial UI on:

- telemetry
- intelligence
- graphs
- scans
- tweak sync
- websocket connection

Initial dashboard should render immediately with staged subsystem hydration.

6. TIMER / INTERVAL STABILIZATION

Investigate:
[IntervalGuard] setInterval(250ms) clamped to 2000ms

Find all intervals below 1000ms.

Replace aggressive polling with:

- websocket push
- debounced updates
- shared polling loops
- visibility-aware timers
