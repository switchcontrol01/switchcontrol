TASK

Fix packaged Electron backend startup failure caused by missing JWT/session secrets in installed desktop mode.

PROBLEM

The previous MODULE_NOT_FOUND issue is fixed. The packaged backend now actually starts, but crashes immediately with:

[FATAL] Neither JWT_SECRET nor SESSION_SECRET is set. Exiting.

This proves:

- resources/dist/index.cjs now runs
- bundled backend is being launched correctly
- current blocker is runtime secret bootstrapping in packaged desktop mode

GOAL

Make the embedded backend boot successfully in the installed Electron app even when JWT_SECRET and SESSION_SECRET are not manually set in the user’s Windows environment.

IMPORTANT

Do not weaken web production security for switchcontrol.org.

This fix must apply only to packaged Electron desktop backend mode:
process.env.ELECTRON_BACKEND === "1"

IMPLEMENTATION

1. Audit all secret requirements in the server startup path:

- server/index.ts
- JWT setup/self-test
- session/auth config
- any code that throws on missing JWT_SECRET or SESSION_SECRET

2. In packaged Electron backend mode only, provide safe local fallback secrets if env vars are absent.

Example desired behavior:

- if ELECTRON_BACKEND=1 and JWT_SECRET missing, generate/use a deterministic local desktop secret
- if ELECTRON_BACKEND=1 and SESSION_SECRET missing, generate/use a deterministic local desktop secret
- these can be derived from app context or loaded from a persisted file in userData
- they must be stable across launches on the same machine so login/session behavior does not break every restart

3. Do NOT apply this fallback for normal web production mode.
   For web mode, current strict secret enforcement must remain unchanged.

4. Preferred implementation:

- create a desktop-only secret bootstrap helper
- if ELECTRON_BACKEND=1:
  - load secrets from a persisted local file if present
  - otherwise generate strong random secrets once and save them
  - inject them into process.env before JWT/session initialization runs

5. Add explicit startup logs:

- whether ELECTRON_BACKEND is active
- whether JWT secret came from env or desktop fallback
- whether session secret came from env or desktop fallback
- path used for persisted desktop secrets file

6. Rebuild and verify manually with:

cd "C:\Users\SwitchTech\AppData\Local\Programs\switchcontrol-electron"
$env:ELECTRON_RUN_AS_NODE="1"
$env:ELECTRON_BACKEND="1"
$env:PORT="5055"
.\SwitchControl.exe .\resources\dist\index.cjs

7. After backend stays alive, verify:

- http://127.0.0.1:5055/api/health returns 200
- no fatal secret error
- packaged app no longer shows embedded backend timeout banner in AI Advisor
- packaged app no longer shows embedded backend timeout banner in BIOS Advisor

CHECKLIST

Must prove:

- bundled backend launches
- no MODULE_NOT_FOUND
- no JWT/session fatal exit
- /api/health returns status ok
- installed Electron app connects to embedded backend

FINAL OUTPUT

Return with:

- exact files changed
- exact secret bootstrap logic added
- exact startup logs showing fallback secret path/source
- successful /api/health response
- confirmation that AI Advisor and BIOS Advisor now load in the installed app
