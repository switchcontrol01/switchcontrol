ASK: Global Audit & Live Synchronization of Duplicate Tweaks

PROBLEM

Multiple areas of SwitchControl expose the same underlying Windows tweak.

Examples include:

Tweaks

Network Tweaks

NIC Tuning

Extreme Labs

AI Advisor

Dashboard

Apply Recommended

Power Plans

Any future tweak pages


Currently these duplicate tweak cards maintain separate UI state.

Example:

Enable RSS inside NIC Tuning.

Network Tweaks still shows RSS as not applied.

Extreme Labs still shows default.

AI Advisor may recommend enabling it again.


The same issue exists for toggle tweaks, slider tweaks, preset tweaks and profile tweaks.

This causes incorrect UI, inconsistent state, unreliable history, broken revert behaviour and user confusion.


---

GOAL

Perform a full audit of every tweak in the application.

Identify every duplicate tweak regardless of where it appears.

Every duplicate must reference one canonical tweak.

There must only ever be one source of truth.


---

REQUIRED IMPLEMENTATION

Audit every tweak page, including:

Tweaks

Network Tweaks

NIC Tuning

Extreme Labs

AI Advisor

Dashboard

Apply Recommended

Power Plans

Security

Cleaner

Startup

Process Manager

BIOS Advisor

Any hidden or future tweak pages



---

CREATE A CANONICAL TWEAK SYSTEM

Every tweak must contain:

displayId

canonicalId

tweakGroup

tweakType

registry/service/command mapping

currentState

pendingState

defaultState

premiumRequired

restartRequired

verificationMethod


Duplicate cards must never own their own state.

Instead every duplicate card must subscribe to the same canonical tweak object.


---

LIVE SYNCHRONIZATION

If the user changes a tweak anywhere in the app:

Immediately update every duplicate.

No refresh.

No page reload.

No restart.

No manual rescan.

Updates should propagate instantly.

Example:

User enables:

RSS

inside NIC Tuning

Immediately update:

✓ Network Tweaks

✓ Tweaks

✓ Extreme Labs

✓ AI Advisor

✓ Dashboard

✓ Apply Recommended

✓ History

Any other duplicate.

Every card should instantly display:

Applied


---

Same behaviour for:

Disable Nagle's Algorithm

Network Throttling Index

Interrupt Moderation

Receive Side Scaling

Flow Control

LSO

Checksum Offload

EEE

Jumbo Frames

TCP tweaks

Registry tweaks

Power tweaks

MMCSS tweaks

System Timer Resolution

IRQ Priority

Every duplicated tweak.


---

SLIDER TWEAKS

This applies to:

Slider tweaks

Segmented sliders

Preset profiles

Advanced sliders

If a slider changes in one location:

Every duplicate slider must immediately move to the same preset.

Current value

Pending value

Applied badge

Verification

Advanced details

must all remain synchronized.


---

APPLY / REVERT

Applying a tweak anywhere must update every duplicate.

Reverting anywhere must update every duplicate.

Trial expiration must update every duplicate.

Profile loading must update every duplicate.

Import/export must update every duplicate.


---

HISTORY

History should only contain one canonical entry.

Not multiple entries for duplicate cards.

Example:

✔ RSS Enabled

instead of

RSS Enabled

NIC RSS Enabled

Receive Side Scaling Enabled

Network RSS Enabled


---

AI ADVISOR

AI Advisor must use canonical tweak states.

Never recommend a tweak that is already enabled through another page.


---

APPLY RECOMMENDED

Apply Recommended must skip tweaks that are already applied through any duplicate.


---

DASHBOARD

Dashboard tweak counts must use canonical states only.

Never double count duplicates.


---

VERIFICATION

Verification must also use canonical IDs.

If Windows reports RSS enabled:

Every RSS card throughout the app must instantly display:

Applied


---

PERFORMANCE

Do not poll every card individually.

Maintain one centralized tweak state store.

Every UI card should subscribe to the canonical tweak state.

Changes should broadcast to all subscribers immediately.

No duplicate verification loops.

No duplicated registry reads.


---

FINAL OUTPUT

SwitchControl should behave as one unified system.

Every duplicate tweak, regardless of where it appears, should always reflect the exact same live state.

Applying, reverting, verifying, loading profiles, trial expiration, imports, exports, AI recommendations, and dashboard statistics must all stay perfectly synchronized across the entire application using one canonical source of truth.
