A) LOGIN FLOW: Stop the 15s timeout when browser is closed early
Problem:
- Current login waits until the 15s timeout even if the user closes the OAuth browser tab/window or the user cancels sign-in.
Requirement:
- If the user closes the external login window or exits the browser early, the app must immediately stop waiting and return to the login screen with a clean "Sign in cancelled" state (no scary error).
Rules:
- Do not show "cannot display" or "N/A" style messages.
- No broken loading state. No zombie polling.
Implementation options (pick the cleanest based on current code):
1) If using an internal Electron BrowserWindow for auth:
   - Listen for `win.on("closed")` and resolve the auth promise as cancelled.
   - Also listen for `webContents.on("did-navigate")` / token callback. If not reached and window closes, treat as cancelled.
2) If using `shell.openExternal` to system browser:
   - Add a lightweight local callback server or deep-link scheme listener already in place.
   - When auth starts, create an AbortController.
   - Add a "Cancel" action in the app UI which aborts immediately.
   - Detect premature cancel by:
     - if auth browser never hits callback within X seconds AND user triggers app focus or cancel, abort without waiting for 15s.
   - Minimum acceptable: Add an explicit cancel button that cancels instantly. Best: Detect cancel when user closes an in-app auth window.

Acceptance checks:
- Start login, close browser immediately: app returns to idle state in under 1 second.
- Start login, complete login: works as before.
- Start login, do nothing: timeout still works and shows a calm retry prompt.
- No memory leak: repeated login attempts do not stack timers or listeners.

F) GPU MODAL: It opens but shows no data
Problem:
- GPU icon works but modal displays nothing or fails to render telemetry.
Likely causes:
- IPC handler not returning expected shape
- renderer expecting different keys
- load field mismatch (`utilizationGpu` vs `load`)
- memoryUsed sometimes undefined and UI not handling it correctly
Requirement:
- Fix GPU telemetry fetch and render only available fields, with clean conditional rendering.
- No "N/A" lines. If a metric missing, omit the row/section.

Implementation checklist:
1) Confirm IPC handler exists: `telemetry:getGpu`
2) Return shape must be consistent:
   - model
   - driverVersion
   - vram
   - memoryUsed (optional)
   - load (optional)
   - temperature (optional)
   - powerDraw (optional)
   - clockCore (optional)
   - clockMemory (optional)
3) In renderer:
   - if GPU data is null: close modal quietly and do nothing (or don’t open).
   - if load is undefined: omit load bar
   - if memoryUsed undefined: omit VRAM section and VRAM line on graph
4) Add 30-sample rolling buffer for graph with polling 800ms.

Acceptance checks:
- On machines with GPU telemetry: GPU modal shows model and at least one metric.
- No empty skeleton forever. No broken layout.
