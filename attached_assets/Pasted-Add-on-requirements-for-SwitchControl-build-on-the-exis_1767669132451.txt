Add-on requirements for SwitchControl (build on the existing app you generated)

Goal
Expand the Tweaks section to be far more comprehensive and structured than competitors, while keeping this build UI-only with simulated toggles and scan history logging. No real Windows changes. Add strong organization, search, filters, risk labels, and “Requires local Windows agent” tags.

Tweaks Page Upgrade
1) Add a top bar with:
- Search input: “Type to search for tweaks”
- Filter chips: All, Recommended, Advanced, Experimental, Privacy, Latency, GPU, Network, Debloat, Services, Visuals
- Sort dropdown: Default, A-Z, Risk (low to high)

2) Add grouping by category with collapsible sections:
- System and Power
- Memory and Storage
- Privacy and Telemetry
- Gaming and Latency
- Input (Keyboard and Mouse)
- GPU and Graphics
- Services and Background
- Windows UX and Visuals
- Debloat and Apps

3) Each tweak should render as a card row like the reference screenshots:
- Title
- One-line description
- Badge: Recommended / Advanced / Experimental
- Badge: Safe / Moderate / Risky
- Tag: Requires local Windows agent
- Toggle switch ON/OFF
- Optional small “info” button opening a modal with:
  - What it does
  - Expected impact (FPS, 1% lows, latency, privacy, boot time)
  - Risks
  - Revert notes

4) Every toggle change must:
- Update UI state (simulated)
- Add an entry to Scan History with timestamp, tweak name, ON/OFF, and a result message like “Simulated apply”
- Persist to localStorage so the toggles remain after refresh

Data model updates
- Add a “tweaks” store in localStorage keyed by tweak id
- History entries should include: category, tweakId, beforeValue, afterValue
