- apply debloat action

Identify:

2. CREATE / FIX REAL DEBLOAT ENGINE
Implement a real backend debloat engine.

Suggested structure:
- debloat-engine.ts
- debloat-profile-registry.ts
- debloat-execution-service.ts
- debloat-restore-service.ts
- debloat-verification-service.ts

This engine must support:
- profile-based selection
- mode-based aggressiveness
- apply selected debloat actions
- restore selected items where supported
- verify resulting state
- return structured results

3. REAL ITEM DEFINITIONS
Each debloat item shown in the UI must map to a real backend definition.

Each item should define:
- id
- display name
- type (app / feature / suggestion / service / optional component)
- category
- removal method
- restore method if available
- safety level
- supported modes
- supported roles/profiles
- requires admin
- verification method
- limitations / unsupported notes if needed

Examples:
- Microsoft Teams
- Feedback Hub
- People App
- Windows Tips
- Xbox components
- optional consumer apps
- suggestions/promotional surfaces
- optional system features where safe

IMPORTANT:
Do not include dangerous removals without clear safety framing.

4. REAL APPLY DEBLOAT FLOW
Implement real apply logic.

When user clicks apply:
- gather selected items
- map to real system removal actions
- execute them
- verify removal state
- return structured results

Removal methods may include:
- Appx package removal
- provisioned package removal
- optional feature disable/remove
- registry/policy toggles for suggestions/tips where applicable

The backend must decide and run the proper action per item.

5. REAL RESTORE FLOW
Implement real restore logic where possible.

Restore should only be available if the item actually supports it.

Examples:
- reinstall Appx package where recoverable
- restore policy/reg settings
- re-enable feature where supported

If restore is not realistically supported:
- mark item as not restorable
- do NOT fake a restore badge or button

6. VERIFICATION
This is critical.

After remove or restore:
- verify actual system state

Examples:
- query Appx package presence
- query provisioned package state
- query optional feature state
- read policy/registry values
- verify service/component state

If verification fails:
- do not mark success
