THE REAL PROBLEMS (2 of them)

There are two independent bugs causing the bad behavior you see.


---

PROBLEM 1: system specs IPC returns undefined → crashes UI

This line is the smoking gun:

Failed to get system specs: TypeError: Cannot read properties of undefined (reading 'model')

And later:

Uncaught TypeError: Cannot read properties of undefined (reading 'toFixed')

What this means

Your frontend assumes IPC data exists.

Example (simplified):

const cpuModel = specs.cpu.model
const ramPercent = memory.usage.toFixed(1)

But in Electron:

IPC handler returned undefined or {}

Or returned partial data

Or returned data later than expected


So React renders → crashes → remounts → repeats.


---

REQUIRED FIX (non-negotiable)

You must defensive-code IPC data.

Tell Replit to do this everywhere system data is read:

if (!specs || !specs.cpu) {
  return <Skeleton />
}

and never call .toFixed() without a guard:

const usage = typeof ramUsage === "number" ? ramUsage.toFixed(1) : "0.0"

If Replit resists, tell it:

> Desktop IPC data is not guaranteed. UI must tolerate undefined or delayed values.



This is standard Electron behavior.


---

PROBLEM 2: Infinite remount loop (your “MOUNT Home” spam)

This spam:

MOUNT Home
MOUNT Home
MOUNT Home

means React is re-mounting the page constantly.

This is NOT StrictMode.
This is NOT Electron.
This is a state feedback loop.


---

Root cause (very likely)

One of these patterns exists in Home or a parent component:

useEffect(() => {
  fetchSystemInfo()
}, [systemInfo])

or

setState(...) → causes rerender → triggers same effect again

Or worse:

useEffect(() => {
  navigate("/home")
})

Any of these cause infinite remount.


---

REQUIRED FIX

Tell Replit to:

1. Find every useEffect in Home


2. Ensure dependencies are stable


3. Ensure no navigation or state set runs unconditionally



Correct pattern:

useEffect(() => {
  fetchOnce()
}, []) // empty deps

OR guarded:

useEffect(() => {
  if (!loaded) {
    fetchOnce()
    setLoaded(true)
  }
}, [loaded])
