PROBLEM

We now have strong blueprint images, but if they are mounted loosely they will either:

replace the background atmosphere

sit like wallpaper

cluster together and feel messy

fight the hero text instead of supporting it


The current purple gradient and lighting already work. We are not replacing that.

AIM

Add the uploaded blueprint images as soft atmospheric overlays inside the existing website background system.

They must:

stay behind the hero text

stay above the base background

feel embedded in the atmosphere

be slightly blurred

drift slowly

be positioned intentionally, not randomly

preserve readability and premium depth


WHAT WE ARE ACHIEVING

We want a layered premium SaaS background with:

technical engineering vibe

subtle motion

atmospheric depth

image-based detail without looking like a wallpaper


The page foundation stays:

dark base

purple/cyan lighting

glows

beams

existing 3D atmosphere


The images are only supporting layers.


---

IMPLEMENTATION

STEP 1: Upload images

Put the uploaded files here:

client/public/assets/blueprints/

Use these exact names:

bp-parts.png → exploded motherboard / fan / hardware parts image

bp-chip.png → layered chip / CPU image

bp-graphs.png → graph / telemetry blueprint image


Do not compress them aggressively. Do not crop them again in code. Do not use them as page background images.


---

STEP 2: Create a strict overlay component

Create:

client/src/components/website/BlueprintImageOverlay.tsx

Use one overlay wrapper containing exactly 3 images, each with a fixed role:

bp-chip = hero support image

bp-graphs = right-side telemetry layer

bp-parts = lower atmospheric engineering layer


Important rules:

no image should use background-size: cover

no image should fill the entire viewport

all images should be absolutely positioned

all images should use low opacity

all images should use blur

all images should use screen blend mode

all images should animate slowly



---

STEP 3: Use this exact visual layout

Layer A: Chip image

Use bp-chip.png

Purpose: Primary technical focal overlay behind the hero area.

Placement:

top: around 10%

left: around 52%

translateX: around -10%

width: around 34vw

max-width: around 520px

rotate: around -10deg


Visual treatment:

opacity: 0.08

blur: 5px

contrast: slightly raised

mix-blend-mode: screen


Animation:

very slow drift

slight upward/downward motion

tiny scale breathing

duration: 34s to 40s


This image should sit behind the hero text but not directly under every letter. It should bias slightly to the right so the text still reads clean.


---

Layer B: Graph image

Use bp-graphs.png

Purpose: Telemetry / systems / tuning signal detail on the right side.

Placement:

top: around 24%

right: around -6%

width: around 42vw

max-width: around 720px

rotate: around 6deg


Visual treatment:

opacity: 0.055 to 0.07

blur: 7px

mix-blend-mode: screen


Animation:

slow lateral drift

almost imperceptible

duration: 38s to 46s


This one should feel farther back than the chip. It should not dominate the hero. It is support only.


---

Layer C: Parts image

Use bp-parts.png

Purpose: Atmospheric engineering layer lower on the page so the site has depth beyond the hero.

Placement:

bottom: around -6%

left: around -8%

width: around 40vw

max-width: around 700px

rotate: around -4deg


Visual treatment:

opacity: 0.05 to 0.065

blur: 8px

mix-blend-mode: screen


Animation:

slow drift upward/right

duration: 42s to 50s


This should feel like a buried layer in the atmosphere, not a visible product image.


---

STEP 4: Mount it in the correct place

Open:

client/src/components/website/WebsiteBackground.tsx

Import the overlay component.

Mount order must be:

1. base dark background


2. gradient foundation


3. glow/rim lighting base


4. BlueprintImageOverlay


5. beams / shine / fog / atmosphere


6. grid or subtle line overlays


7. page content above everything



This is critical.

Strict layering rules

WebsiteBackground main wrapper: absolute inset-0 z-0

BlueprintImageOverlay: inside that background stack

hero/page content wrapper: relative z-10


Do not mount the images inside the hero text container. Do not mount them inside the mockup container. Do not use them as CSS backgrounds on body, main, section, or hero.

They are environmental overlays only.


---

STEP 5: Add motion carefully

All three images need slow drifting keyframes.

Rules:

duration must be at least 30s

no large movement

no spinning

no parallax jumps

no opacity pulsing

no strong zooming


Use movement ranges like:

X shift: 10px to 30px

Y shift: 8px to 22px

scale shift: 1.00 to 1.04


That is enough.

If motion is obvious, it is too much.


---

STEP 6: Blur and opacity rules

Hard limits:

opacity floor: 0.045

opacity ceiling: 0.085

blur floor: 4px

blur ceiling: 8px


If any image becomes clearly readable at first glance, reduce opacity first, not blur.

The goal is: felt, not read


---

STEP 7: Mobile safety

On screens below tablet/mobile:

reduce all blueprint image opacities by about 40%

disable drifting animation

keep images static

keep same layering

preserve atmosphere without GPU load


Do not remove them entirely unless mobile performance becomes bad.


---

DO NOT DO

Replit must not do any of this:

do not replace the current background

do not set any uploaded image to full-screen cover

do not center all 3 images together

do not make them sharp

do not place them above text

do not use high opacity

do not animate them aggressively

do not let them interfere with CTA readability

do not create a collage effect
