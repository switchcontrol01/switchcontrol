TASK
Fix SwitchControl telemetry architecture to eliminate CPU spikes, PowerShell spam, duplicate pipelines, and inconsistent data. This is a hard performance patch. No UI work. No partial fixes.

PROBLEM
Telemetry is currently inefficient and duplicated:
- Two telemetry pipelines run at the same time (Electron + embedded backend)
- PowerShell GPU polling runs every 2s (constant CPU load)
- systeminformation is called from multiple places (main loop + IPC handlers)
- networkStats runs every tick with no TTL
- si.graphics() runs inside loop even though it is static
- Tweaks page triggers 40+ PowerShell calls at once

This causes:
- CPU spikes
- stutter / lack of smoothness
- inconsistent telemetry timing
- poor performance on low-end systems

GOAL
Single telemetry pipeline.
No duplicate system calls.
No PowerShell spam.
All reads from cache.
Smooth, low-overhead, stable telemetry.

IMPLEMENTATION

1. Kill duplicate telemetry pipeline (CRITICAL)
In server/routes.ts:

Replace:
startTelemetryPolling(1000);

With:
if (process.env.ELECTRON_BACKEND !== '1') {
  startTelemetryPolling(1000);
}

Result:
- Web version uses server telemetry
- Electron uses main.js telemetry only
- No duplicate systeminformation calls

2. Add GPU PowerShell TTL (CRITICAL)
In electron/main.js:

Add:
const GPU_POLL_TTL_MS = 15000;

Modify pollTelemetry():

Add:
const gpuPollDue = (Date.now() - _gpuLoadPollLastTs) > GPU_POLL_TTL_MS;

Replace GPU polling block with:
if (!_overBudget && !inCooldown && gpuExistsOnHardware && gpuPollDue) {
  const gpuLoad = await getGpuPerfCounterLoad().catch(() => null);
  _gpuLoadPollLastTs = Date.now();
}

Result:
- No constant PowerShell spawning
- GPU load updates every 15s max
- CPU usage drops significantly

3. Remove si.graphics() from loop
In pollTelemetry():

REMOVE:
const gpuStatic = await getGpuStatic().catch(() => null);

REMOVE all logic merging gpuStatic into runtime data

Ensure GPU static data is ONLY loaded once during startup

Result:
- Removes 300–600ms blocking calls per tick

4. Add networkStats TTL
At top of main.js:

const NET_STATS_TTL_MS = 5000;
let _netStatsLastTs = 0;

In pollTelemetry():

Replace:
si.networkStats()

With:
const shouldPollNet = (now - _netStatsLastTs) >= NET_STATS_TTL_MS;

Use:
shouldPollNet 
  ? si.networkStats().catch(() => [])
  : Promise.resolve(null)

After call:
if (shouldPollNet && netStats) _netStatsLastTs = now;

Fallback:
use last cached netStats if not refreshed

Result:
- Prevents slow NIC drivers from blocking loop
- Stabilizes telemetry timing

5. Force IPC to use cache only (CRITICAL)
In electron/main.js:

Update:
ipcMain.handle('telemetry:getBasic')
ipcMain.handle('telemetry:getEnhanced')

REMOVE all direct calls to:
- si.currentLoad()
- si.mem()
- si.cpuTemperature()

Replace with:
Read from liveTelemetryCache only

If cache not ready:
return safe zero/default values

Result:
- No duplicate WMI/systeminformation calls
- No contention
- Consistent telemetry data

6. Enforce single telemetry source
RULE:
Only pollTelemetry() is allowed to call systeminformation.

Everything else:
- WebSocket
- IPC handlers
- UI

MUST read from:
liveTelemetryCache

Add dev log if violated:
[TelemetryViolation] direct systeminformation call outside main loop

7. Delay telemetry start after app load
In App.tsx or ElectronAppContent:

Delay telemetryManager.start() by ~2000ms after UI load

Result:
- No competition with startup animation
- smoother app entry

8. Optimize tweak:syncAll (PowerShell spam)
Do NOT run all tweak checks at once.

Change behavior:
- Only run checks for visible tweaks (viewport)
- Run additional checks when:
  - user scrolls
  - category expands
