IMPORTANT CONTEXT
The packaged desktop app runs a LOCAL Electron backend.
That local backend is allowed to be offline / no DATABASE_URL / no Stripe / no OAuth secrets.
That is expected.
So in local Electron mode:
- Stripe init must not run
- admin bootstrap must not run
- cloud-only startup work must not run
- missing cloud secrets must not emit prod-looking errors
- auth should be handled by the cloud server, not by pretending local OAuth is broken

REQUIRED FIXES

SECTION 1 — FIX STRIPE STARTUP PATH PROPERLY
In Electron local backend mode:
- do not call Stripe init
- do not await Stripe init
- do not let Stripe init time out
- do not emit stderr error logs for expected missing Stripe secrets
- do not let downstream startup code treat missing Stripe as an error

Implement one single mode gate at the real startup orchestration layer, not just inside Stripe helper internals.
Cloud/server mode can still initialize Stripe normally.
Electron local backend mode must short-circuit before the task is scheduled.

SECTION 2 — FIX ADMIN BOOTSTRAP STARTUP PATH PROPERLY
In Electron local backend mode:
- do not call ensureAdminUsers
- do not schedule it
- do not let it time out
- do not log anything as error about it

This is cloud/server responsibility only.
The local desktop backend should not try to bootstrap admin DB state.

SECTION 3 — FIX ALL PREMATURE AUTH-PROTECTED FETCHES
Find every page, hook, interval, and mount effect that requests protected endpoints before auth is ready.

Protected endpoints must not fire unless ALL are true:
- auth bootstrap finished
- token/session is validated
- user exists
- user.loggedIn === true

Do not use weak guards like just checking token presence.
Do not fire during splash / boot / pre-hydration / stale-token state.

Fix all of these routes:
- `/api/focus/state`
- `/api/focus/history`
- `/api/network-tweaks/state`
- `/api/cleaner/categories`
- `/api/cleaner/history`
- `/api/cleaner/scan-history`
- `/api/app-booster/games`

Audit all polling and refetch intervals tied to these too.
If a page is auth-only, its initial protected fetches should not start until auth confirmed.
If a component is mounted before auth, it must stay idle.

SECTION 4 — REMOVE COOKIE / SESSION DEBUG NOISE FROM PROD
In packaged production:
remove or disable these logs entirely:
- startup cookie enumeration
- raw cookie object dumps
- set-cookie received logs
- set-cookie values logs
- any session/csrf debug dump not required for normal prod support

Keep logs only if they are genuinely necessary and redact values.
Default should be silent in prod.

SECTION 5 — STOP DUPLICATE DISPLAY-SIGNAL DEMAND
Audit why `/api/dashboard-intelligence/display-signal` is hit twice back-to-back.
If two frontend consumers are independently fetching the same cached resource, unify them.
Use shared hook/state/query cache if appropriate.
Do not break UI.
Goal is one logical demand path, not two immediate callers for the same result.

SECTION 6 — CHECK FOR OTHER STARTUP DEAD WORK
Audit startup orchestration for other cloud-only tasks still running in Electron local backend mode.
Anything that is guaranteed unavailable locally should be skipped, not attempted then logged as warning/error later.

Examples:
- cloud health/session sync loops that churn cookies without user value
- cloud-only admin setup
- billing bootstrap
- other server-only initialization
