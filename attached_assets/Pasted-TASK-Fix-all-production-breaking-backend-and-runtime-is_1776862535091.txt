SECTION 1: FORCE REAL DATABASE IN PRODUCTION
==================================================

PROBLEM
Production backend is still booting in NO-DB mode because DATABASE_URL is missing from the packaged backend child process.

REQUIRED FIX
1. Find every place where NO-DB mode is enabled.
2. Make sure that mode can only happen in development.
3. In production, missing DATABASE_URL must be a fatal startup error, not a fallback.

IMPLEMENTATION
- Add a hard guard near DB initialization:

if (process.env.NODE_ENV === 'production' && !process.env.DATABASE_URL) {
  throw new Error('[FATAL] DATABASE_URL missing in production. Refusing to boot in NO-DB mode.');
}

- If there is an isNoDbMode flag, ensure it is something like:
  const isNoDbMode = process.env.NODE_ENV !== 'production' && !process.env.DATABASE_URL;

- Ensure electron/main.js passes DATABASE_URL through to the packaged backend child process.
- Audit the backend launcher env object and make sure DATABASE_URL is explicitly forwarded into the child process env.
- Confirm the packaged backend receives it by logging only presence, never the value:
  DATABASE_URL in child env: YES

- If packaged production is intended to support offline mode, then that must be an explicit, separate mode. Do not reuse dev NO-DB fallback for production.

ACCEPTANCE
- No "Running in DEV NO-DB MODE" in production logs
- No "Database features are disabled" in production logs
- Production boot fails early and clearly if DATABASE_URL is absent
- DB-backed features actually persist data between launches

SECTION 3: FIX FOCUSMODE DB INIT CRASH
==================================================

PROBLEM
FocusMode is trying to call db.execute while db is null.

REQUIRED FIX
FocusMode backend init must not run DB code unless DB is ready and present.

IMPLEMENTATION
- Trace the exact file where FocusMode initializes tables or state.
- Find the current init path producing:
  Cannot read properties of null (reading 'execute')

Then fix as follows:

1. If DB is required for FocusMode persistence:
   - block initialization until db exists
   - fail cleanly if db missing in production

2. If DB is optional in dev:
   - guard dev mode only
   - never attempt db.execute if db is null

Example:
if (!db) {
  if (process.env.NODE_ENV === 'production') {
    throw new Error('[FocusMode] DB missing in production');
  }
  console.warn('[FocusMode] Skipping DB init in dev because db is unavailable');
  return;
}

3. Ensure table init runs after DB bootstrap, not before.
4. Confirm FocusMode routes do not assume persistence tables exist before init finishes.
5. Audit any race between import-time init and runtime DB setup. Move init out of top-level module execution if needed.

ACCEPTANCE
- No FocusMode init errors in logs
- FocusMode routes work without null DB crashes
- Persisted FocusMode state/history actually saves when DB exists
