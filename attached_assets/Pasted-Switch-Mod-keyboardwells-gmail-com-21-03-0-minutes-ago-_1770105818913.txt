What is happening (short + factual)

Unpacked app (dev / portable exe)
Runs straight from the build folder.
Assets are loaded from relative paths that still exist on disk.
Your animation, logo glow, splash, etc all work.

Installed app (NSIS installer)
App is copied into Program Files.
Electron now loads from an asar bundle.
Any asset that is:

referenced by a relative filesystem path

loaded via file:// assumptions

not inside the Vite build output


will silently fail.


That is why:

OAuth deep link works

App opens

BUT animation / logo effects are missing


This is a packaging problem, not an Electron logic problem.


---

The root cause (this is the key insight)

Your animation assets are not guaranteed to be inside the renderer bundle.

Typical mistakes that cause exactly this:

Using /public/... paths that Vite doesn’t inline

Using fs paths in renderer

Using __dirname or process.cwd() in UI

CSS background images pointing to files not emitted

Lottie / video / SVG not imported as modules


Unpacked works. Installed breaks. Classic symptom.


---

The fix (what MUST be true)

Rule 1: Renderer assets must be imported, not referenced

❌ Bad (breaks in installer):

<img src="/logo.png" />
background: url("/glow.png");

✅ Correct (bundled):

import logo from "@/assets/logo.png";
<img src={logo} />

CSS:

background-image: url("../assets/glow.png");

(where the file is imported by Vite)


---

Rule 2: Animation assets must live in client/src

NOT:

/public

/electron

root folder


YES:

client/src/assets/
client/src/animations/

And referenced via import:

import glowAnim from "@/animations/glow.json";


---

Rule 3: No filesystem paths in renderer

If you have anything like:

fs.readFileSync(...)
path.join(__dirname, ...)

inside React / renderer — that will fail in installed builds.

Renderer must be pure web.
