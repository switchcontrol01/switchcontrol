PHASE 8 — FRONTEND ADMIN PANEL
==================================================

Create a real admin panel.

Locations:
- Website: /admin
- App: a new Settings tab called “Admin”

IMPORTANT:
- this tab/route must only be visible to admin account
- non-admin users must never see or access it
- backend must still block access even if a non-admin manually hits the route

Design style:
- glass / milky translucent
- consistent with SwitchControl visual language
- soft blur
- subtle borders
- glow
- smooth transitions
- polished and premium, not generic admin junk

UI structure:
A) User Table
- email
- user id
- plan
- last login
- app active status
- installed app yes/no
- search + pagination

B) User Detail Panel
- full breakdown
- plan / entitlement status
- activity
- flags
- tweak history if available
- notes/reasons if trial note exists

C) Action Panel
- Set Free
- Set Trial
- Set Premium
- Reset Onboarding
- Reset Premium Tour
- Reset Premium Unlock Seen
- Delete User
- Trial controls

D) Trial Management Panel
Show:
- current plan
- trial status
- trial start
- trial end
- exact time remaining
- active / expired label

PHASE 9 — ACTION SAFETY
==================================================

All destructive/sensitive actions must require confirmation modals.

Examples:
- delete user
- revoke premium
- revert to free
- revoke trial
- reset trial
- reset onboarding/premium flags

Modal requirements:
- show target email
- show action name clearly
- require explicit confirmation
- prevent accidental taps/clicks

PHASE 11 — APP / WEBSITE PLAN AWARENESS
==================================================

Both app and website must correctly understand current plan state.

Need:
- free users behave free
- active trial users behave like trial-enabled users
- premium users behave premium
- expired trials behave free
- downgraded premium users behave free immediately after sync

If any caches exist:
- ensure server truth overrides them
- especially for plan downgrade / expired trial / revoked access cases

If Replit needs to update:
- auth store
- premium grace store
- premium unlock logic
- premium tour logic
- settings/account fetch logic
to keep state consistent, do it.

==================================================
PHASE 13 — SECURITY HARDENING
==================================================

Harden the admin system and relevant account flows against:
- SQL injection
- privilege escalation
- ID tampering
- unsafe raw queries
- invalid plan transitions
- CSRF issues
- unauthorized access
- unvalidated input
- stale session issues

Requirements:
- parameterized ORM queries only
- Zod or equivalent request validation
- rate limiting on admin routes
- session validation required
- sanitize/scope outputs
- no raw SQL string concatenation
- no “frontend says user is admin so allow it” behavior

Also review for broader common vulnerabilities from basic to advanced in the touched areas.
