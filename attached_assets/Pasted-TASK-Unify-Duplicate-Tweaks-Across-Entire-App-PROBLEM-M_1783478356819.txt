TASK: Unify Duplicate Tweaks Across Entire App

PROBLEM

Many Windows tweaks exist in multiple sections of SwitchControl, including:

Tweaks

Network Tweaks

NIC Tuning

Extreme Labs

AI Advisor

Apply Recommended

Future optimization profiles


Currently these duplicate tweak cards maintain separate UI states even though they modify the exact same Windows setting.

Example:

User enables Disable Nagle's Algorithm in Network Tweaks.

Network Tweaks shows Applied.

Tweaks page still shows Default.

Extreme Labs may also still show Default.

Nagles algorithm 

Netowkr throttling index


These arr a few examples. 



This is incorrect and creates inconsistent behaviour across the application.


---

GOAL

Every Windows tweak must have a single shared state.

Regardless of where the tweak is applied, every duplicate instance across the application must immediately update.

The application should behave as though only one copy of the tweak exists.


---

IMPLEMENTATION

Create a global canonical tweak system.

Each tweak should have one shared identity.

Example:

displayId

canonicalId

tweakGroup

registry/service/NIC identifier

currentState

appliedSource


Example:

{
    displayId: "network-nagle-disable",
    canonicalId: "tcp-nagle-disable",
    tweakGroup: "network",
    registryKeys: [
        "TcpAckFrequency",
        "TCPNoDelay"
    ]
}

Every duplicate card must reference the same canonicalId.


---

SHARED STATE

Whenever one tweak changes state:

Update the central tweak store.

Notify every page displaying that canonical tweak.

Refresh every duplicate card instantly.

No restart required.


Examples:

Apply Disable Nagle's Algorithm

Immediately update:

Tweaks

Network Tweaks

Extreme Labs

AI Advisor

Apply Recommended

History

Dashboard summaries


Exactly the same applies when reverting.


---

DUPLICATE TWEAKS

Map duplicate tweaks together.

Examples:

Disable Nagle's Algorithm

Disable Nagle's Algorithm

TCP No Delay

TcpAckFrequency

TCPNoDelay


Canonical ID:

tcp-nagle-disable

Network Throttling

Network Throttling Index

MMCSS Network Throttling

Disable Network Throttling


Canonical ID:

network-throttling-index

RSS

RSS Receive Side Scaling

Enable RSS

Network RSS


Canonical ID:

rss-receive-side-scaling

Interrupt Moderation

Interrupt Moderation

Disable Interrupt Moderation

NIC Interrupt Moderation


Canonical ID:

interrupt-moderation

Repeat this process for every duplicated tweak inside SwitchControl.


---

STATE VERIFICATION

The UI must never trust its own toggle state.

Always verify against the real Windows configuration.

Sources include:

Registry

PowerShell

BCDEdit

NIC Advanced Properties

Services


The Windows configuration is the source of truth.


---

HISTORY

History should only record one canonical tweak action.

Example:

Applied Disable Nagle's Algorithm

Source:
Network Tweaks

Do not generate duplicate history entries for identical tweaks shown elsewhere.


---

TRIAL SUPPORT

Trial activation and expiration must operate using canonical IDs.

If a duplicated Premium tweak expires:

Revert Windows once.

Update every duplicate card.

Refresh every page.



---

SAVE SYSTEM

Profiles, backups and AI Advisor must save canonical IDs instead of page-specific IDs.

This prevents duplicated tweak states from appearing after restoring profiles.


---

CHECKLIST

Create canonical tweak IDs.

Remove independent duplicate states.

Build one global tweak state manager.

Sync every duplicate card instantly.

Verify against Windows before displaying state.

Update History.

Update AI Advisor.

Update Apply Recommended.

Update Dashboard.

Update Trial Manager.

Update Profile Import/Export.

Ensure restart persistence.



---

FINAL OUTPUT

SwitchControl should treat every Windows tweak as a single shared object.

If a tweak appears in multiple locations, every copy must always display the exact same state.

Applying or reverting a tweak anywhere in the application should immediately synchronize every duplicate instance automatically.
