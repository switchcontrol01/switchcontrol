TASK

Fix inconsistent dashboard scroll-reveal behavior.

On the dashboard, some cards/boxes animate in correctly with blur + fade + smooth motion when scrolling into view.

But other times those same boxes just pop in instantly with no proper reveal.

This inconsistency makes the page feel unfinished and cheap. The reveal system needs to behave consistently every time.

The goal is simple:
every dashboard section that is supposed to reveal on scroll must reveal the same way, reliably, with no random popping.

PROBLEM

Current issue:

Some dashboard cards are doing the intended reveal:
blur in
fade in
slight motion in
smooth premium entry

But sometimes other cards:
appear instantly
skip blur/fade
pop into place
feel inconsistent depending on scroll timing or render timing

That means the reveal system is not stable.

This is usually caused by one or more of these:

1. reveal observer triggering inconsistently
   some components are entering view before observer setup is ready
   some are already in viewport on mount and skip the intended animation path

2. mixed animation systems
   some cards use one reveal wrapper
   others use raw motion props
   others use no shared reveal logic
   result = inconsistent behavior

3. initial state not being applied reliably
   if a card renders visible before initial blur/opacity state is attached, it will pop instead of animate

4. mount timing / conditional rendering problems
   cards that mount after data loads may skip the same reveal flow as cards already mounted

5. AnimatePresence / layout / whileInView conflicts
   some elements may be using whileInView
   others manual observer logic
   others layout animations
   these can conflict and produce random popping

6. reduced motion or viewport once logic being applied unevenly
   some cards may be flagged as already revealed too early

GOAL

Make dashboard scroll reveal behavior fully consistent.

Every section that is intended to animate in should:
start hidden in the same proper initial state
reveal with the same smooth blur + fade + slight motion
trigger reliably when entering viewport
never randomly pop in without animation

The result should feel premium and deliberate across the whole dashboard.

IMPLEMENTATION

1. Audit the reveal system used on dashboard cards
   Find every dashboard section/card/container currently using reveal animation.

Check whether they all use the same shared reveal mechanism.

I want one consistent reveal path, not mixed logic.

If there are multiple patterns like:
manual motion initial/animate
whileInView
custom observer hook
PageHeader animated sections
raw framer motion blocks

standardize them.

2. Create or enforce one shared reveal wrapper
   Use one shared reveal component or hook for dashboard section entry.

That reveal system should handle:
initial hidden state
blur
opacity
slight y offset
in-view trigger
once behavior if intended
reliable mount behavior

Every dashboard card/section should go through this same system unless there is a very good reason not to.

3. Fix initial state application
   This is critical.

Make sure cards do not render visible first and then try to animate after.

They must start in the intended hidden state before reveal is triggered.

That means:
no flash of visible content before motion attaches
no server/client mismatch style issue
no mount-visible-then-animate bug

If needed, apply initial styles immediately through the wrapper before intersection observer confirms visibility.

4. Handle already-in-view elements properly
   Some cards may already be in viewport when the page loads or when layout shifts.

Those still need to animate correctly, not pop.

Make sure the reveal logic handles:
already visible on first render
fast scroll into view
layout changes after telemetry/data loads
window resize
container height changes

No card should skip reveal just because it was already near the viewport edge.

5. Remove conflicting animation patterns
   Check for components using:
   whileInView
   AnimatePresence
   layout
   manual animate state
   conditional render mount
   stagger parent variants

If these are fighting each other, simplify.

Prefer one clean reveal path:
hidden -> visible
with blur + fade + translate

Do not let nested motion conflicts cause random pops.

6. Check conditional sections and data-driven cards
   Some dashboard boxes may render after data arrives.
   Those are likely the ones popping.

For any section that depends on fetched or live data:
make sure it still enters through the same reveal wrapper
do not let loaded content bypass animation
preserve smooth entry even after async content becomes available
