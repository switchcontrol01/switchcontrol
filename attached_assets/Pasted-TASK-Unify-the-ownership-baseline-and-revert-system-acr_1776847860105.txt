TASK

Unify the ownership, baseline, and revert system across ALL premium-changing system actions:

1. Tweaks
2. Network Tweaks
3. Power Plans

This is release-critical.

GOAL

When a user starts a trial or premium session, then later loses premium or their trial expires:

- revert ONLY what SwitchControl itself applied
- NEVER revert settings the user already had before installing/downloading
- NEVER assume binary on/off if the real system value is multi-state
- restore exact original values, not guessed values

CURRENT PROBLEM

The current ownership logic is too weak if it stores only previousStatus like:
- "on"
- "off"

That is not enough for safe reverts.

Examples of why this breaks:
- NIC settings can be multi-state
- power plan can be a specific GUID, not just “high performance” or “balanced”
- registry tweaks may have exact DWORD/string values that are not simple enabled/disabled
- netsh states can differ by Windows version and wording

If we only store on/off, we can revert users to the wrong state and break machines that were already configured before they downloaded the app.

REQUIRED ARCHITECTURE

Build one shared ownership model for all premium-controlled system changes.

Each managed item must track:

- itemType: "tweak" | "network_tweak" | "power_plan"
- itemId
- appliedByApp: boolean
- baselineCaptured: boolean
- previousValue: exact raw value before SwitchControl changed it
- appliedValue: exact value SwitchControl set
- lastAppliedAt
- lastVerifiedAt
- verificationState: "verified" | "unverified" | "failed"

For power plans also store:
- previousPlanGuid
- appliedPlanGuid

For NIC/network settings also store adapter-specific scope where needed:
- adapterName
- registryKeyword if relevant

CRITICAL RULES

1. Capture baseline BEFORE applying
Do not let UI guess previous state.

Executor layer must:
- read current real value from system
- store it as previousValue
- then apply the requested change

Order must always be:
read baseline -> store baseline -> apply -> verify -> record ownership

2. Store exact real values, not on/off labels
Examples:
- registry DWORD exact value
- registry string exact value
- netsh parsed state exact normalized value
- NIC property registry value or exact readback value
- power plan exact active GUID

3. Only mark appliedByApp if execution actually succeeded
Do not record ownership from:
- UI intent
- optimistic toggle
- staged frontend state
- failed command

4. Revert by restoring exact previousValue
Do NOT revert by simply “disabling”
Do NOT revert by applying a generic default
Do NOT revert by assuming balanced/off/enabled

Restore the exact baseline value captured before the app changed it.

5. If no baseline exists, do NOT revert
Fail safe.
If baselineCaptured is false, leave the system alone and log why.

6. Multi-state values must be handled correctly
Examples:
- Flow Control
- RSS queue counts
- interrupt moderation values
- custom power plan GUIDs
- registry values that were custom before install

7. Trial expiry / premium downgrade must only revert app-owned changes
When premium ends:
- iterate app-owned premium-controlled items only
- restore exact baseline
- mark reverted only after verification or safe readback confirmation

8. Never overwrite a user’s original config snapshot after the first app-owned apply
If baseline already exists for that item and scope, keep it.
Do not keep replacing baseline with newer values after repeated toggles.
The baseline must represent the user’s state before SwitchControl first changed it.

IMPLEMENTATION

A. Shared ownership store / schema
Create or upgrade one shared persistence model for:
- tweaks
- network tweaks
- power plans

Suggested structure:

{
  itemType,
  itemId,
  scopeKey,
  appliedByApp,
  baselineCaptured,
  previousValue,
  appliedValue,
  previousPlanGuid,
  appliedPlanGuid,
  adapterName,
  registryKeyword,
  verificationState,
  lastAppliedAt,
  lastVerifiedAt
}
