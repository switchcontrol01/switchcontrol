ASK
Disable DevTools everywhere in the packaged Electron app, while keeping them available only in development.

PROBLEM
Right now DevTools can still be opened or inspected in production. I need production builds hardened so users cannot open DevTools with keyboard shortcuts, right click, or programmatic calls.

GOAL
Make DevTools work only in dev mode.
In packaged production builds:
- no DevTools
- no F12
- no Ctrl+Shift+I
- no Ctrl+Shift+J
- no Ctrl+U
- no right click inspect
- no programmatic openDevTools path left active

FILES TO CHECK
- electron/main.js
- electron/preload.js
- app/window creation file if different from main.js
- any renderer root file that adds keyboard listeners
- any helper/debug utilities that open DevTools

IMPLEMENTATION

1. Detect dev mode properly
Use a single source of truth like:
- app.isPackaged
- NODE_ENV
- existing isDev helper if already present

Production must mean:
- packaged build
- DevTools disabled

2. Lock BrowserWindow DevTools at creation
For every BrowserWindow:
- set `webPreferences.devTools = isDev`
- confirm no other window uses `devTools: true` in production
- check main window
- check child windows
- check auth/login popup windows
- check updater/premium/payment windows
- check any hidden/background windows

3. Add a hard production lock helper in main process
Create a reusable helper like `lockDevTools(win)` and apply it to every BrowserWindow in production.

That helper must:
- immediately close DevTools if they open
- block keyboard shortcuts:
  - F12
  - Ctrl+Shift+I
  - Ctrl+Shift+J
  - Ctrl+U
- block right click context menu inspect path
- prevent any programmatic open path from succeeding in production

Expected pattern:
- `webContents.on('devtools-opened', ...) => closeDevTools()`
- `webContents.on('before-input-event', ...) => preventDefault()`
- `webContents.on('context-menu', ...) => preventDefault()`

4. Search entire project for DevTools openings
Search for:
- openDevTools
- toggleDevTools
- inspectElement
- devTools: true
- context-menu
- before-input-event
- setWindowOpenHandler

Remove or guard every debug path so it only runs in dev.

5. Add preload safety layer
In preload.js add a production-only keyboard blocker for:
- F12
- Ctrl+Shift+I
- Ctrl+Shift+J
- Ctrl+U

This is secondary protection, not the only protection.

6. Do not break development
Dev mode must still allow DevTools normally.

CHECKLIST
- production BrowserWindow has devTools disabled
- all windows use the same hardening
- no remaining openDevTools path in production
- right click inspect blocked in production
- keyboard shortcuts blocked in production
- dev mode still works normally
- packaged production build tested

FINAL OUTPUT
Return:
- exact files changed
- exact windows hardened
- exact debug paths removed or guarded
- confirmation that dev mode still allows DevTools
- confirmation that packaged production blocks all DevTools entry points
