What Replit just admitted is critical:
Auth provider = custom OAuth via website backend using session cookies
That explains almost every bug you’re seeing. This is not cosmetic. This is architectural.
Below is the truth, then exactly what must be done, then the message you send to Replit.
What is ACTUALLY broken (root causes)
1. Logout bug (auto-logs back in)
This is 100% expected with cookie-based auth if not explicitly cleared.
What’s happening:
You “log out” in the app UI
BUT the HTTP-only session cookie from switchcontrol.org is still valid
On next app boot, the backend sees the cookie and re-authenticates silently
This is not a UI bug. This is backend + Electron cookie handling.
2. Premium resets to free next day
Also explained by cookie auth.
Likely causes:
Premium is tied to a web session, not a persisted user entitlement
When cookie expires or refreshes, entitlement lookup fails
Or Stripe test mode customer ID ≠ authenticated user ID
Or entitlement API is cached per session instead of per user
If premium were stored server-side correctly, this could not happen.
3. “Go to app” does nothing
This means the website has no way to reliably open the Electron app AND confirm identity.
Right now:
Website thinks “premium unlocked”
Electron app has no confirmed entitlement refresh
No IPC confirmation
No deep-link → entitlement handshake
So nothing triggers.
4. Replit’s task list is weak
Look at it:
“Organize settings change logic better”
“Make screen transition smooth”
These are secondary issues. They are polishing a broken engine.
The NON-NEGOTIABLE fixes (architecture level)
A. Logout must invalidate the session cookie
You must implement this:
Backend endpoint:
Copy code

POST /auth/logout
That endpoint must:
Invalidate the session server-side
Expire the cookie
Return success
Electron app must:
Call /auth/logout
Clear local state
Clear Electron cookies for the domain
If you do not do this, logout will NEVER be correct.
B. Premium must be server-authoritative
Premium cannot be:
Stored in localStorage
Stored in memory only
Derived from “last known state”
It MUST be:
Stored in DB tied to user ID
Returned by /me or /entitlements
Checked on:
app boot
focus regain
deep-link return
login
If premium flips to free, the server is returning free. Period.
C. “Go to app” must perform a handshake
Correct flow:
User pays
Backend marks user premium
Website shows “Go to app”
Clicking it:
opens switchcontrol://premium
OR sends a signed token
Electron receives deep link
Electron calls /me
Backend confirms premium
App updates state
Animation plays ONCE
Anything else is unreliable.
D. Cookie auth + Electron requires explicit cookie handling
Electron does NOT behave like Chrome.
You must:
Explicitly allow cookies for the backend domain
Clear them on logout
Log cookie presence on boot
Otherwise you get “ghost logins”.
