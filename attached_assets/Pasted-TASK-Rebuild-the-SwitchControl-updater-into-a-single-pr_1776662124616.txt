TASK

Rebuild the SwitchControl updater into a single-provider, R2 generic-provider-only update pipeline.

The updater must become:

production-safe

structurally clean

easy to debug

impossible to confuse with GitHub Releases

consistent across frontend, Electron main, preload IPC, build, packaging, and release pipeline


We are not doing GitHub Releases as the update backend anymore.

We are doing:

R2 generic provider only

one release host

one metadata source

one installer source

one stable channel model

optional beta support only if implemented cleanly


The final system must be strong enough for real public release, not just "kind of works".


---

PROBLEM

The current updater is close, but not fully hardened.

Current risks / flaws

1. Provider confusion

comments say generic provider / R2

GitHub workflow uploads release assets to GitHub Releases

this creates split-brain release behavior



2. No single source of truth

metadata may exist in one place

installer may exist in another

runtime may be checking a third assumption



3. Channel naming is messy

channel: 'latest' is not a clean channel design

stable and beta need explicit behavior



4. IPC surface is under-hardened

renderer can trigger updater actions

no strict validation or capability boundary is visible



5. No explicit runtime verification of the update feed origin

updater should log and validate exactly which provider and URL it trusts



6. Version management is split

root package and electron package can drift

this causes confusion and future mistakes



7. Release workflow is still GitHub-oriented

that is wrong for an R2-only updater

release automation should build artifacts and upload only to R2



8. Windows-only updater flow still references extra metadata that may not belong

remove dead or unrelated release artifacts



9. Recovery and failure handling need tightening

repeated failure states should be clear

stale state must not linger



10. Because the app runs elevated, update flow must be stricter than average



no sloppy boundaries

no mixed release sources

no ambiguous config



---

GOAL

After this refactor:

SwitchControl uses R2 generic provider only

packaged app checks one exact release host

update metadata and installer always live together

stable updates are deterministic

beta is supported only if implemented cleanly

all version numbers are synced from one source

no GitHub Release dependency remains in the updater flow

preload and renderer only expose the minimum safe update actions

updater logs exactly what source it is using

failed update states are clean and recoverable

release pipeline is simple and production-grade


The updater should feel like infrastructure, not guesswork.


---

ARCHITECTURE DECISION

Use this as the final architecture

Update backend

Cloudflare R2 bucket

exposed through custom domain:

https://releases.switchcontrol.org



Stable metadata

https://releases.switchcontrol.org/latest.yml


Stable installer

https://releases.switchcontrol.org/SwitchControl Setup <version>.exe

or whatever exact filename electron-builder outputs

keep naming deterministic
