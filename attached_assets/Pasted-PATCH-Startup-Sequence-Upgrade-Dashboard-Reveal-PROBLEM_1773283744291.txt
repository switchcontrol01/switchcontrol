PATCH: Startup Sequence Upgrade + Dashboard Reveal

PROBLEM

The startup experience currently has a few issues even though the base animation is good.

1. The startup screen finishes and then the screen goes blank for a moment.


2. During this blank state, the dashboard later fades in with no real transition.


3. System metrics initially show Unavailable and only appear a few seconds later.


4. The startup scene could feel more premium with more shine, glow, particles, and motion.


5. The rotating startup text system works well but does not have enough variation.



Right now the experience feels like:

startup → blank screen → dashboard appears → metrics load later.

That sequence breaks immersion and makes the app feel unfinished.


---

AIM

Keep the exact startup structure and animation that already exists.

Do not redesign it.

Do not remove the existing startup animation.

Do not remove the existing rotating text system.

We are only improving it so the transition and loading feel premium and intentional.


---

WHAT WE ARE ACHIEVING

When the app launches:

1. Startup animation plays as it currently does.


2. Rotating startup messages continue to change each launch.


3. System metrics begin loading during the startup animation.


4. When startup finishes, the screen should not go blank.


5. Instead, a camera glow transition happens.


6. A bright glare/light sweep appears like sunlight passing across the screen.


7. During this glare moment the dashboard zooms out and reveals itself.


8. The dashboard sweeps in slightly from the top left diagonal.


9. Metrics are already loaded and visible immediately.



The result should feel like:

startup → glow flash → dashboard reveal → everything ready.

No blank screen.

No metrics delay.

No hard cut.

TASK 3 — Preload system metrics during startup

Right now metrics load after the dashboard appears.

That causes the Unavailable → data appears problem.

Instead:

System telemetry should begin loading while the startup screen is visible.

During startup animation:

• start CPU data collection
• start RAM stats
• start GPU data
• start disk usage
• start system specs

Store the values in the same shared state used by the dashboard.

Then when the dashboard appears, it already has data.

Dashboard should immediately show:

CPU
RAM
GPU
Disk

without any loading delay.

TASK 4 — Remove the blank screen

Right now the sequence is:

startup fades → blank screen → dashboard appears.

This blank moment must be removed.

Instead:

startup should transition directly into dashboard reveal.

Startup disappears while dashboard appears.

There should never be a moment where the screen is empty.

TASK 5 — Add Camera Glow transition

Use a transition similar to the CapCut Camera Glow effect.

The idea:

1. A soft light glare sweeps across the screen.


2. Bright center glow appears briefly.


3. The dashboard becomes visible during that glow.


4. The camera slightly zooms out as the glow fades.



This makes the dashboard reveal feel cinematic.

Implementation concept:

• bright radial glow center
• horizontal light streak
• short bloom burst
• slight camera zoom-out
• quick fade of the glow

The glow should last about 400ms to 700ms.

It should feel smooth, not dramatic.


---

TASK 6 — Dashboard diagonal sweep entrance

Instead of fading in, the dashboard should:

• appear slightly offset toward top-left • move slightly down-right • scale from about 0.98 → 1 • opacity from 0 → 1

Movement must be subtle.

The motion should feel like the dashboard is sliding softly into place.

Duration target:

600ms to 900ms.

Easing:

smooth easing, not bounce.
