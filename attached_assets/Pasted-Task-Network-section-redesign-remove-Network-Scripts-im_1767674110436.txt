Task: Network section redesign (remove Network Scripts, improve Network Tweaks UI, add per-tweak info panel)

High level goals:
- Remove “Network Scripts” from the sidebar/nav and any routes.
- Keep ONLY “Network Tweaks” for the Network area.
- Upgrade Network Tweaks UI to a modern card-based layout with categories (SMB, TCP/IP, UDP, Security, DNS).
- Each tweak must have:
  - toggle
  - tags (Recommended / Advanced / Experimental, Safety)
  - info button that opens a right-side panel (or modal) showing:
    - Description (unique)
    - Impact (unique, not generic)
    - Expected change (pills: Latency/Network/Stability risk)
    - Notes / warnings (optional)
- The info panel must close reliably with X and return to the list.

Implementation steps:
1) Remove Network Scripts from navigation
- Find the sidebar/nav config and remove the “Network Scripts” entry.
- Remove any routes/pages/components for Network Scripts.
- Remove any links/buttons that reference it.
- Ensure the app still builds with no dead imports.

2) Network Tweaks UI layout
- Create a dedicated page layout for Network Tweaks:
  Header: “Network Tweaks”
  Subheader: “Optimize latency, throughput, and stability. Apply carefully.”
- Add a search bar: “Search network tweaks…”
- Add filter chips: All, SMB, TCP/IP, UDP, Security, DNS
- Render category sections with collapsible headers (default expanded):
  - SMB
  - TCP/IP
  - UDP
  - Security
  - DNS
- Inside each category, render a responsive 2-column grid on desktop, 1-column on small screens.
- Each tweak card:
  Left: name + short one-liner
  Right: toggle + info icon/button
  Under name: tags (Recommended/Advanced/Experimental + Safety)
  Optional warning line if needed (red text) e.g. WireGuard warning.

3) Data model (shared/schema)
For each network tweak define:
- id (string)
- name (string)
- category ("SMB" | "TCP/IP" | "UDP" | "Security" | "DNS")
- summary (short one-liner)
- description (longer)
- impact (bullet list, unique)
- safety: "Safe" | "Moderate" | "Risky"
- level: "Recommended" | "Advanced" | "Experimental"
- expected: { network?: "None|Low|Medium|High", latency?: "None|Low|Medium|High", stabilityRisk?: "None|Low|Medium|High" }
- warning?: string (optional)
- apply(): client calls server route that runs the command/registry (can be stubbed if not implemented yet)
- revert(): optional (stub ok)

4) Info panel behavior
- Clicking info opens the panel with that tweak’s data.
- X closes it and restores scrolling and interactions.
- Clicking outside closes it too (optional).
- Pressing Escape closes it (optional).
