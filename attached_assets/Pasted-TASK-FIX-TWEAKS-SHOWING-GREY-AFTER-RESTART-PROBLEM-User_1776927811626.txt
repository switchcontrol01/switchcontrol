TASK — FIX TWEAKS SHOWING GREY AFTER RESTART

PROBLEM

Users report:
- tweaks applied and shown green
- restart PC or reopen app
- tweaks show greyed out
- but they should still still be active on the real system

This means the UI state is becoming false or stale after relaunch.
The system state and the app state are diverging.
That destroys trust immediately.

GOAL

Make tweak state fully durable and truthful across:
- app close and reopen
- tab switching
- route changes
- restart
- relaunch after reboot

On app launch:
- detect actual real system state for ALL tweak types
- hydrate UI from real verification, not default false values
- never flash incorrect grey states before verification finishes
- prevent stale async responses from overwriting fresh state
- make every section behave the same way

SECTIONS IN SCOPE

Apply this to all of these:
- normal tweaks
- network tweaks
- NIC tuning / NIC properties
- power plans
- startup / app booster state if it uses the same pattern
- any premium revert summary state that depends on real applied values

FILES TO AUDIT

Frontend:
- client/src/components/tweaks/TweaksList.tsx
- client/src/hooks/use-tweak-executor.ts
- client/src/pages/NetworkTweaks.tsx
- client/src/pages/NicTuning.tsx
- client/src/pages/PowerPlans.tsx
- any shared store/hooks used for applied state
- any route-level useEffect that initializes tweak cards

Backend / Electron:
- electron/main.js
- electron/tweak-executor.js
- electron/network-tweak-executor.js
- electron/nic-executor.js
- electron/power-plan-manager.js
- any IPC handlers for:
  - tweak:checkStatus

  - nic:getState / nic:checkStatus
  - powerPlans:getState

ROOT ISSUE TO SOLVE

The app must stop treating "not yet checked" as "false".

Right now the likely bad flow is:
- page mounts
- tweak cards initialize as off / grey
- verification runs later or is skipped
- older async responses overwrite newer state
- route remounts reset local state again
- closing and reopening restores UI defaults instead of real verified state

That architecture is wrong.

REQUIRED FIXES

1. ADD REAL LAUNCH VERIFICATION

On app startup and page entry:
- run a real checkStatus / syncAll for every tweak family
- do not trust persisted UI state alone
- persisted state can be used only as cache or hint, never source of truth

2. REMOVE DEFAULT FALSE INIT

Do NOT initialize any tweak state like:
- applied: false
- enabled: false
- active: false

Use a tri-state model instead:
- unknown
- applied
- not_applied

Example:
status: 'unknown' | 'applied' | 'not_applied'

While status is unknown:
- show shimmer / loading / neutral state
- do not show grey off state yet

3. SAFE HYDRATION ORDER

Correct order must be:

- create empty store with unknown states
- optionally load cached snapshot
- immediately request real verification from Electron/backend
- when verified results return, replace state with verified truth
- persist verified truth only after real verification completes

4. BLOCK STALE ASYNC OVERWRITES

Every verification wave must carry a request generation ID.

Pattern:
- increment requestVersion before starting sync
- when response returns, ignore it unless it matches latest requestVersion

This is mandatory.
If user switches tabs or page remounts, older responses must not overwrite newer state.

5. CENTRALIZE STATE, DO NOT LET PAGES OWN TRUTH

Do not keep authoritative applied state inside local component state in each page.

Create one shared authoritative store for:
- tweaks
- network tweaks
- NIC tuning
- power plans

Pages should render from the shared store only.
Pages may trigger refresh, but they must not own separate truth copies.

6. DO NOT RESET STATE ON TAB SWITCH

Route changes, accordion open/close, card expansion, modal open/close, and page remounts must not reset applied state back to false or empty.

If local component state currently rebuilds cards from defaults on every mount, remove that.
Use the store.

7. POWER PLAN MUST VERIFY REAL ACTIVE PLAN

For power plans:
- on launch, read the actual active Windows power scheme GUID
- map it to UI state
- if SwitchControl premium plan is active, show that
- if Balanced is active, show Balanced
- never default to off / neutral without verification

8. NIC TUNING MUST VERIFY PER PROPERTY

For NIC tuning:
- on launch, read current adapter property values from the system
- map each property card to verified state
- unsupported properties must be marked unsupported
- unknown must stay loading until checked
- do not mark unsupported as off

9. NETWORK TWEAKS MUST VERIFY REAL SYSTEM VALUES

For network tweaks:
- recheck actual registry / netsh / adapter value on launch
- do not use prior toggle memory alone
- cards must reflect the real machine state

10. NORMAL TWEAKS MUST VERIFY AGAIN AFTER EXECUTE

After user applies or reverts a tweak:
- do not just optimistically set green/grey forever
- immediately run a verify step
- update UI only from verified result
- persist only verified result

11. EXPLICIT RESULT OBJECTS ONLY

Every sync/check handler must return structured result objects.
Never return null for meaningful state.

Bad:
- return null

Good:
{
  ok: true,
  family: 'tweaks',
  statuses: {
    'mmcss-gaming': { status: 'applied', verified: true },
    'telemetry': { status: 'not_applied', verified: true }
  },
  checkedAt: ...
}

For skipped or already-running states:
{
  ok: false,
  skipped: true,
  reason: 'already_running'
}
