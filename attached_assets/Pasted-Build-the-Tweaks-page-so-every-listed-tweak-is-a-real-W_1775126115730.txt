Build the Tweaks page so every listed tweak is a real Windows action, not simulated UI state.

Non-negotiable rules:

1. Every tweak must support:

- apply
- verify
- revert
- requiresAdmin
- requiresRestart
- risk
- execution log
- user-facing success/failure reason

2. Do not mark a tweak as active unless verify() confirms the system state actually changed.

3. Do not fake anything in local state only.

4. Preserve current UI, categories, and visual design, but replace simulated behavior with real execution.

5. Add a shared tweak engine used by all tweak cards and by Apply Safe / Reset actions.

6. Every tweak must write a structured result log:

- tweak id
- action
- timestamp
- command(s) run
- verification result
- reboot required
- failure reason

7. If a tweak is unsafe, outdated, or not reliably implementable on modern Windows, do not silently fake it. Instead:

- keep it visible
- mark it unsupported or experimental
- explain why
- disable Apply if needed

Architecture to build:

Create a real tweak registry like this:

type TweakDefinition = {
id: string;
title: string;
description: string;
category: string;
risk: "safe" | "moderate" | "advanced" | "experimental";
requiresAdmin: boolean;
requiresRestart?: boolean;
unsupportedReason?: string;
apply: () => Promise<TweakExecutionResult>;
revert: () => Promise<TweakExecutionResult>;
verify: () => Promise<TweakVerifyResult>;
};

type TweakExecutionResult = {
ok: boolean;
rebootRequired?: boolean;
commandsRun: string[];
message: string;
};

type TweakVerifyResult = {
isApplied: boolean;
message?: string;
};

Execution layer requirements:

Implement shared helpers for:

- registry read/write/delete
- service start type change
- scheduled task enable/disable
- PowerShell command execution
- powercfg execution
- bcdedit execution
- process kill
- Appx package removal or disable where appropriate
- feature detection
- admin check
- reboot-needed aggregation

Use the existing Electron main process as the only place where privileged commands execute. The renderer must never directly run shell commands.

Required tweaks to implement as real, with apply + verify + revert:

SAFE / FIRST WAVE:

- Disable Hibernation
  apply: powercfg /hibernate off
  verify: hiberfil.sys disabled or hibernate off reflected
  revert: powercfg /hibernate on

- Disable Maintenance
  disable scheduled maintenance tasks that are safe to disable
  verify task state
  revert re-enable

- Disable Background Apps
  use current Windows-supported privacy/background policy and verify
  revert to default

- Disable Notifications
  use registry/policy path for toast notifications
  verify actual notification setting
  revert

- Disable Storage Sense
  disable Storage Sense policy/setting
  verify
  revert

- Disable Search Highlights
  disable Windows Search Highlights via supported registry/policy
  verify
  revert

- Enable Gaming Mode
  enable Windows Game Mode
  verify registry value
  revert

- Remove Xbox Game Bar
  disable Game Bar and capture hooks
  verify all related GameDVR/GameBar values
  revert

- Disable Telemetry
  implement only the Windows telemetry/privacy values that are valid and reversible
  do not overclaim
  verify exact values changed
  revert

- Disable Copilot
  disable Windows Copilot entry points where supported on current Windows
  if unsupported on this build, mark unsupported instead of faking
  verify
  revert

- Disable NVIDIA Telemetry
  detect NVIDIA first
  disable NVIDIA telemetry scheduled tasks/services only if present
  verify task/service state
  revert

- Disable Print Spooler / Fax & Printer related services
  implement only if services exist
  verify start mode and running state
  revert

- Hide Recent Files
  disable recent items / Quick Access recent files history
  verify
  revert

- Enable Compact Explorer
  set compact mode in File Explorer if supported
  verify
  revert

MODERATE / SECOND WAVE:

- Disable Hyper-V
  use bcdedit + optional feature disable only if present
  warn that this can affect WSL2, Android emulators, Docker, VBS, Memory Integrity
  requires restart
  verify feature state and hypervisor launch type
  revert cleanly

- Disable Large System Cache
  set LargeSystemCache value
  verify
  revert

- Disable SysMain / Superfetch
  disable SysMain service
  verify service start type and state
  revert

- Disable Prefetch
  set EnablePrefetcher and related values carefully
  verify
  revert

- Tune Priority
  implement Win32PrioritySeparation only if using sane documented values
  verify
  revert

- Disable Bluetooth
  only disable Bluetooth services/adapters if present
  verify actual adapter/service state
  revert

- Disable Wi-Fi
  only disable WLAN service or adapters if present
  verify actual adapter/service state
  revert

- Disable Xbox Services
  disable Xbox related services/tasks if present
  verify
  revert

ADVANCED / GUARDRAILED:

- Optimize Memory Settings
  implement only documented, reversible memory-manager tweaks that are actually intended by Windows
  verify each registry value
  revert

- Disable Page Combining
  implement only if supported on this Windows build
  verify with PowerShell or registry-backed detection
  revert

- Disable Energy Logging
  disable related diagnostics/event tracing only if path exists
  verify
  revert

- Timer Resolution
  do not fake with registry
  only wire this if there is an actual helper/agent process capable of requesting timer resolution at runtime
  if not present, mark unsupported or “requires agent”
  do not pretend it is persistent

- Enable Preemption
  do not ship placebo
  implement only if you can point to the exact GPU scheduling/preemption control you are modifying and verify it
  otherwise mark unsupported

DO NOT SHIP AS REAL UNLESS PROPERLY JUSTIFIED:

- Disable Desktop Composition
  on modern Windows this is legacy/outdated and likely not a valid tweak
  mark experimental or unsupported unless there is a real, verified modern equivalent
  do not fake it

UI behavior requirements:

- Each toggle reflects verify() result on page load
- Toggle click runs apply or revert then immediately re-verifies
- Show pending spinner while executing
- Show failed state with exact plain-English reason
- Show “restart required” badge when relevant
- Apply Safe should only apply tweaks explicitly tagged safe and supported
- Reset should revert only tweaks currently verified as applied by SwitchControl
- Add “unsupported” badge where needed instead of fake toggle success

Important product honesty requirements:

- Reclassify any tweak whose current “recommended” tag is misleading
- Do not tag Disable Wi-Fi or Disable Bluetooth as recommended for general users
- Hyper-V must show a strong warning about WSL2, Docker, emulators, virtualization, and security features
- Timer Resolution must not be marked real unless an actual runtime helper exists
- Desktop Composition must not be advertised as a modern real optimization unless verified

Implementation requirement:

Work directly in the existing tweak execution framework and convert the current tweak cards one by one to real behavior. Keep the design, but replace simulated logic with production-grade execution and verification.

Deliverables:

1. Updated tweak engine
2. Real implementations for all supported tweaks listed above
3. Unsupported handling for unsafe or non-implementable tweaks
4. Logs/history integration
5. Verification on app load
6. Bulk Apply Safe and Reset wired to the real engine

Before finalizing, provide a matrix listing for every tweak:

- implemented
- unsupported

- exact apply method
- exact verify method
- exact revert method
