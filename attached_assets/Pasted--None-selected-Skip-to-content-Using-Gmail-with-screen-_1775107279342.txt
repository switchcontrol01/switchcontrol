TASK

Fix the desktop telemetry pipeline and renderer so the Live System Monitor stops showing only CPU and correctly renders multiple telemetry lines for RAM, disk, GPU, and network when data exists.

PROBLEM

The current desktop app only reliably shows the CPU line. This is not just a chart styling issue. There are multiple root causes in the telemetry contract and frontend assumptions.

ROOT CAUSES FOUND

1. GPU telemetry shape mismatch

In electron/main.js, telemetry:getGpu returns an ARRAY of GPU controllers:

return controllers;

But the frontend treats the result like a single object in multiple places.

Examples:

- client/src/components/dashboard/GpuModal.tsx
- client/src/pages/Home.tsx

Both assume:

- res.load
- res.temperature
- res.powerDraw
- etc

Those properties do not exist on the array itself, so GPU detail detection and GPU modal logic break.

2. RAM shape mismatch

In electron/main.js, system:getRamUsage returns:

- total
- used
- free
- usagePercent

But parts of the frontend expect:

- totalGB
- usedGB

This causes RAM fallback logic to be inconsistent and can prevent the graph or stats from behaving correctly.

3. LiveGraph visibility logic is wrong

client/src/components/dashboard/LiveGraph.tsx decides whether to render lines using history-based checks like:

const hasRamData = data.some(d => d.ram !== null);

That is fragile because:

- the array starts empty
- some values start null
- idle network gets forced to null
- GPU is already broken due to the array/object mismatch

CPU survives because it is always present.

4. Network telemetry is incorrectly nulled when idle

In electron/main.js inside telemetry:getLive:

netRxSec: netRxKBs > 0 ? netRxKBs : null,
netTxSec: netTxKBs > 0 ? netTxKBs : null,

Idle traffic should be 0, not null. Null makes the graph think the metric does not exist.

5. Memory cleaner has a crash bug

In client/src/components/dashboard/MemoryCleanerModal.tsx, RotateCcw is used but not imported from lucide-react.

That can crash the result view after a clean completes.

GOAL

Make the telemetry contract consistent and make the graph render all available metrics, not just CPU.

FILES TO FIX

1. client/src/components/dashboard/LiveGraph.tsx
2. client/src/components/dashboard/GpuModal.tsx
3. client/src/pages/Home.tsx
4. client/src/components/dashboard/MemoryCleanerModal.tsx
5. electron/main.js

IMPLEMENTATION

1. Fix GPU array handling in GpuModal.tsx

Current code assumes api.telemetry.getGpu() returns a single object.

Update it so it safely handles the backend array:

const res = await api.telemetry.getGpu();
const gpu = Array.isArray(res) ? res[0] : res;
if (!gpu) return;
setData(gpu);

Then replace all later references from res.something to gpu.something.

2. Fix GPU detail detection in Home.tsx

Where the code currently checks:

if (gpuData.load !== undefined || gpuData.temperature !== undefined || ...)

change it to:

const gpu = Array.isArray(gpuData) ? gpuData[0] : gpuData;
if (gpu) {
  const hasDetail =
    gpu.load !== undefined ||
    gpu.temperature !== undefined ||
    gpu.powerDraw !== undefined ||
    gpu.clockCore !== undefined ||
    (gpu.memoryUsed !== undefined && gpu.vram !== undefined);
  setGpuDetailAvailable(hasDetail);
} else {
  setGpuDetailAvailable(false);
}

Do not treat the GPU payload as an object if the IPC returns an array.

3. Fix LiveGraph visibility logic

In client/src/components/dashboard/LiveGraph.tsx, stop deciding line visibility by scanning historical data with data.some(...).

Use latest telemetry state instead.

Replace this pattern:

const hasRamData = data.some(d => d.ram !== null);
const hasDiskData = data.some(d => d.disk !== null);
const hasNetRx = data.some(d => d.netRx !== null);
const hasNetTx = data.some(d => d.netTx !== null);

with logic based on the latest point or latest state, for example:

const latestPoint = data[data.length - 1];

const hasCpuTemp = latestPoint?.cpuTemp != null;
const hasGpuLoad = latestPoint?.gpuLoad != null;
const hasGpuTemp = latestPoint?.gpuTemp != null;
const hasGpuMem = latestPoint?.gpuMemPct != null;
const hasRamData = latestPoint?.ram != null;
const hasDiskData = latestPoint?.disk != null;
const hasNetRx = latestPoint?.netRx != null;
const hasNetTx = latestPoint?.netTx != null;

The line should render if the current telemetry says the metric exists, not only if prior history happened to contain a non-null sample.

4. Fix RAM data point assignment in LiveGraph.tsx

Current code:

ram: ramPercent > 0 ? ramPercent : null,

Change to something based on actual RAM availability:

ram: hasRam ? ramPercent : null,

where hasRam is derived from whether total RAM and used RAM are valid, not whether percent is greater than zero.

5. Fix network values in electron/main.js

Inside telemetry:getLive, change:

netRxSec: netRxKBs > 0 ? netRxKBs : null,
netTxSec: netTxKBs > 0 ? netTxKBs : null,

to:

netRxSec: netRxKBs,
netTxSec: netTxKBs,

Idle traffic must be 0, not null.

6. Fix RAM contract mismatch

Pick one consistent contract and use it everywhere.

Preferred fix:
keep IPC returning both raw bytes and friendly GB values so frontend stays simple.

Update system:getRamUsage in electron/main.js to return:

return {
  total: mem.total,
  used: mem.total - mem.available,
  free: mem.available,
  usagePercent: Math.round(((mem.total - mem.available) / mem.total) * 100),
  totalGB: Math.round(mem.total / 1024 / 1024 / 1024),
  usedGB: Number(((mem.total - mem.available) / 1024 / 1024 / 1024).toFixed(1)),
  freeGB: Number((mem.available / 1024 / 1024 / 1024).toFixed(1)),
};

Then update any frontend RAM fallback code to use these fields consistently.

7. Fix MemoryCleanerModal crash

In client/src/components/dashboard/MemoryCleanerModal.tsx add the missing icon import:

RotateCcw

from lucide-react.

Also validate the native response before calling setResult(res). If the response is missing required fields, show a toast instead of rendering broken data.
