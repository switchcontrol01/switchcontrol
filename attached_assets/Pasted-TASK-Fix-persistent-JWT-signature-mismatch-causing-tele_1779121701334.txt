TASK:
Fix persistent JWT signature mismatch causing telemetry WebSocket rejection spam in packaged Electron builds.

PROBLEM:
The packaged app backend is repeatedly rejecting telemetry WebSocket clients with:

[AUTH] JWT verification failed: invalid signature
[WS] Rejected telemetry client (invalid or expired token)

Renderer reconnects endlessly and logs:
[Telemetry] WebSocket connected

Premium entitlement state is valid, so this is NOT a premium verification issue.

Observed behavior strongly indicates stale JWT tokens or mismatched JWT_SECRET values between:

- renderer auth state
- Electron backend child process
- persisted desktop secrets
- packaged app sessions after reinstall/update

ROOT CAUSE HYPOTHESIS:
The backend is verifying tokens using a different JWT_SECRET than the one originally used to sign them.

Likely causes:

- JWT secret regeneration
- desktop-secrets.json replacement
- stale persisted JWT after update/reinstall
- backend startup race condition
- token issued before secret bootstrap completed

GOAL:
Create a stable, permanent JWT auth system for Electron packaged builds.

REQUIRED IMPLEMENTATION:

1. JWT SECRET STABILITY

- NEVER regenerate JWT_SECRET if desktop-secrets.json already exists.
- Only create secrets once on first install.
- Persist permanently across launches and updates.

2. ADD JWT FINGERPRINT LOGGING
   Add fingerprint logging everywhere JWTs are issued and verified.

Example:
const crypto = require("crypto");

function jwtFingerprint(secret) {
return crypto
.createHash("sha256")
.update(secret)
.digest("hex")
.slice(0, 8);
}

Log:
[AUTH] JWT secret fingerprint(issue)=xxxxxxxx
[AUTH] JWT secret fingerprint(verify)=xxxxxxxx

Also log:

- token issuer source
- Electron process type
- auth bootstrap timing

3. FORCE AUTH RESET ON INVALID SIGNATURE
   If jwt.verify fails with invalid signature:

- clear stored auth
- clear websocket auth state
- clear persisted JWT
- require silent re-auth or login refresh
- STOP websocket reconnect spam

Current behavior loops infinitely:
WebSocket connected
JWT invalid
Rejected telemetry client
Reconnect
Repeat forever

That must be prevented.

4. WEBSOCKET AUTH HARDENING
   Do NOT allow telemetry reconnect attempts when:

- JWT is invalid
- JWT expired
- JWT missing

Add reconnect suppression with cooldown.

5. RENDERER AUTH RECOVERY
   When backend returns:
   TOKEN_INVALID_RELOGIN_REQUIRED

Renderer must:

- clear Zustand auth state
- clear localStorage auth
- clear persisted JWT
- refresh auth session properly
- request fresh token
- reconnect telemetry only after success

6. ADD CRASH/BOOT DIAGNOSTICS
   Create a dedicated diagnostics section at startup:

[AUTH-DIAGNOSTICS]
JWT_SECRET source
JWT fingerprint
desktop-secrets path
token exists
token issued timestamp
token exp timestamp
renderer auth state
backend auth state
ws auth state

7. PREVENT SECRET DRIFT
   Verify:

- Electron main process
- backend child process
- renderer auth layer

ALL use identical JWT_SECRET.

Add assertion:
if (mainFingerprint !== backendFingerprint) {
console.error("[FATAL AUTH] JWT secret mismatch detected");
}

8. TELEMETRY WS FIX
   Current log:
   [Telemetry] WebSocket connected

is misleading because transport connects before auth rejection.

Fix logging so:

- "connected" only prints AFTER auth success
- rejected auth prints once
- reconnect attempts are rate-limited
