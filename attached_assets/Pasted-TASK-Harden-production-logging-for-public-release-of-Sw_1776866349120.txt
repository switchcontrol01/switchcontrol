TASK
Harden production logging for public release of SwitchControl 1.0.1.

PROBLEM
The app writes too many logs into %APPDATA%\SwitchControl\logs. Public users will open the app often, which will flood the logs folder, waste disk space, and make the app look noisy and unprofessional.

GOAL
Production logging must be minimal, bounded, and self-cleaning.

REQUIREMENTS
1. Keep only these production log outputs:
- latest.log
- backend.log
- crash/error log only if needed

2. Remove normal creation of per-launch timestamped startup logs in production.
Only create a dedicated startup dump file if startup fails critically.

3. Add log rotation for all persistent logs:
- max size per file: 5 MB
- max retained rolled files per log: 3
- delete oldest beyond retention

4. Add log folder cleanup on startup:
- delete log files older than 14 days
- enforce total logs folder size cap of 20 MB
- if over cap, delete oldest files first

5. Strip verbose production logging:
Remove or gate behind DEBUG_MODE all of these:
- full boot evidence dumps
- full env key diagnostics
- cookie dumps
- request-by-request 200 logs
- telemetry warmup chatter
- giant JSON payload logging
- repeated updater boilerplate beyond major state changes

6. Keep only high-value production logs:
- app startup success/failure
- backend startup success/failure
- updater state changes
- auth success/failure at high level
- tweak execution success/failure
- crash traces
- 5xx server errors
- severe 4xx auth failures only when useful

7. HTTP route logging:
- do not log every successful 200 request in production
- only log 5xx
- log 401/403 only if sampled or if they indicate a real auth bug
- keep full request logging in dev only

8. Add a single switch for verbose logging:
- DEBUG_MODE=true or LOG_VERBOSE=true enables current deep logs
- production default must be quiet

9. Do not break existing logger behavior or crash reporting.

FILES TO CHECK
- electron/main.js
- any file logger module
- backend logger / Express request logger
- updater logger
- telemetry logger
- auth logging
- startup logging utilities

IMPLEMENTATION
- centralize production log policy in one logger config
- implement rotate-on-write or rotate-on-start
- implement folder pruning on app launch
- gate noisy logs behind DEBUG_MODE / LOG_VERBOSE
- reduce request logging in packaged production builds

CHECKLIST
- production build no longer creates endless startup log files
- latest.log and backend.log rotate correctly
- logs folder stays under 20 MB after repeated launches
- production no longer logs every successful request
- production no longer dumps cookies/env/large payloads
- debug mode still allows verbose diagnostics
- no regressions in updater/auth/backend startup

FINAL OUTPUT
Return:
1. exact files changed
2. exact logging behavior before vs after
3. retention and size limits implemented
4. any logs intentionally kept in production
5. confirmation that public builds will no longer flood %APPDATA%\SwitchControl\logs
