TASK: PERFORMANCE + TELEMETRY STABILITY PATCH (CRITICAL)

PROBLEM
Current telemetry + backend flow causes unnecessary CPU usage, re-renders, and potential UI stutter. Some operations also block the main thread or run while the app is hidden.

GOAL
Reduce background CPU usage, eliminate unnecessary React re-renders, prevent blocking operations, and stabilize telemetry behavior without breaking functionality.

---

IMPLEMENTATION

1) CAP TELEMETRY HISTORY (CRITICAL)

In telemetry store (_onTick):

- Add MAX_HISTORY = 60 (or 120 max)
- All history arrays must be sliced to this cap

Use pattern:
const push = (arr, val) => [...arr.slice(-(MAX_HISTORY - 1)), val];

Apply to all:
cpu, ram, gpu, vram, rx, tx, disk metrics

---

2) FIX ZUSTAND SELECTORS (CRITICAL)

Audit ALL:
useTelemetryStore(...)
usePerformanceStore(...)

Rules:

- NEVER return full object
- NEVER return new object without useShallow

Bad:
useTelemetryStore(s => ({ telemetry: s.telemetry }))

Good:
useTelemetryStore(useShallow(s => s.telemetry))

Best:
useTelemetryStore(s => s.telemetry?.cpu?.load ?? 0)

Apply across entire client/src

---

3) THROTTLE PERFORMANCE STORE WRITES (CRITICAL)

In telemetryManager onmessage:

Do NOT call reportCpu every tick

Add threshold:
if (Math.abs(cpu - lastCpu) >= 5) → update
else skip

Prevents constant re-renders

---

4) FIX SPIKE DETECTION (HIGH)

Replace:
[...history].reverse().find(...)

With backward loop:
for (let i = history.length - 1; i >= 0; i--)

No array copy allowed

---

5) STOP WEBSOCKET RECONNECT SPAM WHEN HIDDEN (HIGH)

In socket.onclose:

If document.hidden:

- use max reconnect delay

Also add:
visibilitychange listener:

- reconnect immediately when user returns

---

6) REMOVE execSync FROM MAIN PROCESS (CRITICAL)

Replace:
execSync in appBooster:scanGames

With:
execFile + Promise (async)

Blocking Node main thread is unacceptable

---

7) ADD psLimiter TO HEAVY POWERSHELL TASKS (HIGH)

Apply to:

- startup:scan
- any large PowerShell scan

Reject if already running
