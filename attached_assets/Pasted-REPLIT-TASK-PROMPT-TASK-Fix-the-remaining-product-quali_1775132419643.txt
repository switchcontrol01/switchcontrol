PART 2. NORMALIZE TELEMETRY CONTRACT AT THE BACKEND

Primary file:

electron/main.js


Consumers:

client/src/components/dashboard/LiveGraph.tsx

client/src/components/dashboard/GpuModal.tsx

client/src/components/dashboard/DiskTelemetryModal.tsx

client/src/pages/Home.tsx

any other telemetry consumers


Current issue: Backend returns legacy flat fields like:

cpuUsage

ramUsage

gpuLoad

diskPercent

netRxSec


Frontend then does guesswork and fallbacks.

This must be replaced with one normalized structure.

Implement a normalized telemetry shape for telemetry:getLive.

Recommended shape:

{
  timestamp: number,
  cpu: {
    usagePct: number,
    tempC: number | null,
    maxTempC: number | null,
    coreCount: number,
    perCorePct: number[],
  },
  ram: {
    totalGb: number,
    usedGb: number,
    usagePct: number,
  },
  gpu: {
    available: boolean,
    vendor: string | null,
    model: string | null,
    usagePct: number | null,
    tempC: number | null,
    vramUsedMb: number | null,
    vramTotalMb: number | null,
    powerW: number | null,
    clockMhz: number | null,
  },
  disk: {
    selectedMount: string | null,
    usagePct: number,
    readIOps: number,
    writeIOps: number,
  },
  network: {
    rxKBps: number,
    txKBps: number,
  }
}

Rules:

Always return the same structure

Use null for unavailable metrics, not magic values

Use 0 only when the metric is valid and genuinely zero

Disk/network idle should still be valid zero, not null

GPU available should reflect whether meaningful GPU telemetry exists

Keep logging, but make logs reflect the normalized structure


Do not keep dual contracts alive longer than necessary.
