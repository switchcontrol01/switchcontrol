TASK
Upgrade the SwitchControl admin panel into a proper product operations dashboard.

PROBLEM
The current admin tools cover basic user management, trials, premium grants, device resets, admin logs, and user search. That is useful, but it is not enough to run a growing paid product.

Right now, support and revenue visibility are weak:

- no clear trial conversion view
- no fast way to see trials expiring soon
- no Stripe charge lookup in the admin UI
- no webhook delivery visibility
- limited device lock visibility
- weak support search by Stripe/customer/device fields
- destructive admin actions do not force a clear reason
- no health panel to catch payment/config/data issues early

GOAL
Build practical admin tools that help us:

- retain trial users
- fix payment issues faster
- debug premium problems faster
- track Stripe webhook/payment state
- manage device lock support cases
- catch system/config problems before users report them

Do not overbuild. This should be functional, clean, and reliable.

IMPLEMENTATION

1. Add admin stats bar
   At the top of the admin page, add a compact stats row showing:

- Total users
- Active premium users
- Active trial users
- Trials expiring in next 24 hours
- Trials expiring in next 7 days
- Trial users who expired without converting

Use real DB values only. No fake numbers.

2. Add trials expiring soon panel
   Create a dedicated admin section for trials expiring soon.

Show users whose "trialEndsAt" is within the next 7 days.

Columns:

- email
- plan
- trial start date if available
- trial end date
- hours remaining
- last app active date if available
- has used AI Advisor if available
- has used BIOS Advisor if available

Actions:

- extend trial 24 hours
- extend trial 48 hours
- extend trial 7 days
- grant premium

Every action must create an admin audit log entry.

3. Add Stripe status lookup on user detail
   In the admin user detail panel, add a “Stripe Status” section.

Show:

- Stripe customer ID
- latest charge/payment status
- latest payment amount
- latest payment date
- latest checkout/session if available
- whether a Stripe webhook event exists for the latest payment if available

Add backend endpoint:

GET /api/admin/users/:id/stripe-status

This endpoint should:

- require admin auth
- fetch user from DB
- use stored Stripe customer ID
- call Stripe safely on demand
- return latest relevant payment/charge data
- handle missing customer ID cleanly

Do not call Stripe on every admin page load. Only fetch when the admin opens the Stripe section or clicks refresh.

4. Add Stripe webhook delivery log
   Improve Stripe event tracking.

If the current "stripe_processed_events" table only stores event IDs, extend it or add a new table/log wrapper to store:

- event ID
- event type
- Stripe object ID if available
- affected user ID if resolved
- processed status
- processed timestamp
- error message if processing failed

Show last 20 Stripe events in admin UI.

This is for debugging payment issues fast.
