AI Advisor still has a critical execution consistency problem.

Current behavior:
The AI says things like:

- "I'll apply this tweak for you now"
- "Let's enable Timer Resolution"
- "I can optimize this for you"

But the actual UI action never appears.

No:

- Apply button
- Recommendation card
- Modal
- Navigation
- Execution flow

This makes the assistant feel unreliable because it verbally commits to actions it does not execute.

This is NOT a UI issue.
This is an action-generation contract failure.

Required fix:

The AI must NEVER claim an action was performed unless a real executable action payload exists.

New strict rules:

1. If the AI says:

- "I'll apply"
- "Applying"
- "Let's enable"
- "I can turn on"

Then the response MUST include a valid executable action marker.

Example:

<<APPLY:timer-resolution>>

If no valid tweak ID exists:

- the AI is forbidden from implying execution
- fallback to explanation or navigation only

2. Add server-side enforcement

Before returning the AI response:

- scan for execution phrases
- verify at least one valid APPLY marker exists

If execution language exists WITHOUT action markers:

- either:
  - inject the correct marker automatically
  - or rewrite the response before sending

This must not rely purely on model obedience.

3. Add action-intent classification

User prompts like:

- "apply it"
- "do it for me"
- "turn it on"
- "optimize my pc"
- "show me"
- "take me there"

should trigger deterministic action routing BEFORE the AI generates freeform text.

Meaning:

- intent first
- language second

4. Add visible execution feedback

When an APPLY marker is emitted:

- recommendation cards should ALWAYS render
- Apply modal should ALWAYS appear after click
- tweak state should sync immediately after success

No silent action paths.

5. Add hard validation logs

Add logs like:

[AI:action] detected intent=apply
[AI:action] tweakId=timer-resolution valid=true
[AI:action] recommendationCard rendered=true

And:

[AI:contract] execution_language_without_marker detected

6. UX Goal

The AI should feel like:

- a system operator
  NOT
- a chatbot pretending to operate the app

Current screenshots show the AI verbally promises actions while doing nothing.
That destroys trust instantly.
