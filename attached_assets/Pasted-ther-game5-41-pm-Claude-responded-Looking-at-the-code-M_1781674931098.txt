The detection flow:
Game detection happens in electron/main.js via the appBooster:scanGames IPC handler, which checks four sources in order: Epic manifests, hardcoded knownPaths, Xbox roots, and Steam library common folders, then falls back to a running-process check.
Why MSFS24 specifically likely fails:
MSFS2024 has a few characteristics that break the standard detection paths:
It's distributed primarily through the Microsoft Store / Xbox app, not Steam or Epic in most cases. Looking at the Xbox detection path in main.js, it only scans X:\XboxGames folders plus one registry key (GamingRootPath). MSFS installs are often enormous (100GB+) and many users redirect them to a custom drive/folder that isn't under the standard XboxGames directory — if that's the case here, the Xbox scan simply won't find it.
The executable name matters a lot. MSFS2024's actual exe is typically FlightSimulator2024.exe (or similar) inside a deeply nested path like Content\LocalCache\Packages\Microsoft.FlightSimulator2024_8wekyb3d8bbwe\.... If the catalog entry's executable field or knownPaths doesn't match the actual installed exe name/depth exactly, every detection method fails even if the game is genuinely installed.
The Steam version (if that's what's installed) goes through steamCommonPaths, which only checks one level deep plus one additional subdirectory level (findExeIn isn't used here — the steam branch in appBooster:scanGames manually checks gameDir then one subDirs level). MSFS's Steam install structure may nest the exe deeper than that, causing the scan to give up before reaching it.
What I'd check first:
Open the game's catalog entry — likely in client/src/lib/gameDetection/catalog.ts — and look at the executable and knownPaths fields for the MSFS24 entry. Two questions matter: does executable exactly match the real filename on disk (case and spelling), and do any knownPaths cover where it's actually installed (Xbox app installs often go to a user-chosen drive root, not Program Files).
If it's a Microsoft Store/Xbox install, the more reliable fix is extending the Xbox detection in main.js to also check the registry for the per-app install location (HKLM\SOFTWARE\Microsoft\WindowsStore or the GamingApp package manifest path) rather than relying solely on the XboxGames folder convention, since custom install drives are extremely common for a game this size.
