TASK

Fix the onboarding/tour replay bug for free-trial users.

PROBLEM

When a user is granted a free trial and opens the app, the trial activation flow starts smoothly, but the premium tour keeps replaying continuously instead of running once and ending.

This is a state/trigger bug.

The expected behavior is:

1. free-trial activation flow runs once
2. free-trial tour runs once
3. if intended, premium-style intro/tour runs once
4. exit animation runs
5. entire flow is marked complete
6. it must NOT autoplay again on the next render, refresh, route change, or entitlement re-check

GOAL

Make the entire free-trial onboarding flow deterministic and one-time only.

Free-trial users must not get stuck in an endless premium-tour replay loop.

IMPORTANT

Do not patch this with a timeout or visual hack.
Fix the trigger/state logic properly.

EXPECTED FLOW

For a free-trial user:

- detect active trial from backend state
- if free-trial onboarding has not been seen, start free-trial flow
- once free-trial flow is complete, mark it completed
- if premium-style intro/tour is intentionally included, run it once only
- once complete, mark that completed too
- run exit animation once
- no further autoplay

ROOT CAUSE AREAS TO AUDIT

1. Trigger conditions
   Check all "useEffect", mount logic, entitlement listeners, and account refresh handlers that can start:

- free trial activation
- free trial tour
- premium tour
- exit animation

2. Persistent flags
   Audit whether the following exist and are actually written/read correctly:

- hasSeenTrialActivation
- hasSeenTrialTour
- hasSeenPremiumTour
- hasSeenUpgradeAnimation
- any local session guard state

3. Backend vs frontend state
   Ensure frontend is not replaying because:

- flags are not persisted to backend
- flags are saved locally only and lost
- account refresh returns stale values
- plan state changes retrigger tour start logic

4. Completion handlers
   Ensure each flow stage has a hard completion write:

- on free-trial flow complete -> mark hasSeenTrialTour true
- on premium intro/tour complete -> mark hasSeenPremiumTour true
- on final exit complete -> mark final flow completed for session

5. Route / remount loops
   Check whether route changes or shell remounts are reopening the onboarding flow.

6. Session guard
   Add a session-level in-memory guard such as:

- onboardingFlowRunning
- onboardingFlowCompletedThisSession

So even if account refresh happens, the current session does not replay the flow.

REQUIRED LOGIC

Implement a deterministic onboarding state machine.

Suggested stages:

- idle
- trial_activation
- trial_tour
- premium_intro
- exit
- completed

This flow should advance once and never restart unless explicitly reset by admin.

Do NOT rely on scattered booleans alone.
