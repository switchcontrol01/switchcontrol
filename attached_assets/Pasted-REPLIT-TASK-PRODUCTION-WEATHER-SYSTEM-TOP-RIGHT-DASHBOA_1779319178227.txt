REPLIT TASK: PRODUCTION WEATHER SYSTEM (TOP RIGHT DASHBOARD)

GOAL:
Build a lightweight premium weather intelligence widget for the top-right dashboard area.

IMPORTANT:
This must feel native to SwitchControl.
No cheap weather app look.
No CPU spikes.
No excessive polling.
No layout shifts.
No startup delays.
No render blocking.

---

CORE REQUIREMENTS

1. LOCATION

- Detect user location automatically
- Fallback to country not town. if detection fails
- Allow manual override later

2. WEATHER DATA
   Display:

- Current temp
- Condition icon
- Rain chance
- Wind speed
- Humidity
- Feels-like temp

3. UPDATE STRATEGY
   CRITICAL:
   Do NOT poll every 3 seconds.

Use:

- Initial fetch on dashboard load
- Cache results in localStorage
- Refresh every 15 minutes
- Silent background refresh only
- No UI freezing during refresh

4. PERFORMANCE
   Must:

- Load instantly
- Never block dashboard render
- Never delay startup
- Never trigger global rerenders
- Never run intervals faster than 15min

Use:

- isolated component
- memoization
- lightweight state only
- lazy mount after dashboard visible

5. UI DESIGN
   Placement:

- Top-right dashboard

Style:

- premium glass
- subtle blur
- matte dark background
- small footprint
- soft hover glow
- no huge cards
- no oversized text

Animation:

- single smooth fade-in only
- no repeated animations
- no bouncing
- no blur transitions

6. WEATHER ICONS
   Use lightweight icon mapping:

- clear
- cloudy
- rain
- thunder
- fog
- snow

Icons should:

- match SwitchControl visual language
- be subtle
- not cartoonish

7. BACKEND
   Create lightweight endpoint:
   GET /api/weather

Requirements:

- aggressive caching
- timeout protection
- fail gracefully
- never crash dashboard if API fails

8. FAILURE HANDLING
   If weather fails:

- widget still renders
- show fallback state
- no console spam
- no notification spam

9. FUTURE SUPPORT
   Architecture should support future additions:

- weather-based AI suggestions
- rain alerts
- cooling recommendations
- network quality warnings
- storm mode
- FPS thermal prediction

---

EXTRA PREMIUM FEATURES

If low overhead:

- slight tint shift depending on weather
  rain = cooler tint
  sun = warmer tint

- hover expand for extra details

- optional compact forecast strip later

---

CRITICAL RULES

DO NOT:

- use huge weather libraries
- spam API calls
- use websocket weather feeds
- create memory leaks
- create interval duplication
- cause React rerender storms
- block Electron startup
- delay telemetry rendering

This system must feel:
FAST
CLEAN
NATIVE
PREMIUM
INVISIBLE PERFORMANCE-WISE

AFTER IMPLEMENTATION

Audit:

- memory usage
- startup impact
- rerender frequency
- API frequency
- dashboard FPS impact
- Electron idle CPU usage
