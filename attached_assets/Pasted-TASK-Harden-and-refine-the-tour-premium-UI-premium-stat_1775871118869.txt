TASK
Harden and refine the tour, premium UI, premium state flows, graph primitives, and animation system without removing any existing features or reducing the premium feel.

GOAL
The current SwitchControl tour and premium UI system already has strong visual ambition and a good premium direction.
The problem is not that it looks bad.
The problem is that the code and motion system are becoming visually rich but structurally loose.

I do NOT want features removed.
I do NOT want the premium feel reduced.
I do NOT want the visuals flattened or simplified into something boring.

I want:
- hardening
- cleanup
- better structure
- stronger consistency
- safer state flow
- better performance discipline
- better graph reuse
- more controlled premium motion language

IMPORTANT
Do NOT remove any existing premium animations, tours, overlays, lock states, success states, or graph concepts.
Do NOT downgrade the visual ambition.
This is a hardening and refinement pass, not a simplification pass.

CRITICAL
Do not come back with “I removed X because it was too much.”
Do not strip out premium moments.
Do not reduce the motion language to generic app motion.
Keep the richness, but make it more robust, consistent, reusable, and controlled.

SCOPE
This task covers:
- OnboardingTour
- GuidedTour
- TourShell
- tour-store
- AnimateIn
- AnimatedCrown / premium badges
- PremiumUnlockAnimation
- PremiumUpgradeAnimation
- PremiumSuccess page flow
- Premium overlays / lock overlays / page overlays
- Premium surfaces/backgrounds/particles/sheen
- Premium grace store
- Tour graph primitives and their reuse potential

MAIN OBJECTIVES

1. HARDEN STRUCTURE
The system currently has too much responsibility concentrated in large components.
Refactor and clean up structure without changing behavior.

2. KEEP ALL FEATURES
No removals.
No “temporary simplification.”
No flattening of premium identity.

3. UNIFY PREMIUM MOTION LANGUAGE
Right now the premium system has multiple strong ideas, but it needs tighter consistency across:
- lock states
- unlock states
- premium overlays
- premium success
- premium tours
- crown/badge moments

4. REUSE GRAPH PRIMITIVES
The graph language in the tours is strong.
It needs to become more reusable and systemized.

5. HARDEN STATE FLOWS
Premium unlock, premium grace, tour transitions, and success states need safer logic and less fragile timing.

IMPLEMENTATION

1. AUDIT THE FULL TOUR + PREMIUM UI SYSTEM
Audit the current system and identify:
- oversized components
- duplicated animation logic
- repeated motion tokens
- repeated premium color tokens
- fragile timer-driven phase logic
- state-transition risks
- premium unlock logic risks
- premium grace cache risks
- opportunities to extract graph primitives
- opportunities to centralize motion/theme constants

Return a clean internal map of what is duplicated, what is fragile, and what should be extracted.

2. HARDEN TourShell WITHOUT REDUCING FEATURES
TourShell currently handles too much.

Refactor it into cleaner internal pieces while keeping behavior the same.

Suggested extraction:
- Tour overlay / backdrop layer
- Tour card shell
- Tour footer navigation
- Completion moment
- Tour theme tokens / premium vs non-premium theme logic

Requirements:
- same visual quality
- same flow
- same step behavior
- same completion experience
- cleaner internal structure
- easier future maintenance

Do NOT reduce any current visual richness.

3. HARDEN COMPLETION MOMENT TIMING
The completion sequence currently depends on hardcoded timeouts.

Refactor timing into clearer, centralized timing constants so future animation tuning does not silently break behavior.

Need:
- centralized timing constants
- phase timing clearly named
- onDone logic still works
- no cut-off of exit motion
- no hidden timer magic

Keep the same premium feel.

4. UNIFY PREMIUM MOTION LANGUAGE
Create a more consistent premium motion system across:
- PremiumUnlockAnimation
- PremiumUpgradeAnimation
- PremiumPageOverlay
- PremiumLockOverlay
- PremiumModal
- AnimatedCrown / PremiumBadge
- premium tour moments

Need consistency in:
- easing curves
- glow language
- pulse behavior
- unlock energy
- lock-state tone
- premium lighting treatment
- timing hierarchy

Do NOT make everything identical.
But make it feel like one product family, not multiple separate premium animation experiments.

5. EXTRACT AND REUSE GRAPH PRIMITIVES
The TourLineGraph is one of the strongest visual systems currently present.
Systemize it.

Need:
- extract reusable graph primitive(s)
- keep the same high-quality line-draw / glow / fill behavior
- preserve labels and values
- make it reusable across more of the app later
- reduce tour-only coupling

This should become the base graph language for:
- dashboard mini graphs
- tweak comparisons
- confidence graphs
- latency graphs
- score trajectories
- system trend visuals

Do NOT degrade the graph visuals.

6. IMPROVE CAUSE-AND-EFFECT GRAPH MOTION
Where graphs or preview panels are shown, strengthen the feeling of meaningful motion.

Need:
- lines should imply system improvement, degradation, stabilization, or active analysis
- avoid motion that feels decorative only
- preserve fluid expensive graph feel
- strengthen the “this means something” quality

Keep the current premium look, but make motion more semantically intentional.

7. EXTRACT SHARED MOTION TOKENS
There are too many repeated:
- durations
- delays
- easing curves
- color rgba strings
- glow strengths
- repeated animation patterns

Create centralized motion/theme tokens for:
- premium motion
- tour motion
- success motion
- lock/unlock motion

Requirements:
- no behavior downgrade
- easier future tuning
- cleaner consistency
- less copy-paste animation logic
