**Problem: SwitchControl App Booster is hurting the very games it's supposed to help**

We have a Windows gaming optimization app called SwitchControl. It includes an "App Booster" feature that applies per-game system optimizations (CPU priority, GPU preference, FSO disable, Network QoS, etc.) to improve FPS and latency.

The problem is two-fold:

**1. SwitchControl itself tanks 1% lows while running in the background during gameplay.**

The app runs a telemetry polling loop every 2 seconds that calls `si.currentLoad()`, `si.cpuTemperature()` via WMI, and spawns PowerShell processes to read GPU performance counters via `Get-Counter`. On CPU-sensitive games like Fortnite, this background polling competes for CPU time and causes scheduler jitter that shows up as frame time spikes and bad 1% lows. The GPU perf counter PowerShell spawn has up to a 9 second timeout and is the worst offender.

**2. The current game optimizations are missing the highest-impact tweaks.**

The 6 actions currently applied per game (CPU priority class, FSO disable, GPU preference, Game Mode, Xbox DVR off, Network QoS) are all fine but leave significant performance on the table. Missing are: timer resolution (0.5ms via timeBeginPeriod), HPET disable, Win32PrioritySeparation set to 0x26 for foreground thread boost, NVIDIA GPU power management forced to max performance via driver registry key, E-core affinity exclusion on 12th/13th/14th gen Intel, per-interface Nagle disable for all catalog games (currently only manual games get this), and suspension of high-overhead background processes (Discord GPU compositor, browser renderer processes, Epic/Steam background workers) via our existing but disconnected Process Control system.

**What we want to build:**

First, a Game Sentinel: detect when a boosted game's process is running via periodic tasklist checks, and when detected automatically pause the telemetry loop, cancel pending PowerShell GPU counter calls, and push the polling interval to 30 seconds minimum. Resume normal operation when the game process exits. This is the single highest ROI change.

Second, expand the per-game action set with the missing high-impact tweaks listed above, with Fortnite and competitive shooters as the primary target since that's our core user base.

Third, wire App Booster into our existing Process Control system so that when a profile is applied, background processes are automatically deprioritized for the duration of the gaming session.

Our stack is Electron + React/TypeScript frontend, Express backend, PostgreSQL. The game detection, IPC bridge, and telemetry infrastructure are all already built — this is purely about adding the Game Sentinel logic to main.js and expanding the action set in appBoosterProfiles.ts.
