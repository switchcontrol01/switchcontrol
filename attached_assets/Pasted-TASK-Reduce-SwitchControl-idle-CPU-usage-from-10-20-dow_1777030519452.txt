TASK
Reduce SwitchControl idle CPU usage from 10–20% down to a realistic 1–5% target by making telemetry smarter, less frequent, and render-safe.

PROBLEM
The current telemetry system still uses expensive calls too often:
- si.currentLoad()
- si.networkStats()
- si.cpuTemperature()
- si.graphics()
- getLhmTelemetry()
- PowerShell GPU perf counters
- Recharts re-rendering on every telemetry tick

This causes high CPU usage even when the app is idle.

GOAL
Make telemetry low-cost without breaking the dashboard:
- Idle app target: 1–3% CPU
- Dashboard with graph open target: 2–5% CPU
- No constant LibreHardwareMonitor polling
- No constant GPU PowerShell polling
- No graph re-render when values barely changed
- Pause telemetry when hidden/minimized/not on dashboard
- Keep UI visually smooth using cached/interpolated values, not heavy polling

IMPLEMENTATION

1. Update server/lib/telemetry.ts scheduler constants:
- POLL_BASE_MS from 2000 to 4000
- POLL_LOW_END_MS from 6000 to 10000
- GPU_TTL_MS from 8000 to 15000
- CPU_TEMP_TTL_MS from 8000 to 15000
- DISK_IO_TTL_MS from 4000 to 8000
- PROC_TTL_MS from 30000 to 60000
- CPU_BUDGET_PCT from 5 to 3

2. Add a heavy-task cooldown.
If appCpuPct > 3%, skip all heavy tasks for 15 seconds.
Do not just skip one tick.

Add module state:
let heavyCooldownUntil = 0;

Inside tick():
const inCooldown = Date.now() < heavyCooldownUntil;

If app CPU is over budget:
heavyCooldownUntil = Date.now() + 15000;
skippedTicks++;

Then only run heavy tasks if:
!overBudget && !inCooldown

3. Make LibreHardwareMonitor optional.
Do not call getLhmTelemetry automatically every few seconds.
Only call LHM when:
- user opens hardware details modal
- user opens GPU modal
- user manually clicks refresh
- AI Advisor requests deep hardware scan

Remove LHM from normal background polling.
Keep cached last LHM result for 60 seconds.

4. In electron/main.js:
- TELEMETRY_BASE_MS from 2000 to 4000
- TELEMETRY_SLOW_MS from 5000 to 10000
- CPU_BUDGET_PCT from 5 to 3
- CPU_TEMP_TTL_MS from 8000 to 15000
- DISK_IO_TTL_MS from 4000 to 8000
- LHM_POLL_TTL_MS should not be used in background polling anymore
- FS_SIZE_TTL_MS from 12000 to 30000

5. Remove getLhmTelemetry() from pollTelemetry().
Do not run it inside the normal telemetry loop.

Replace this section:
else if (now - _lhmLastTs > _lhmTtl) {
  _lhmCache = await getLhmTelemetry()
}

With:
- no background LHM call
- only use existing _lhmCache if it exists

6. Add a new IPC handler:
telemetry:refreshDeepHardware

This manually runs:
- getLhmTelemetry()
- si.graphics()
- si.cpuTemperature()
- si.memLayout()

It should cache result for 60 seconds and return cached data if called again too soon.

7. Stop PowerShell GPU usage during startup.
Remove this startup prewarm from startTelemetryPolling():

getGpuPerfCounterLoad().then(...)

This is expensive and causes launch CPU spike.
Only call telemetry:refreshGpuLoad manually when the user opens GPU details.

8. In LiveGraph.tsx:
Change Electron graph interval from 2000 to 4000.

Replace:
intervalRef.current = setInterval(fetchTelemetry, 2000);

With:
intervalRef.current = setInterval(fetchTelemetry, 4000);

9. Add render-skip logic in LiveGraph.
Before setData(), compare latest point with new point.

If CPU, RAM, GPU, disk are all changed by less than 1%, skip setData.
Example:
const last = prev[prev.length - 1];
if (
  last &&
  Math.abs(last.cpuLoad - cpuLoad) < 1 &&
  Math.abs(last.ram - ramPercent) < 1 &&
  Math.abs((last.gpuLoad ?? 0) - (gpuLoad ?? 0)) < 1 &&
  Math.abs((last.diskActiveTime ?? 0) - (diskActiveTime ?? 0)) < 1
) {
  return prev;
}

This prevents Recharts re-rendering when nothing meaningful changed.

10. Pause graph polling when route is not Dashboard.
If LiveGraph is unmounted, polling must stop.
If route changes away from dashboard, stop polling immediately.
Make sure cleanup clears interval.

11. Add telemetry debug output.
Expose:
- appCpuPct
- lowEndMode
- heavyCooldownUntil
- tickCount
- skippedTicks
- taskTimings
- telemetry interval
