TASK
Fully implement Focus Mode with REAL backend execution and a refined frontend so it becomes a true system-level performance and distraction control mode.

GOAL
Turn Focus Mode into a real system state engine that:
- applies multiple system-level changes at once
- improves performance and removes distractions
- is fully reversible
- is backend-driven and verifiable
- feels premium and controlled in UI

CRITICAL
Backend is mandatory.

If a toggle exists:
- it must execute a real system-level action
- it must support enable AND disable (revert)
- it must return real success/failure

No fake toggles.
No UI-only behavior.
No silent failures.

If something cannot be safely implemented:
- disable it or mark unavailable
- do NOT fake it

---

IMPLEMENTATION

1. CREATE FOCUS MODE ENGINE (BACKEND CORE)

Create a backend module:
- focus-mode-engine.ts

Responsibilities:
- apply focus profile (enable)
- revert focus profile (disable)
- track applied changes
- verify applied state
- return structured results

---

2. DEFINE REAL ACTIONS PER TOGGLE

Each toggle must map to real system behavior.

Implement using:
- PowerShell
- registry
- services
- process management
- Windows APIs where possible

Required mappings:

NOTIFICATIONS
- disable Windows notifications (Focus Assist / Quiet Hours via registry or API)

NETWORK PRIORITY
- adjust QoS or DSCP tagging where possible
- optionally raise priority for active process

OVERLAYS
- detect and terminate overlay processes:
  - Discord overlay
  - Steam overlay helper
  - Xbox Game Bar

INPUT LOCKDOWN
- block Win key / Alt+Tab where feasible
- or reduce via registry / policy / hooks (safe implementation only)

BACKGROUND APPS
- suspend or lower priority of non-essential processes
- or stop specific known background apps

POWER LOCK
- switch to high performance power plan
- disable idle states where applicable

IMPORTANT:
Only implement what is safe and reversible.

---

3. APPLY FLOW

When user enables Focus Mode:

- gather enabled toggles
- execute all corresponding backend actions
- track each action result
- store applied state
- return structured response:
  - success
  - partial success
  - failed
  - requires restart

---

4. REVERT FLOW

When Focus Mode is disabled:

- revert all previously applied actions
- restore original states
- verify restoration
- return real result

Do NOT assume default values. Track previous state where needed.

---

5. STATE TRACKING

Store:
- which toggles were active
- what changes were applied
- previous values (for revert)
- timestamp

Use:
- in-memory + optional persistence

---

6. VERIFICATION (CRITICAL)

After each action:
- verify system state

Examples:
- check registry values
- check power plan
- check process state
- check service state

If verification fails:
- return failure
- do NOT mark success

---

7. FRONTEND CONNECTION

Fix Focus Mode UI so:

When toggles change:
- update local state only

When user activates Focus Mode:
- send request to backend
- show “activating” state
- wait for response
- update UI based on REAL result

Same for disabling.

---

8. GLOBAL FOCUS MODE STATE

Add:
- global “Focus Mode Active” indicator
- visible across app

UI should reflect:
- active / inactive
- current profile
- duration remaining (if timer used)
