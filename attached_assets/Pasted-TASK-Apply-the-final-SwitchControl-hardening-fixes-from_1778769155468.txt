1. Fix PowerShell injection risk in "appBoosterProfiles.ts"
   File:

- "client/src/lib/gameDetection/appBoosterProfiles.ts" or wherever "appBoosterProfiles.ts" lives

Find:

- "buildNetworkQosPs"
- any code that builds PowerShell strings using "installPath", "exePath", or user-provided game paths

Add strict path validation before building PowerShell.

Use a helper similar to:

const WINDOWS_EXE_PATH_RE = /^[A-Za-z]:\\[^"<>|*?\r\n]{1,260}\.exe$/i;

function validateWindowsExePath(value: unknown): string | null {
  if (typeof value !== "string") return null;
  const trimmed = value.trim();
  if (!WINDOWS_EXE_PATH_RE.test(trimmed)) return null;
  return trimmed;
}

function escapePowerShellDoubleQuoted(value: string): string {
  return value
    .replace(/`/g, "``")
    .replace(/\$/g, "`$")
    .replace(/"/g, '`"')
    .replace(/\r|\n/g, "");
}

Requirements:

- reject invalid paths
- never interpolate raw "installPath" or raw "exePath"
- escape double quotes, backticks, dollar signs, CR, and LF before putting a value inside a PowerShell string
- if the path is invalid, do not generate the QoS action
- return a clear warning or skip reason

Do not weaken the static catalog behavior. Static executable names are fine, but user-provided paths must be validated.
