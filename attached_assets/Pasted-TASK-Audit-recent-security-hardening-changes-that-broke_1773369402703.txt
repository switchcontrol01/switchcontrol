TASK: Audit recent security hardening changes that broke Google OAuth across website and Electron

PROBLEM

Google login used to work correctly.

Before:
- user could click a Google account
- auth would complete normally
- website login worked
- Electron handoff worked and reopened the app automatically

Now after recent security checklist / hardening changes:
- Google login behavior is broken
- clicking an account may load and appear to stall
- browser may eventually land on a success/fallback page
- website login is also affected
- Electron login is also affected
- issue happens across multiple devices

Because the same regression appears on website and across devices, this strongly suggests a shared server-side auth/security regression, not a local device-only problem.

GOAL

Find exactly which security hardening change broke Google OAuth and fix it without removing the valid security improvements that should remain.

Restore the previous working behavior:
- website Google login works end-to-end
- Electron Google login works end-to-end
- successful auth properly redirects / hands off
- no hanging after account selection
- no broken callback/session state
- no stuck fallback page

IMPLEMENTATION

SECTION 1 — IDENTIFY ALL RECENT SECURITY CHANGES TOUCHING AUTH

Audit the recent security checklist changes and identify everything that modified:

- session middleware
- cookie settings
- SameSite
- Secure
- Domain
- Path
- Helmet / CSP
- frame / navigation policies
- redirect validation
- callback validation
- CSRF / origin / referer checks
- JWT / issuer validation
- session regenerate/save flow
- auth route middleware
- CORS or credentials behavior

List exactly what changed that could affect OAuth.

SECTION 2 — COMPARE CURRENT AUTH FLOW AGAINST PREVIOUS WORKING BEHAVIOR

Trace the current Google OAuth flow and compare it to the previous known-working behavior.

Determine exactly where it now diverges:
- auth start
- state/cookie preservation
- callback handling
- session persistence
- redirect/handoff
- success page script execution
- Electron handoff

Do not guess.
Find the exact regression point.

SECTION 3 — AUDIT COOKIE SETTINGS FOR OAUTH COMPATIBILITY

Inspect all auth/session cookies involved in the Google flow.

Verify whether recent hardening changed:
- SameSite
- Secure
- Domain
- Path
- expiration

Pay special attention to:
- SameSite=Strict
- path too narrow
- domain mismatch
- secure-only behavior conflicting with flow expectations

If a stricter cookie policy broke OAuth, fix it in the minimal correct way.

SECTION 4 — AUDIT CSP / SECURITY HEADERS

Inspect Helmet and CSP changes.

Determine whether CSP or related headers are blocking:
- callback page scripts
- success-page redirect logic
- custom protocol handoff
- inline launch script if used
- navigation required for auth completion

Check browser console/network/header behavior and identify any blocked script or navigation relevant to the auth flow.

SECTION 5 — AUDIT CALLBACK / SESSION FINALIZATION

Inspect whether security changes altered:
- req.session.regenerate
- req.login
- req.session.save
- redirect timing
- state/cookie cleanup

Make sure callback still:
- authenticates user
- persists session
- saves session before redirect
- preserves source/next values as needed

SECTION 6 — AUDIT REDIRECT / URL VALIDATION

Inspect any new redirect sanitization or allowlist logic.

Ensure it is not incorrectly blocking:
- valid post-login website redirects
- Electron handoff URLs
- expected success-page behavior

If custom protocol redirects are intentionally blocked directly, confirm the fallback success page still works correctly.

SECTION 7 — RESTORE WORKING OAUTH WITHOUT THROWING AWAY GOOD SECURITY

Do not blindly revert all security changes.

Instead:
- identify the specific breaking hardening
- relax only what is required for OAuth compatibility
- preserve the hardening that is still valid and safe

SECTION 8 — VERIFY BOTH FLOWS AFTER FIX

Confirm:
- website Google login works again
- Electron Google login works again
- account selection no longer hangs
- callback completes
- session persists
- browser/app handoff works as designed

CHECKLIST

[ ] Redirect validation was checked

[ ] No broad unnecessary rollback of security changes was done

FINAL OUTPUT

After fixing, report:

- files changed
- exact security change that caused the regression
- whether cookie settings were part of the issue
- whether CSP/security headers were part of the issue
- whether callback/session persistence was part of the issue
- what was changed to restore OAuth compatibility
- which security hardening remains in place
- confirmation that website and Electron login both work again
