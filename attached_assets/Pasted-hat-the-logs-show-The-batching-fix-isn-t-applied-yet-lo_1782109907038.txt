Problem 1: Network/Bluetooth always empty
In driverIntelStore.ts, inside acquireHardware(), after the system intelligence profile fetch times out, the code currently just reads p?.network.interfaces which is empty because netIf timed out.
The fix is to add a fallback that calls window.electronAPI.nic.getAdapters() directly when the profile's network interfaces array is empty. This IPC call goes through your existing nic-executor.js which uses netsh/WMI in a way that's much faster than systeminformation. Take the first adapter that is active and not a loopback/virtual, use its name for both netName and btName.
Problem 2: Audio always empty
Same file, same function. After getting the profile, check if p?.audio?.devices is empty or missing. If so, call window.electronAPI.system.getInfo() — actually that won't have audio. The real fix is adding a new narrow IPC handler in main.js that runs a tiny PowerShell one-liner: Get-WmiObject Win32_SoundDevice | Select-Object -First 1 -ExpandProperty Name with a 3 second timeout. Expose it as electronAPI.system.getAudioDevice(). Then in acquireHardware() call that as the audio fallback.
Problem 3: Storage empty
In acquireHardware(), when p?.storage.layout is empty because diskLayout timed out, add a fallback that calls window.electronAPI.storage.getVolumes() which already exists in your preload. Parse the drive letter from the volume and use it as the SSD name for vendor detection.
Problem 4: Batching still not applied
The Promise.allSettled() in collect() in systemIntelligence.ts still needs replacing with the 5 serialized batches with 400ms gaps as described earlier. This is what will prevent the remaining simultaneous WMI spike you can still see in the logs at 06:26:35.
