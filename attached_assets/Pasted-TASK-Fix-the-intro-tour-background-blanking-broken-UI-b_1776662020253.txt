TASK

Fix the intro tour background blanking / broken UI bug during tour step navigation.

PROBLEM

During the onboarding intro tour, the underlying app UI partially disappears, blanks, or renders in a broken half-hidden state when the tour changes steps and routes.

This is not a styling issue.

It is caused by render lifecycle collisions between:

- AppLayout page remounting
- useRevealOnScroll resetting revealed sections
- TourShell route-driven navigation state

ROOT CAUSE TO VERIFY

1. AppLayout remounts the page on every route change because the motion page wrapper uses "key={location}"
2. "useRevealOnScroll" removes ".is-visible" from all "[data-reveal]" elements whenever "locationKey" changes
3. TourShell drives route changes during the intro tour, so the background page is being remounted and hidden while the overlay is active
4. The current "isTourNavigating" guard only suppresses some animation behavior, but does not stop destructive remount/reset behavior

GOAL

During any intro tour step navigation:

- do not blank the page
- do not remove ".is-visible" from revealed sections
- do not remount the entire page shell unnecessarily
- keep the underlying app visually stable while the tour moves between steps
- preserve all existing tour progress and completion state

HARD RULES

- do not do cosmetic animation tuning first
- do not reset tours
- do not clear localStorage
- do not change onboarding completion flags
- do not introduce hacks that hide the issue without fixing the render lifecycle
- fix root cause, not symptoms

IMPLEMENTATION

1. In "useRevealOnScroll"

- read "isTourNavigating" and "isTourActive" from "useTourStore"
- if either is true, do not run the reset that removes ".is-visible"
- do not reinitialize the reveal observer during tour-driven route changes
- make sure tour navigation cannot temporarily blank revealed sections

2. In "AppLayout"

- stop using "key={location}" during tour navigation
- use a stable key while "isTourNavigating" is true, for example:
  "key={isTourNavigating ? "tour-stable-page" : location}"
- confirm that the page shell is not being destructively remounted during intro tour route changes

3. In "TourShell"

- keep ownership of "setTourNavigating" lifecycle inside the tour itself
- set "setTourNavigating(true)" before "navigate(route)"
- clear it only after the new route has mounted and committed, using double "requestAnimationFrame" or another stable post-mount method
- remove competing automatic clear logic from "AppLayout" if that logic is firing too early

4. Preserve tour behavior

- intro tour must still function normally
- trial tour must remain unaffected
- premium tour must remain unaffected
- no regression to step navigation, completion, skip, or final completion moment

5. Verification
   Test specifically:

- intro tour route changes
- sidebar still visible
- page body no longer blanks
- revealed sections stay rendered during tour transitions
- no broken half-hidden dashboard under overlay
- no tour reset required

CHECKLIST
